# 卒業後の削除と復元（段階 4 以降）の確認結果

要件定義書の「卒業後の削除時期・削除方法・復元方法」。コミット `fb3d660`・`41b567f`（2026-11-21）。規則と GAS（`app-7`）も入れかえた。

## 先生が決めたこと（2026-11-21）

- 先生がボタンで消す（日付が来ても、自動では消さない）。
- 消してから 30 日は、もどせる。

## 決めた動き（Claude Code が決め、実装の前に先生に伝えた）

| 項目 | 動き |
|---|---|
| 場所 | 先生のメニューの「卒業」。入学年度ごと（生徒 ID の `s26-` など）に、人数と状態を出す |
| 消す | 「この学年の記録を消す」→ 説明を読み、入学年度の数字を入れてから実行 |
| 消した直後（30 日の間） | その学年の生徒は、ログインできず、何も読めない。データは残る。「もどす」で元どおり |
| 30 日をすぎたら | 「クラス」の画面に知らせ。「卒業」の画面を開くと、進み具合を見せながら完全に消す。止めても、次に続きから消せる |
| 完全に消すもの | 記録・写真・PDF・手書き・小さい画像・自分の用語・印・先生の返事・理科クエストの記録・名簿・ID の台帳・最初のパスワード。その生徒がかかわったクラスの AI のまとめ |
| 消さないもの | 先生の授業・資料・クラス・単元 |
| 写真・PDF を消せないとき | その授業の記録を消さずに止めて、理由を出す |
| Drive で確かめられないファイル | 止める。先生が確かめの画面で「はい」と答えたときだけ、とばして続ける |
| 完全に消している途中の生徒 | もどせない・出し直せない（規則でも画面でも） |

実装の前に伝えた内容から変えた点: 完全に消すのは「先生がどの画面を開いても」ではなく、「卒業」の画面を開いたときにした（時間がかかるので、進み具合が見える画面で行う）。

## 作り

- データ: `removed/<生徒 ID>` = `{ removedAt, uid?, purging? }`。消す = `accounts/<uid>` を外す（規則がどれも `accounts` を見ているので、生徒は何も読めなくなる）。
- `js/graduate-logic.js`（学年の分け方・30 日）、`js/graduate-flow.js`（消す・もどす・完全に消す）、`js/views/teacher-graduates.js`（画面）。
- 完全に消す順番: 「途中」の印を書く → かかわるクラスをさがす（今の名簿・入学年度以上の全部のクラスの記録・生徒の印の場所）→ 授業ごとに、ファイルをゴミ箱へ → 記録を消す → 生徒ごとに、用語・印・名簿・台帳を消す → 最後に `removed` を消す。
- 規則: 先生が消せるのは「消してある」生徒のものだけ。`removed` の uid は、今の台帳と同じでなければ書けない。「途中」の印が付いた生徒には、アカウントを結びつけられない。消してある生徒は、理科クエストの自分の記録も読めない。
- GAS `app-7`: `trashStudentFiles`（先生だけ。20 個まで。持ち主が「消してある」生徒のファイルだけをゴミ箱に入れる。確かめられなかったものは `unknown` で返す）。

## 分かっている限界

- Firebase のログイン用アカウント本体は、アプリからは消せない（何も読めない状態で残る）。消すなら、Firebase の画面の Authentication から。
- 消した直後の最大 60 秒は、GAS の本人確認が残る（その間、ログインしたままの生徒は、自分のファイルを読めることがある）。
- これより前に出し直した生徒の、古いアカウントの理科クエストの記録は、たどれないので消せない（2026-11-20 の時点で、本番に理科クエストの記録は 1 件も無い）。
- 完全に消したあと、先生の授業は残る。いらない授業は、授業の画面で 1 つずつ消す。
- Drive のゴミ箱に入れたファイルは、Google の決まりで 30 日後に消える。
