設計書の「4 以降: アプリ内の自動要約」のうち、AI を使うまとめの確認結果です。コミット `789dfa0`（2026-11-18 公開）。

- 本名、メールアドレス、パスワード、キー、トークンは書きません。

## 1. 先生の決定（2026-11-18）

- 先生の「記録」に、AI（OpenAI の API）で作るまとめを足す。今ある「まとめ（自動）」（AI なしの集計）は残す。
- 生徒が文字で書いた文章を OpenAI に送ることを、了承した。指摘を受けて「生徒が文の中に書いた名前などは、そのまま送られる」ことを伝え直し、それでもよいと確かめた。
- まとめの 5 つの項目（クラス全体の様子／疑問のまとまり／まちがって覚えていそうな所／次の授業で取り上げるとよいこと／声をかけたい生徒）は、案のとおり。
- 鍵は、先生が GAS のスクリプト プロパティに入れる。チャット・コード・リポジトリには置かない。

## 2. 作ったもの（Claude Code が決めた動き）

- 「AI でまとめる」を押したときだけ送る。確かめの窓で、人数と、送るものの説明を出す。作ったまとめは `aiSummaries/<クラス>/<授業>`（先生だけが読み書きできる）に保存し、次からは保存したものを出す。
- 流れ: 先生の画面 → 中つぎ → GAS（`summarize`。先生だけ）→ OpenAI の Responses API。鍵（`OPENAI_API_KEY`）とモデルの名前（`OPENAI_MODEL`）は、GAS のスクリプト プロパティから読む。
- 送るもの: 授業名、重要用語、文字で書いた「分かったこと」「疑問」「メモ」、理解度、出席番号の呼び名。送らないもの: 名前・ID・クラス名・学校名の欄、手書き、写真、PDF。文の中の、生徒の ID・メールアドレス・10 けた以上の数字は、送る前に伏せる。文の中に書かれた名前は、見分けられないので、そのまま送られる。
- AI を 2 回呼ばない（失敗しても、自動ではやり直さない）。AI の返事は、GAS とブラウザの両方で確かめて整えてから出す（送っていない呼び名は落とす）。
- GAS は `app-4`。規則の確認は 107 項目。中つぎ（`relay/worker.js`）は変えていない。
