# 授業ログアプリ 設計書（全体の段階分けと、初期版の設計）

作成日: 2026-11-12　／　もとにした資料: `授業ログアプリ_要件定義書.md`（以下「要件定義書」）と、2026-11-12 の会話

この設計書は、要件定義書の全体を段階に分け、初期版で作るものを決める。実装計画は、この設計書の承認後に別のファイルとして書く。

「ユーザーの決定」と書いた項目はユーザーが会話で決めたこと。「Claude の判断」と書いた項目は Claude Code が決めたことで、ユーザーは変更できる。要件定義書とこの設計書が違うところは、この設計書を優先する（違いは 2 章にまとめた）。

## 1. 目的

授業 1 回ごとに、先生の板書・配布資料と、生徒自身のメモ・写真・振り返りを 1 か所に残す。生徒はあとから「その日どんな授業をしたか」を見返せる。先生は生徒一人ひとりの理解度と疑問を読める。

初期版が成功した状態（ユーザーの決定）:

- 授業中、生徒は iPad で授業ページを開き、先生のプリント（PDF）や板書を見る。メモは、アプリに文字か手書きで書く。紙のプリントに書いた生徒は、写真に撮って自分の記録に加える。
- 授業の終わりに、生徒が振り返り（理解度・分かったこと・疑問）を入力する。
- 先生は、板書の写真または事前に作った画像を、その授業のページに置く。
- 生徒が授業ページを開くと、板書・プリント・自分のメモ・振り返りが並んでいて、その日の授業が分かる。
- 放課後、先生は授業ごとに、理解度のグラフと全員分の振り返りを読む。

利用の規模（ユーザーの決定）: 生徒は合計約 100 人。1 クラスあたり週 4〜5 回の授業で使う。生徒 1 人が 1 回の授業で残す写真は 1〜2 枚。保存は卒業まで（3 年）。追加費用なし。

## 3. 全体の段階分け（Claude の判断）

各段階は、それだけで授業に使える状態で終える。段階 1b 以降は、前の段階を使った結果を見てから実装計画を書く。

| 段階 | 内容 |
|---|---|
| 0 | 接続確認。学校の iPad と学校のネットワークから、Firebase と「先生の Drive に保存する仕組み」が使えるかを、小さな確認ページで確かめる（6 章） |
| 1a（初期版の前半） | ログイン、先生のクラス・名簿・ID 発行、単元と授業、先生の資料（写真・PDF）、生徒の授業一覧（サムネイル）、授業ページ、文字のメモ、振り返り（文字）、先生の記録確認（グラフ・一覧・コピー）、年度の切り替え |
| 1b（初期版の後半） | 手書き（メモと振り返り）、生徒の写真・PDF の添付 |
| 2 | 先生から生徒の疑問へのコメント返し |
| 3 | 生徒が自分の記録を自分の Drive に残すための書き出し（3.1）。年度末（2027 年 3 月）より前に使える状態にする |
| 4 以降 | PDF・写真への直接書き込み、オフラインでの記録、アプリ内の自動要約、参加コード、卒業後の削除と復元 |

1a と 1b に分ける理由: 手書きと添付は、Drive への保存を多く使う部分で、動作の重さを段階 0 と 1a の結果で確かめてから作りたいため。1a だけでも「資料を見る・文字で書く・振り返る・先生が読む」が授業で使える。

### 3.1 生徒の Drive に記録を残す（段階 3。目的はユーザーの決定、方法は Claude の案でユーザーの確認待ち）

背景（ユーザーの説明）: 先生が市外に異動すると、学校の Google アカウントがなくなることがある。そのとき、先生の Drive に置いた写真・PDF とアプリの保存の仕組みは使えなくなる。別の先生のアカウントへ引っ越す方法ではなく、生徒が自分の Drive の中に記録を残せる方法がほしい。

方法の案:

- 生徒の画面に「記録をまとめて保存」を置く。年度または単元を選ぶと、その範囲の授業（先生の板書・配布資料、自分のメモ・手書き・写真、振り返り）を、授業ごとに順に並べた 1 つの読み物の画面にする。
- 生徒はその画面を、iPad の「プリント」→「PDF として保存」で PDF にし、自分の Google Drive（iPad の「ファイル」または Drive アプリ）に保存する。操作の手順を画面に図で示す。
- アプリは生徒の Google アカウントにログインしない（Google ログインを使わない決定と、本名や学校のメールアドレスを保存しない決定を守るため）。保存の操作は生徒自身が行う。
- 残るのは「読める形の控え」であり、アプリに読み込み直すことはできない。
- 先生の Drive が保存の本体であることは変わらない。先生の異動が決まったときは、その年度のうちに生徒へ書き出しを指示する運用になる。

初期版では、この書き出しがあとで作れるように、次だけを守る: 1 つの授業の全部の中身（資料・記録・添付・手書き）を、1 か所の処理で集められる作りにしておく。

## 4. 初期版（1a・1b）に入れるもの・入れないもの

### 入れるもの

- ログイン: 先生はメールアドレスとパスワード。生徒は ID とパスワード。
- 先生: クラスの作成、名簿の登録（生徒 ID の発行、クラスと出席番号の割り当て）、配布用の ID・パスワード一覧の印刷、パスワードの出し直し、単元の作成、授業の作成（日付・授業名・単元・対象クラス）、授業への写真・PDF の追加と削除、年度の切り替え（進級）。
- 生徒: 授業一覧（日付順・単元別、年度の切り替え）、授業ページ（先生の資料を見る、メモ、写真・PDF の添付、振り返り）、パスワードの変更。
- 先生の記録確認: クラスと授業を選び、理解度のグラフと全員分の振り返りを読む。生徒の授業ページを開く。全員分をコピーする。
- 自動保存と、保存状態の表示、保存に失敗したときの再試行。
- 練習モード（`?demo=1`。手元のパソコンだけで動く。ClassPulse と同じ考え方）。

### 入れないもの

- 先生のコメント・確認済みの印（段階 2）、生徒どうしの共有、記録の書き出し（段階 3）。印刷は ID 一覧だけ。
- PDF・写真の上への書き込み、オフライン対応（Service Worker）、アプリ内の自動要約、参加コード。
- 写真と PDF 以外のファイルの添付。先生を増やす画面（先生はユーザー本人だけ）。
- 卒業後の自動削除。保存期間の指定だけから、削除や公開を決めない（要件定義書のとおり）。

### してはいけないこと

- 生徒の記録・添付を、本人と先生以外が読めるようにする（URL やファイル ID を知っていれば開ける、という作りも含む）。
- 生徒の本名、学校のメールアドレスなど、個人が分かる情報をアプリに保存する。
- 「提出」の操作を作って、提出するまで先生に見えないようにする（書きかけも先生に見える）。
- 課金の設定（Firebase の Blaze プランなど）を前提にする。
- 進級のときに、過去の授業や記録を消す・移す。

### 5.1 これまでのアプリと同じにするところ（ユーザーの決定: 今までの作り方を参考にする）

- フォルダ: `C:\Users\yan12\Documents\keita\AI開発\授業ログアプリ`。Git リポジトリにする。
- `CLAUDE.md` と `AGENTS.md` を ClassPulse（スライドアプリ）のものをもとに置く。Claude Code が設計と指示書、サブエージェントが実装、Codex がレビュー（使えないときは別の Claude エージェント）。
- 実装指示書は `.ai-tasks/`、レビュー結果は `.ai-review/`。`tools/codex-implement.ps1`、`tools/codex-review.ps1`、`tools/pages-branch.ps1` をスライドアプリからコピーして使う。
- 要件定義書を `docs/requirements.md` に置く（原本はそのまま残す）。
- HTML・CSS・JavaScript だけで書く。ビルドの工程とパッケージのインストールを使わない。
- ロジックは `node --test` で確かめる（`npm test`）。画面はブラウザで確かめる。
- iPad の Safari を基準にする。先生は教務用 PC のブラウザ（Chrome・Edge）でも使う。
- 公開は GitHub Pages（`pages` ブランチ）。
- フォントは BIZ UDPGothic、PDF を読む部品は pdf.js を、スライドアプリと同じ版・同じ置き方で使う。
- Firebase は SDK を入れず、REST で使う。通信の部分は 1 つのモジュールにまとめ、画面やロジックは URL や書式を直接知らない。スライドアプリの通信・ログインのコードを写して、このアプリ用に直す。

### 5.2 保存の仕組み（Claude の判断。保存先を先生の Drive にすることはユーザーの決定）

3 つの部品を使う。

| 部品 | 役割 | 無料の枠（2026-11-12 に公式情報で確認） |
|---|---|---|
| Firebase Authentication | 先生と生徒のログイン | 無料 |
| Firebase Realtime Database | 文字の情報（クラス、名簿、単元、授業、文字のメモ、振り返り、一覧用の小さい画像、ファイルの目録） | 保存 1GB、受信 月 10GB、同時接続 100 |
| Google Apps Script（以下 GAS）のウェブアプリ + 先生の学校用 Google Drive | 写真・PDF・手書きデータの保存と取り出し | GAS は無料。Drive は学校の容量を使う |

Firebase は ClassPulse とは別の、新しいプロジェクトを作る（無料の枠を分けるため）。Spark プラン（無料）のままにする。

使わないと決めたもの:

- Firebase の Cloud Storage: 2026 年 2 月以降、無料の Spark プランでは使えず、Blaze プラン（支払い方法の登録が必要）が要る。
- Firestore: 無料の保存は 1GiB。手書きや写真を入れると足りない。文字だけなら Realtime Database で足り、スライドアプリのコードを使い回せる。

量の見積もり（Claude の概算）:

| もの | 1 件の大きさ | 1 年 | 3 年 | 置き場所 |
|---|---|---|---|---|
| 生徒の写真 | 約 0.2〜0.3MB（長辺 1600px の JPEG に縮める） | 約 2 万 4 千枚、約 5〜7GB | 約 14〜20GB | Drive |
| 手書きデータ | 1 枚 約 0.03〜0.1MB | 最大で約 1.6GB | 約 5GB | Drive |
| 先生の写真・PDF | 写真 約 0.3MB、PDF は 10MB まで | 数 GB まで | — | Drive |
| 文字の記録 | 1 件 約 1KB | 約 16MB | 約 50MB | Realtime Database |
| 一覧用の小さい画像 | 1 枚 約 10KB | 約 15MB | 約 50MB | Realtime Database |

Realtime Database の「同時接続 100」は、REST で 1 回ごとに通信を閉じる使い方（EventSource で待ち受けない）にして、枠に当たらないようにする。このアプリには、画面をリアルタイムに同期する機能はない。

### 5.3 先生の Drive に保存する仕組み

- 先生が、自分の学校用 Google アカウントで GAS のプロジェクトを 1 つ作り、リポジトリの `gas/Code.gs` を貼って、ウェブアプリとして公開する（実行するユーザー: 自分、アクセスできるユーザー: 全員）。手順書を `docs/setup/` に用意する。
- アプリは、ファイルの保存・取り出しのたびに、ログイン中の Firebase の ID トークンを付けて GAS を呼ぶ。
- GAS は、そのトークンを使って Realtime Database から「この人はだれか（先生か、どの生徒 ID か）」を読む。トークンがにせものなら Firebase が断るので、これが本人確認になる。確認の結果は GAS の中に数分だけ覚えておき、毎回は問い合わせない。
- GAS は、次の決まりで開けるかどうかを自分で決める。**生徒が書きかえられる情報だけを根拠にしない**（たとえば、生徒が自分の記録に他人のファイル ID を書いても、開けないこと）。
  - 生徒個人のファイル（写真・PDF・手書き）: 持ち主の生徒 ID と先生だけ。
  - 先生の資料: 先生と、その授業の対象クラスに所属している（または過去に所属していた）生徒。
- Drive の中のファイルは、だれとも共有しない（リンク共有にしない）。開けるのは GAS を通したときだけ。
- 取り出したファイルは、端末の中（Cache API か IndexedDB。アプリが自分で入れる）に取っておき、同じファイルを何度も GAS に取りに行かない。
- GAS のウェブアプリをブラウザから呼ぶときの決まり（点検で分かったこと。実装計画はこれを前提にする）:
  - トークンはヘッダーではなく本文に入れ、`text/plain` の POST で送る（ヘッダーを足すと事前確認の通信が飛び、GAS が応答できない）。
  - GAS は常に「成功（200）」を返すので、成否は返ってくる JSON の中で表す。
  - GAS の中でエラー・時間切れ・混雑が起きると、アプリからは「通信に失敗した」としか見えない。圏外と区別できないので、どちらも同じ「やり直し」で扱う。
  - 失敗に見えても保存は済んでいることがある。保存は、端末が作ったキーを付けて送り、同じものを 2 回送っても 1 個になるようにする。
  - ファイルは base64 の文字にして受け渡す（約 1.33 倍の大きさになる）。
- GAS には同時に動ける数と 1 日の実行時間に上限がある（公式の表では 1 日の実行時間は Workspace で 6 時間。同時実行は 1 人あたり 30 という情報があるが、公式の表では未確認）。生徒全員の呼び出しが先生 1 人の実行として数えられるので、1 クラスが同時に授業ページを開く授業の始まりが、いちばん混む。このため、次を守る。
  - 1 つの授業の先生の資料は、1 個ずつではなく、1 回の呼び出しでまとめて取り出す（大きい PDF は、開くときに別に取り出す）。
  - 1 台の端末からの GAS の呼び出しは、同時に 1 つだけにする（順番に行う）。
  - 失敗したときは、端末ごとにばらばらの間をあけて自動でやり直す。
  - 手書きの保存は、書き終わって数秒たってから、かつ前の保存から 30 秒以上あけて行う。アプリの中で授業ページを離れるとき（「一覧へ」）にも保存する。保存までの間は端末の中に下書きを残す。
  - 先生の記録確認で手書きの振り返りを並べるときは、1 人ずつではなく、まとめて 1 回で取り出す。
- 写真は端末で縮めてから送る。PDF は 1 つ 10MB まで。生徒の添付は 1 回の授業につき 6 個まで（Claude の判断）。
- Drive の中では、ファイルの目録（どのファイルがだれの・どの授業のものか）を GAS 側でも持ち、あとで別の保存先へ引っ越せる形にしておく。

### 5.4 ログインと ID（方式は Claude の判断。「ID を先生が事前に作る」「出席番号だけ」はユーザーの決定）

- 先生: Firebase のコンソールで、ユーザー本人が自分のアカウントを 1 つ作り、データベースの `teacherList` に登録する（ClassPulse と同じ）。アプリに新規登録の画面は作らない。
- 生徒 ID: 入学から卒業まで変わらない番号（例: `s26-017`。入学年度と連番）。出席番号とは別。先生の画面でまとめて発行する。
- Firebase のログインはメールアドレスの形が要るので、アプリが ID から、専用のメールアドレスを作って使う（生徒はメールアドレスを見ない・入力しない）。
  - このメールアドレスは、**だれもメールを受け取れないドメイン**で作る。Firebase のパスワード再設定メールは、だれでも送らせることができるため、他人が受け取れるドメインだと乗っ取りの道になる。第 1 候補は `.invalid` で終わるドメイン。Firebase が受け付けない場合は、メールを受け取る仕組みのない別のドメインにする。どれを使えるかは段階 0 で確かめる。
- 最初のパスワードは、アプリが自動で作る（8 文字。読みまちがえやすい文字を除く）。先生の画面で「ID・最初のパスワード」の一覧を印刷できる。一覧には名前を手で書き込む欄を空ける。どの ID がだれかの対応は、アプリの外（先生の手元）で持つ。
- 生徒は、ログイン後に自分でパスワードを変えられる。新しいパスワードは 8 文字以上で、自分の ID を含まないものだけを受け付ける（画面側の検査。Claude の判断）。ID は連番で推測できるので、弱いパスワードを許すと他人になりすませるため。
- パスワードの出し直し: 先生の画面で、その ID に新しいログイン用アカウントを発行し、古いアカウントを記録から切り離す。記録は「生徒 ID」に結び付けて保存するので、出し直しても記録はそのまま残る。（Firebase は、無料の枠と管理用の鍵なしでは、他人のパスワードを直接書きかえることも、アカウントを消すこともできないため、この方法にする。）
  - 古いアカウントは元のメールアドレスを持ち続けるので、新しいアカウントは「ID + 何回目か」から作る別のメールアドレスになる。ログイン画面が ID から正しいメールアドレスを決められるように、「ID → 今は何回目か」の表を、ログイン前でも読める場所に置く（中身は数字だけ）。
  - 切り離しは、「アカウント → 生徒 ID」の対応を消すことで行う。GAS が本人確認を覚えておく時間は 1 分までにし、出し直しのあとに古いアカウントでファイルを開ける時間を短くする。
  - 発行しようとしたメールアドレスがすでに使われていた場合は、回数を 1 つ進めて発行する。
- アカウントの発行には「1 時間に 100 件まで」という Firebase 側の上限があるので、名簿の一括発行は、上限に当たったら待ってから続きを行えるようにする。
- 最初のパスワードは、印刷のために先生だけが読める場所に保存する。生徒が自分でパスワードを変えたあとは、その ID の保存分を消す。
- ログインの状態は端末に残す（毎回の入力を求めない）。iPad は 1 人 1 台なので、端末に取っておいた資料や下書きを生徒ごとに分ける作りは要らない。「ログアウト」は置き、押したときに、端末に取っておいたファイルと下書きを消す（送れていない下書きがあるときは、先に知らせる）。

### 5.5 年度と進級

- クラスは年度ごとに作る（例: 2026 年度 2 年 A 組）。所属は「年度・クラス・出席番号・生徒 ID」の組で登録する。
- 進級のとき、先生は新しい年度のクラスを作り、生徒 ID を新しいクラスと出席番号に割り当てる。前の年度のクラス・授業・記録には手を付けない。
- 生徒は、授業一覧の「年度」を切り替えて、前の学年の授業と自分の記録を見られる。前の年度の記録も書き足せる（Claude の判断。復習で使うため）。
- 先生も、過去の年度のクラスと記録を見られる。

### 5.6 ユーザーにお願いする作業

- Firebase のプロジェクトを新しく作り、Realtime Database と Authentication（メール／パスワード）を有効にし、規則を貼る。自分の先生アカウントを作る。
- 学校用 Google アカウントで GAS のプロジェクトを作り、コードを貼って公開する。
- GitHub に新しいリポジトリを作り、Pages を有効にする。
- 段階 0 の確認ページを、学校の iPad で学校のネットワークから開く。

どれも手順書を用意する。パスワードなどの秘密はリポジトリに入れない。Firebase の設定値と GAS の URL は公開してよい値で、データを守るのは規則と GAS の確認である。

## 6. 段階 0: 接続確認

確認ページ（`check.html`）と、確認用の小さな GAS で、次を確かめる。ここで使えないものが見つかったら、初期版を作る前にユーザーと代わりの方法を相談する。

1. 学校の iPad・学校のネットワークから、Firebase（ログインとデータベース）につながる。
2. 実在しない専用のメールアドレスの形で、生徒用のアカウントを作ってログインできる。
3. 先生の学校用アカウントで、GAS のウェブアプリを「全員」がアクセスできる設定で公開できる（学校の設定で止められていないか）。
4. 学校の iPad から GAS を呼び、写真 1 枚を先生の Drive に保存し、取り出して表示できる。かかる時間を記録する。
5. 同じことを家庭のネットワーク（学校の外）からもできる。
6. 混み合いの確認: 確認ページの「同時に 40 回呼ぶ」ボタンで、1 クラスが同時に授業ページを開いたときに近い呼び出しを行い、成功した数・失敗した数・かかった時間を記録する。できれば、実際に 1 クラスの iPad で同時に開いてもらう。
7. 先生の学校用 Drive の空き容量（3 年で 30GB ほど置けるか）を、Drive の画面で見て記録する。
8. 確認ページに、iPad の機種と iPadOS の版、端末の中の保存（localStorage・IndexedDB）が使えるかどうかを表示し、記録する。

3 が止められていた場合の候補（そのときに相談する。今は決めない）: 学校の管理者に設定を頼む、先生の個人の Google アカウントを使う（15GB まで。学校の決まりの確認が要る）、Firebase の有料プランの無料分を使う（支払い方法の登録が要る）。

## 7. 画面

画面は 1 つの `index.html` の中で切りかえる。会話で見せた見本は `.superpowers/brainstorm/6260-1794483811/content/` にある（`student-lesson-layout.html` の A 案、`student-list-thumbnails.html`、`list-and-teacher-review.html` の ②）。配色と書体は見本と ClassPulse をもとに Claude が決める。

共通: iPad で押しやすい大きさのボタン（44px 以上）、読みやすい文字の大きさ。先生の資料は青系、生徒自身の記録は黄土色系の見出しと枠で区別する（色だけでなく「先生の資料」「自分の記録」の文字でも示す）。

### 7.1 ログイン

「ID またはメールアドレス」と「パスワード」の 2 つの欄。`@` があれば先生、なければ生徒として扱う。まちがえたときは文字で理由を出す。

### 7.2 生徒の授業一覧（ユーザーの決定: サムネイル形式）

- 上部: クラス名、自分の出席番号、「日付順／単元別」の切り替え、年度の選択、メニュー（パスワードの変更、ログアウト）。
- 授業をタイルで並べる。iPad 横向きで横 4 枚、縦向きで 3 枚。新しい授業が先。日付順では「今週」「先週」、それより前は月ごとに区切る。単元別では、同じタイルを単元名の見出しごとに並べる（単元のない授業は「その他」）。
- タイル: 上にサムネイル、下に日付・授業名・印（「記録あり」「振り返りがまだ」）。
  - 「振り返りがまだ」: 理解度を選んでいない。「記録あり」: 理解度を選んである。
- サムネイル（ユーザーの決定）:
  - 板書の写真があれば、その 1 枚目。板書がなければ、先生の PDF の 1 ページ目。先生の資料が何もない授業だけ、灰色の枠に授業名を出す。生徒自身の写真は使わない。
  - 先生の資料が複数あるときは、サムネイルの上で左右に指をすべらせると次の画像に切り替わる（Instagram の複数枚の投稿のように）。下に小さな点で、枚数と今の位置を示す。並び順は、板書の写真が先、PDF の 1 ページ目が後（点と並び順は Claude の判断）。
  - 軽く押すと授業ページを開く。すべらせる操作と押す操作を区別する。PC では左右の矢印でも切り替えられる。
- 一覧用の画像は、先生が資料を追加したときに端末で小さく作り（長辺 320px ほど）、Realtime Database に保存する。一覧は新しい授業から少しずつ読み込み、読んだ画像は端末に取っておく。

### 7.3 生徒の授業ページ（ユーザーの決定: 左右に並べる）

- 上部: 「一覧へ」、日付と授業名、保存状態。
- 左（先生の資料）: 板書の写真と PDF。押すと大きく表示する（写真は拡大・縮小、PDF はページ送り）。大きく表示している間も、閉じればすぐ右側に戻れる。
- 右（自分の記録）: 上から、メモ、自分の写真・PDF、振り返り。
  - メモ: 「手書き／文字」を切り替える。両方の内容を別々に保存し、切り替えても消えない。（1a では文字だけ。）
  - 自分の写真・PDF（1b）: 「＋ 写真・PDF」で、カメラで撮る・写真から選ぶ・ファイルから選ぶ。小さく並べ、押すと大きく表示する。削除できる（確認を出す）。
  - 振り返り: 理解度（4 つのボタンから 1 つ。選び直せる）、「分かったこと・学んだこと」、「疑問・まだ分からないこと」。文章の 2 つは、それぞれ「手書き／文字」を切り替えられる（1a では文字だけ）。
- 縦向きでは、左右ではなく上下（資料が上、記録が下）に並べる。
- 必須の項目はない。文字は 1 つの欄につき 2000 文字まで（Claude の判断）。

### 7.4 手書き（1b）

- 生徒はペンを持っているが、指で書くこともある（ユーザーの説明）。
- 手書きの欄に「書く／動かす」の切り替えボタンを置く（ユーザーの決定）。「書く」のときは、指でもペンでも線を引ける。「動かす」のときは、指で触れても線を引かず、画面を上下に動かせる。
- ペン（Apple Pencil など）は、「動かす」のときでも線を引ける。ペンで書いている間は、手のひらが触れても線を引かない（Claude の判断。ペンの生徒が切り替えを押さずに済むように）。
- 手書きの欄を開いたときは「動かす」から始める（Claude の判断。ページを動かそうとして、うっかり線を引くのを防ぐ）。今どちらなのかを、色と文字で示す。
- 道具: ペン（黒・赤・青、太さ 2 種類）、消しゴム（線ごとに消す）、1 つ戻す、全部消す（確認を出す）。
- 書く場所は、下に足していける（縦に長くできる）。
- 画像ではなく、線の座標として保存する（容量を小さくするため、点を間引く）。
- iPad の Safari は 1 枚の描画領域の大きさに上限があるので、縦に長い手書きは、見えている範囲だけを描く方式（または SVG）で作る。1 枚の大きな canvas にはしない。

### 7.5 先生のクラス・授業管理

- クラス: 年度ごとの一覧、作成、名前の変更。
- 名簿: 生徒 ID をまとめて発行（人数を入れる）、クラスと出席番号の割り当て（表で入力。前年度のクラスから ID を引き継いで割り当てる操作を用意する）、ID・最初のパスワード一覧の印刷、パスワードの出し直し。
- 単元: 作成、名前の変更、並べ替え。
- 授業: 日付・授業名・単元・対象クラスを入れて作る。同じ内容を複数のクラスに行うときは、対象クラスを複数選ぶと、クラスごとに別の授業として作られる（板書がクラスごとに違うため。Claude の判断）。作成後も、日付・授業名・単元を直せる。
- 複数のクラスに同じ配布資料を付けるときは、ファイルを 1 回だけ上げ、選んだクラスの授業すべてに付けられる（Claude の判断）。ファイル本体は 1 つで、複数の授業から指す。1 つの授業から外しても、ほかの授業が指している間は本体を消さない。
- 授業の資料: 写真（カメラ・写真・ファイル）と PDF を追加する。追加のときに種類（板書／配布資料）を選ぶ。並べ替えと削除ができる。授業の前でも後でも追加できる。
- 授業の削除: 生徒の記録が 1 件でもある授業は消せない（Claude の判断。初期版にはゴミ箱がないため）。

### 7.6 先生の記録確認（ユーザーの決定: 見本のとおり）

- クラスと授業を選ぶ。
- 左: 理解度の棒グラフ（4 段階それぞれの人数と、「まだ入力なし」の人数）。
- 右: 全員分の振り返りの一覧。「疑問」と「分かったこと」を切り替える。1 行に、出席番号・理解度・文章（手書きは小さい画像）。並び順は、理解度が低い順（入力なしは最後）と出席番号順を切り替えられる。書きかけもそのまま出す。
- 「全員分をコピー」: 今出している項目の全員分の文章を、出席番号も ID も付けずに、1 人 1 行でコピーする（先生が自分の使っている AI に貼って要約させるため）。手書きの分は「（手書き N 件は含まれていません）」と添える。
- 行を押すと、その生徒の授業ページを読み取り専用で開く（メモ・写真・振り返りを含む）。前の人・次の人へ移れる。

## 8. 保存とエラー

- 自動保存（Claude の判断）。文字と理解度は、変更の約 2 秒後に保存する。手書きと添付は 5.3 のとおり。
- 保存状態を上部に文字で出す:「保存中」「保存しました」「保存できませんでした（再試行）」。
- 保存に失敗しても、入力中の内容は画面と端末の中に残す。自動で数回やり直し、それでもだめなら「再試行」を押せるようにする。
- iPad の Safari は、タブを閉じる・ホーム画面に戻るときに、確認を出すことも、保存の処理を確実に走らせることもできない。このため、守れるのは次の 3 つとする: アプリの中の移動（「一覧へ」など）での保存と「まだ保存できていません」の知らせ、端末の中の下書き、次に開いたときの送り直し。
- Safari は、7 日間そのサイトを使わないと端末の中の保存を消すことがある。長い休みのあとは、ログインし直しになり、送れていなかった下書きは失われる。下書きは一時的な保険として扱い、保存状態の表示で「保存しました」になったことを生徒が確かめられるようにする。
- 通信が切れている間は「接続が切れています」と出す。つながったら自動で保存する。（通信が切れたまま、開いていない授業を新しく開くことはできない。これはオフライン対応の範囲で、後の段階。）
- 同じ生徒が 2 つの端末で同じ授業を同時に書いた場合は、後から保存したほうが残る（Claude の判断。初期版では食い違いを細かく扱わない）。授業ページを開いたときと、画面に戻ってきたときに、最新の内容を読み直す。
- 写真の送信に失敗したら、その写真に「送れませんでした（やり直す）」と出す。

## 9. 保存する情報のまとまり

細かい形は実装計画で決める。守ることだけを書く。

| まとまり | 中身 | 読める人 | 書ける人 |
|---|---|---|---|
| 先生の一覧 | 先生のアカウント | 本人 | コンソールのみ |
| アカウントと生徒 ID の対応 | ログイン用アカウント → 生徒 ID | 本人と先生 | 先生 |
| 最初のパスワード | 生徒 ID → 最初のパスワード | 先生 | 先生（消すのは本人も可） |
| クラス・所属 | 年度、クラス名、生徒 ID、出席番号 | 先生と、所属する生徒 | 先生 |
| 単元・授業 | 単元名、日付、授業名、対象クラス、資料の目録、一覧用の画像 | 先生と、対象クラスの生徒 | 先生 |
| 生徒の記録 | 生徒 ID × 授業: 文字のメモ、理解度、振り返りの文章、添付と手書きの目録、更新日時 | 本人と先生 | 本人 |
| ファイル本体（Drive） | 写真、PDF、手書きデータ | GAS が 5.3 の決まりで判断 | 同じ |

- 生徒は、自分が所属していない（過去にも所属していなかった）クラスの授業を読めない。
- 生徒は、ほかの生徒の記録を、読むことも書くこともできない。
- 規則のテスト（だれが何を読めて、何を読めないか）を手順書に入れ、公開の前に確かめる。
