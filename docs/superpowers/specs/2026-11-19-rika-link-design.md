# 設計書: 授業ログと理科クエストをつなぐ

2026-11-19。先生と決めた内容と、段階の計画です。モックアップは `docs/mockups/rika-link.html`。

## 1. 目的

理科クエスト（`理科アプリ`。公開先 `…github.io/Rika_app/`）を、授業ログの生徒が自分のアカウントのまま使えるようにする。記録は生徒ごとに残し、どの端末でも続きができるようにする。

今の理科クエストは、ログインが無く、記録が端末のブラウザの中だけにある。タブレットが変わると記録が消え、個人のデータとして管理できない。

## 2. 先生の決定（2026-11-19）

| 点 | 決定 |
|---|---|
| 入れ方 | アプリ（コードと公開先）は別のまま。ログインと記録の置き場所だけ 1 つにする |
| 入口 | 授業ログの生徒の最初の画面のいちばん上に置く |
| 授業の記録 | 理科クエストの結果は、授業ログの授業の記録には出さない |
| 単元 | 先生がクラスごとに「今の単元」を決める。決めていないクラスは、生徒が選ぶ |
| ほかの単元 | 生徒は、先生が決めた単元のほかにも進めてよい |
| 今日のクエスト | 今までどおり、アプリが生徒ごとに自動で決める（`js/recommend.js`） |
| ログインなし | 使える。そのときは「この端末だけ」と帯で知らせる |
| 端末にある前の記録 | 初めてつないだときに、中身を見せて聞いてから引きつぐ |
| 記録の置き場所 | 授業ログと同じ Firebase（`jyugyolog`）。生徒本人と先生だけが読める |
| 先生の確認 | クラスの進み具合を見る画面を作る（あとの段階） |
| 理科アプリの書きかえ | 許可（この作業のため） |

## 3. しないこと

- 理科クエストのコードや教材を、授業ログの中に移さない（書き方がちがい、教材が約 3.6 MB ある）。
- ライブクイズ（別の Firebase `rika-quest`。ログインなし）は変えない。
- 本名・メールアドレスを保存しない。ニックネームは今までどおり「実名は入れない」。
- Firebase の無料プラン（Spark）をこえない。

## 4. しくみ（Claude Code の案）

- 2 つのアプリは同じ住所（`schooldatahuruyama-lgtm.github.io`）の下にあるので、ブラウザの保存場所（localStorage）を共有している。授業ログのログインは `jugyolog:auth`（`{ uid, refreshToken }`。`js/auth.js`）に入っている。理科クエストはこれを**読むだけ**で、同じアカウントの通行証を取り直せる。ID やパスワードは入れ直さない。
- 理科クエストは `jugyolog:auth` を書きかえない・消さない。ログアウトは授業ログの側だけで行う。
- 記録は、まず今までどおり端末に保存する（`rika-quest:v1`）。そのあと、つながっていれば Firebase へ送る。通信が無いときは学習を止めず、送れていない件数を帯で知らせ、つながったときに送る。
- データの置き場所（案。名前は段階 2 の指示書で確定する）:

| 場所 | 中身 | 読める人 | 書ける人 |
|---|---|---|---|
| `rika/records/<生徒の uid>` | その生徒の理科クエストの記録（ニックネーム・アバター・進み具合） | 本人・先生 | 本人 |
| `rika/classUnit/<クラスの id>` | 先生が決めた「今の単元」の id | そのクラスの生徒・先生 | 先生 |

- 規則（`docs/setup/rules.json`）に上の 2 つを足し、「規則の確認」にも項目を足す（ほかの生徒の記録を読めない・書けない、生徒が単元を書きかえられない、など）。

## 6. 端の場合（段階 2・3 の指示書に、くわしく書く）

- 不正な入力: Firebase から読んだ記録が壊れている・形がちがう・とても大きいときは、端末の記録を上書きしない。帯で「記録を読みこめませんでした」と知らせる。先生が決めた単元の id が、教材に無い id のときは、「決めていない」と同じに扱い、先生の画面に印を出す。
- 重複と境界: 2 台の端末で同じ生徒が学習したときに、どちらを残すか（新しい方を残す／合わせる）は、段階 0 で記録の形を見てから決め、実装の前に先生に伝える。共用の端末で別の生徒がログインしたときは、前の生徒の記録を見せない。
- 違反や失敗の見せ方: 送れていない記録は、件数を黄色の帯で出す。だまって捨てない。ログインが切れたときは、灰色の帯にして「授業ログにログインする」を出す。

## 10. 段階 2b の結果（2026-11-19。授業ログ `54b994b`、理科アプリ `4e327f3`）

記録を、授業ログのアカウントに保存する。実装は、どちらも Codex。

### 先生と決めた動き

1. ログインして開くと、アカウントの記録を読みこんで続きから始まる。
2. 2 台で同じ生徒が学習したら、どちらの分も残して合わせる。
3. 通信がないときは、端末にためて、黄色の帯で件数を知らせ、つながったら送る。
4. 共用のタブレットでは、ログインした生徒の記録だけが出る（プロフィールの切りかえは出さない）。
5. 初めてつないだとき、端末に前の記録があれば、中身を見せて「わたしの記録です／ちがいます」を選ぶ。
6. ログインなしでは、今までどおり端末の中だけ。

### 作り（Claude Code が決めた）

- 置き場所: `rika/state/<uid>`（今の状態。`{ v, updatedAt, json, base }`）と `rika/log/<uid>/<id>`（履歴のかたまり。1 回だけ書ける）。キーは Firebase の uid。読めるのは本人と先生。先生は消すことだけできる。
- 古い状態からの上書きは、規則で止める（`base` が今の `updatedAt` と同じで、`updatedAt` が大きいときだけ書ける）。拒まれた端末は、読み直して合わせてから送り直す。
- 端末では、ログイン中はアカウントごとの入れ物（`rika-quest:acct:<uid>`）を使う。同期の情報も同じ入れ物の中に置き、一緒に保存する。端末モードの入れ物（`rika-quest:v1`）は別。
- 履歴の 1 件ごとに固有の番号（`eid`）を付け、同じ番号は 1 回だけ数える。
- 端末に保存できないまま入れ物の切りかえが要るときは、切りかえを進めず、帯で「『記録を書き出す』で残してください」と知らせる。

### 分かっている限界

## 11. 段階 3 の結果（2026-11-20。授業ログ `b9d996f`、理科アプリ `b2fb571`・`021f17b`）

先生がクラスごとに「今の単元」を決める。実装は、どちらも Codex。

### 決めた動き（Claude Code が決め、実装の前に先生に伝えた）

| 点 | 動き |
|---|---|
| 先生が決める場所 | 授業ログの「クラス」の一覧。クラスごとに「理科クエストの単元」が出て、「単元を決める」で 20 個の単元から選ぶ。「決めない」にも戻せる |
| 生徒の入口のカード | 「今の単元: 1年 光の世界」と出る。決めていないクラスでは出ない |
| 理科クエストでの効き方 | 先生が単元を変えると、生徒が次に開いたときに、その単元に 1 回だけ切りかわる。そのあと生徒がほかの単元を選ぶのは自由。先生が決めた単元には印が付き、「この単元にする」で戻れる |
| クラスが 2 つ以上ある生徒 | いちばん新しい年度のクラスの単元を使う |
| 教材にない単元の id | 理科クエストでは「決めていない」と同じ。先生の画面には「教材にない単元です」の印 |
| 読めなかったとき | 学習は止めない。前に受け取った単元のまま続ける |
| ログインなし・先生のアカウント | 今までどおり（自分で選ぶ） |

### 作り

- 置き場所: `rika/classUnit/<classId>` = 単元の id の文字列。先生が書き、先生とそのクラスの生徒が読める。
- 授業ログは、理科クエストの単元の表の写し（`js/rika-units.js`）を持つ。理科クエストの単元を足した・変えたときは、ここも直す。
- 理科クエストは、`accounts/<uid>` → `memberOf/<生徒の ID>` → `classes/<classId>` → `rika/classUnit/<classId>` の順に読む（読むだけ）。記録の送り受けとは別に動かす。
- 受け取りずみの印（`classUnitApplied`）と、受け取った時刻（`classUnitAppliedAt`）をプロフィールに持つ。2 台の端末で食いちがうときは、時刻の新しい方を残す。「決めない」を受け取ったときも時刻を残す。

### レビュー

### 公開後に見つけた不具合（直した）

理科クエストの新しい版に入れかわる途中、古い `index.html` と新しい `js/app.js` がまざり、新しい部品（`js/class-unit.js`）が無くてアカウントのモードに入る処理が止まった（開き直すと直る）。部品が無いときは、単元の読みこみだけをやめて先へ進むように直した（`021f17b`）。直す前の版（`b2fb571`）が公開されていたのは、2026-11-20 の 15 分ほど。

### 分かっている限界

- 2 台の端末の時計が大きくずれていると、先生の単元が 1 回よぶんに当たり、生徒が選んだ単元が先生の単元に戻ることがある（選び直せる）。
- クラスを消す操作はアプリに無いので、消したクラスの単元が残ることはない。Firebase のコンソールでクラスを消したときは、`rika/classUnit/<classId>` も消す。
- 理科クエストの単元を足した・id を変えたときは、授業ログの `js/rika-units.js` も直す。
