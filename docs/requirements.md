# 授業ログアプリ 要件定義書

プロジェクト名：授業ログアプリ（仮称）　初版：2026年11月11日

# 概要

先生が用意した授業の板書写真・配布資料に、生徒が自分の写真、メモ、振り返りを追加して残す。授業中の記録、授業の終わりの振り返り、家庭での復習を一つにつなげ、過去の授業を卒業まで見返せるようにする。

解決する課題は、①板書や資料が散らばって探しにくいこと、②生徒の学びや疑問が積み重なりにくいこと、③先生が一人ひとりの理解や疑問を把握しにくいこと。先生が共有する授業資料と、生徒個人の記録を授業ごとにまとめる。

# ターゲットユーザー

| 項目 | 想定 |
|---|---|
| 先生 | ご本人。担当クラスの授業と生徒の記録を扱う |
| 生徒 | 担当する中学生、合計約100人 |
| 生徒の端末 | iPad |
| ログイン | 先生・生徒とも学校のGoogleアカウント |
| 使用場面 | 授業中、授業の終わり、家庭での復習 |
| 保存期間 | 各生徒の卒業まで。進級後も過去の授業記録を残す |
| 費用の条件 | 写真・PDFの保存を含め、追加費用なしを条件に方式を選ぶ |

約100人は利用者の合計。同時に利用・保存する人数は未設定で、実装時の動作確認に向けて授業の使い方に合わせて見積もる。先生の利用端末は未決定。

# アプリのゴール

## WHO 誰に

担当する生徒と、その授業を受け持つ先生。

## WHAT 何を

1回の授業について、先生の板書・配布資料、生徒自身の写真・PDF、文字や手書きのメモ、共通項目の振り返りをまとめて残せる場所を提供する。

## HOW どうなってもらいたいか

- 生徒は必要な授業資料を探しやすくなり、学んだことや疑問を後から見返せる。

- 生徒は授業中から家庭での復習まで、同じ授業の記録を積み重ねられる。

- 先生は生徒一人ひとりの記録を読み、理解や疑問を確認できる。

# 主要機能

## 必須機能 MVP

| 機能 | 初期版でできること |
|---|---|
| ログイン | 学校のGoogleアカウントで、先生・生徒が自分の画面に入る |
| クラス管理 | 先生がクラスを用意する。参加コードによる参加と、先生による名簿登録の両方を使える |
| 授業ページ | 先生が日付・授業名を登録し、生徒が記録する授業を用意する。単元別の整理に必要な情報も持たせる |
| 共通資料の共有 | 先生が板書の写真やPDFを授業に追加し、対象の生徒に共有する |
| 生徒の添付 | 生徒が自分の授業記録に写真・PDFを追加する |
| 自由メモ | 生徒が文字入力と手書きの両方で記録できる |
| 共通の振り返り | 全授業で同じ項目を使う。文章による振り返りも、文字入力・手書きに対応する |
| 先生の閲覧 | 先生が生徒の記録を閲覧できる。書きかけの内容も確認対象にする |
| 公開範囲 | 生徒自身が追加した記録は、その生徒と担当の先生だけが見られる |
| 過去の授業の閲覧 | 日付順と単元別を切り替え、アプリ内で見返せる |
| 進級後の継続 | 年度が変わっても過去の記録を残し、卒業まで見返せる |

## 振り返り項目の仮決定

| 項目 | 入力の形 |
|---|---|
| 今日の理解度 | 選択肢から選ぶ。段階数・選択肢の文言は未決定 |
| 分かったこと・学んだこと | 文章や手書きで記録する |
| 疑問・まだ分からないこと | 文章や手書きで記録する |

この3項目を当面の共通項目とする。内容は後から要件を見直す可能性がある。授業ごとに項目を変更する方式や、先生が項目を自由に編集する設定画面は、今回の合意には含まれない。入力を必須にする項目や文字数の上限は未決定。

## 追加予定機能

以下は「できれば入れたい」という希望であり、初期版への搭載はまだ決めていない。

| 追加候補 | 使い方 |
|---|---|
| 写真・PDFへの直接書き込み | 板書写真を丸で囲む、配布プリントに答えや気づきを書き足す |
| オフラインでの記録 | ネットにつながっていないときもメモ・振り返りを残し、再接続時に反映する |

自由メモや振り返りへの手書きは初期版の必須機能。写真・PDFの上への書き込みが追加候補となる。オフライン時に扱う資料・添付の範囲や、再接続時の詳しい動作は今後設計する。

## 今回の範囲

先生による生徒の記録への対応は閲覧のみとする。コメントや確認済みマーク、生徒同士の記録共有、記録をPDFにまとめる書き出し・印刷機能は今回の対象外。添付するファイルは写真とPDFとし、初期の利用範囲は先生ご本人の担当授業とする。

# 技術仕様

## 利用と保存の基本方針

生徒がiPadで利用し、学校のGoogleアカウントで本人を区別する。先生の授業資料、生徒ごとの記録、クラスの所属を関連付け、必要な相手だけに表示する。ブラウザで使う形式かインストールする形式か、保存先、サービスの組み合わせは未決定。

| 情報 | 作成する人と閲覧する人 |
|---|---|
| 授業の共通資料 | 先生が登録し、配布先のクラスの生徒と先生が見る |
| 生徒個人の写真・PDF・メモ・振り返り | 本人が記録し、本人と担当の先生だけが見る |
| 書きかけの個人記録 | 先生も閲覧できる。先生に見せるための提出操作を前提にしない |

個人記録の写真・PDFにも同じ公開範囲を適用する。進級時には過去の授業と本人の記録のつながりを維持する。卒業後の削除時期・削除方法・復元方法は未決定。

## 追加費用なしで使うための確認

追加費用なしを運用条件とする。現在は保存・実行方式を選ぶ前の段階であり、約100人分の写真・PDFを卒業まで保存できる容量と、必要な操作を処理できる量を確認して方式を決める。

学校のGoogle Driveを保存先の候補とする場合は、学校で実際に利用できる容量と、先生・生徒への割り当てを確認する。Google Workspace for Educationの保存容量は利用者間で共有され、管理者が利用者グループごとに上限を設定できる。[Google公式の保存容量の説明](https://knowledge.workspace.google.com/admin/getting-started/editions/overview-of-google-workspace-for-education-storage)

学校アカウントで使うアプリの設定も確認する。Googleの説明では、18歳未満の生徒が未設定の外部アプリを利用するには管理者によるアクセス許可が必要となる。今回のアプリの扱いは採用する方式に合わせて確認する。[Google公式の生徒向けアプリ利用設定](https://support.google.com/edu/classroom/answer/15163043?hl=ja)

写真・PDFの容量上限、1回の授業あたりの添付数、写真のサイズ調整、共有資料の保存方法は実装時に検討する。Googleログインの採用は確定しているが、Google Driveへの保存はまだ採用決定していない。

## データベース設計

保存する情報の整理案。具体的な保存サービスや内部の形式は今後決める。

| 情報のまとまり | 記録する内容の例 |
|---|---|
| 利用者 | 学校のアカウント、表示名、先生・生徒の区別 |
| クラスと所属 | 年度、クラス、担当の先生、所属する生徒、参加コード |
| 単元と授業 | 単元名、授業名、日付、対象クラス |
| 先生の資料 | 授業に対応する板書写真・PDF |
| 生徒の記録 | 授業と本人、文字・手書きのメモ、振り返り、本人の写真・PDF、更新日時 |

# UI/UX方針

## 画面で大切にすること

- 生徒が授業を選び、その授業の資料と自分の記録に迷わずたどり着ける。

- 先生の共通資料と、自分が追加した記録の違いが分かる。

- iPadで押しやすいボタンと、読みやすい文字の大きさを使う。

- 文字入力と手書きを選びやすくする。

- 日付順と単元別を切り替える操作を分かりやすくする。

## 画面構成のたたき台

以下は確認済みの使い方を画面にした案であり、配置・配色・書体・アプリ名は今後決める。

| 画面 | 主に行うこと |
|---|---|
| 生徒の授業一覧 | 日付順・単元別で授業を探す |
| 生徒の授業ページ | 先生の写真・PDFを見る、自分の写真・PDFを加える、文字・手書きでメモや振り返りを残す |
| 先生のクラス・授業管理 | クラス、参加コード、名簿、単元、授業資料を扱う |
| 先生の記録確認 | 授業や生徒を選び、記録・理解度・疑問を読む |

## 保存に失敗した場合の設計案

保存状況を分かりやすく示し、保存できなかったときは入力中の内容を保ちながら再試行できる形を検討する。自動保存か手動保存か、反映の頻度、通信が切れたときに端末内へ残す範囲は未決定。オフライン対応を採用する場合は、再接続時の反映や記録の食い違いを扱う方法も決める。

## 次の一手

まず、生徒の授業一覧と授業ページ、先生の記録確認画面の見本を作り、資料を見る・書く・見返すという一連の操作を具体化する。続いて、学校アカウントの利用設定と保存容量に合う方式を選び、初期版を実装する。

実装時に決める主な点は、理解度の選択肢、保存の方法、添付容量、卒業時の扱い、先生が使う端末、参加コードと名簿が重なったときの扱い。自動削除や卒業後の公開などを、保存期間の指定だけから決めない。

## 初期版で確認する動作

1. 先生がクラスと授業を作り、写真・PDFを共有できる。

2. 生徒が参加コードと名簿登録のどちらからでも、正しいクラスに参加できる。

3. iPadで文字・手書き・写真・PDF・振り返りを記録し、開き直して見返せる。

4. 生徒本人と担当の先生だけが、その生徒の記録と添付を開ける。

5. 先生が書きかけを含む記録を閲覧できる。

6. 日付順と単元別で同じ授業にたどり着ける。

7. 進級後も過去の授業記録を見返せる。

8. 実際の授業に近い人数・保存量で使い、追加費用なしの条件と保存の安定性を確認できる。
