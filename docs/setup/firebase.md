# Firebase の準備の手順書（段階 0）

授業ログは、ログインとデータの保存に Google の Firebase を使います。このページは、先生が自分で行う準備の手順です。順番にやれば大丈夫です。わからなくなったら、そこで止めて Claude Code に画面の様子を伝えてください。

**料金について:** プランは無料の「Spark プラン」のままにします。「Blaze プラン」への切り替えや、クレジットカードなどの支払い方法の登録はしません。画面に「アップグレード」と出ても押さないでください。

必要なもの: Google アカウントと、パソコンのブラウザ。

**ClassPulse とは別のプロジェクトを作ります。** 無料の枠を分けるためです。ClassPulse のプロジェクトは使わないでください。

---

## 1. プロジェクトを作る

1. ブラウザで https://console.firebase.google.com/ を開き、Google アカウントでログインします。
2. 「プロジェクトを作成」（または「プロジェクトを追加」）を押します。
3. プロジェクト名に `jugyolog` など好きな名前を入れて「続行」を押します。
4. 「Google アナリティクス」の画面が出たら、スイッチを**オフ**にして「プロジェクトを作成」を押します（アナリティクスは使いません）。
5. 「新しいプロジェクトの準備ができました」と出たら「続行」を押します。

## 2. Realtime Database を作る

1. 左のメニューの「構築」（または「Build」）を開き、「Realtime Database」を選びます。
2. 「データベースを作成」を押します。
3. 場所を聞かれたら、好きな場所を選んで「次へ」を押します（どれでも大丈夫です）。
4. セキュリティルールは「**ロックモードで開始**」を選んで「有効にする」を押します。
5. データベースの画面の上に、`https://〜.firebasedatabase.app`（または `https://〜.firebaseio.com`）で始まる URL が出ます。これを**控えておきます**（手順 6 で使います）。最後に `/` は付けません。

## 3. ルールを貼って公開する

1. Realtime Database の画面で「ルール」のタブを開きます。
2. 今ある文字をすべて消します。
3. このフォルダの `docs/setup/rules-check.json` を開き、中身を**すべてコピー**して、ルールの欄に貼ります。
4. 「公開」を押します。

これは段階 0（つながるかの確認）用のルールです。あとの段階で、ルールは差し替えます。

## 4. データに `check/ping` を入れる

1. Realtime Database の「データ」のタブを開きます。
2. データベース名（URL の行）の右にある「＋」を押します。
3. 「名前」に `check` と入れ、「値」は空のままにして、もう一度「＋」を押して下の階層を作ります。
4. 「名前」に `ping`、「値」に `true` と入れて「追加」を押します。値の種類を選ぶ欄があれば、「boolean」を選びます。

できあがりは、次のような形です。`true` に引用符（" "）が付いていないことを確かめます。

```
check
  └ ping: true
```

## 5. Authentication を始める

1. 左のメニューの「構築」から「Authentication」を選び、「始める」を押します。
2. 「ログイン方法」のタブで「メール / パスワード」を選び、一番上のスイッチを**有効**にして「保存」を押します。下の「メールリンク（パスワードなしでログイン）」は**オフのまま**にします。
3. 「匿名」は**有効にしません**。

## 6. データベースの URL とウェブ API キーを Claude Code に伝える

1. 左上の「プロジェクトの概要」の横の歯車を押し、「プロジェクトの設定」を開きます。
2. 「全般」のタブにある「ウェブ API キー」を**控えます**。
3. 次の 2 つを Claude Code に伝えます。
   - データベースの URL（手順 2 で控えたもの）
   - ウェブ API キー

「ウェブ API キー」の欄が無いときは、同じ「全般」のタブを下へ進み、「マイアプリ」の `</>`（ウェブ）のアイコンを押して、ウェブアプリを 1 つ登録します。

1. 「アプリのニックネーム」に好きな名前を入れます。「Firebase Hosting も設定します」のチェックは**入れません**。
2. 「アプリを登録」を押します。
3. 画面に出る `apiKey: "AIza..."` の行の、`"` と `"` の間の文字がウェブ API キーです。控えます。画面のコードを貼ったり、コマンドを実行したりする必要はありません。
4. 「コンソールに進む」を押して閉じます。

データベースの URL とウェブ API キーは、**公開してよい値**です。データを守るのは、手順 3 のルールです。

## 7. してはいけないこと

- 「Blaze プラン」に切り替えない。
- 支払い方法（クレジットカードなど）を登録しない。
- 「アップグレード」と出ても押さない。
- パスワードを Claude Code に伝えない。

## 8. 確認が終わったら

段階 1a まで日があくときは、Authentication の「ログイン方法」のタブで「メール / パスワード」を**無効**にして「保存」を押します（だれでもアカウントを作れる状態を閉じるためです）。再開するときは、同じ所で**有効**に戻します。

## 9. 本番の規則を貼る（段階 1a）

段階 1a から使う、本番のルールに差し替えます。やり方は手順 3 と同じです。

1. Authentication の「ログイン方法」で「メール / パスワード」が**有効**になっているか確かめます（手順 8 で無効にしたときは、有効に戻します）。
2. Realtime Database の画面で「ルール」のタブを開きます。
3. 今ある文字をすべて消します。
4. このフォルダの `docs/setup/rules.json` を開き、中身を**すべてコピー**して、ルールの欄に貼ります。
5. 「公開」を押します。

本番のルールにも、段階 0 の確認用の `check` の決まりが入っています。`check/ping` のデータは消さずにそのまま残します。

**規則を直したときは、毎回貼り直して公開します。** アプリを更新するだけでは、Firebase の規則は変わりません。段階 1a-2 では、先生が `lessons` 全体を読めるように規則が変わったため、最新の `docs/setup/rules.json` で上の手順 2〜5 をもう一度行います。公開したら、アプリの先生の画面で「規則の確認」を行い、追加した 10 項目を含む 29 項目がすべて ○ になり、片付けの失敗が出ていないことを確かめます。

## 10. 先生のアカウントを作る

先生がアプリにログインするためのアカウントを作り、「先生の一覧」（`teacherList`）に登録します。

1. 左のメニューの「構築」から「Authentication」を選び、「ユーザー」のタブを開きます。
2. 「ユーザーを追加」を押します。
3. 先生のメールアドレスと、**自分で決めたパスワード**を入れて「ユーザーを追加」を押します。
4. 一覧に、いま追加したユーザーが出ます。その行の「ユーザー UID」（英数字の長い文字）をコピーします。
5. Realtime Database の「データ」のタブを開きます。
6. データベース名（URL の行）の右にある「＋」を押し、「名前」に `teacherList` と入れ、「値」は空のままにして、もう一度「＋」を押して下の階層を作ります。
7. 「名前」に、手順 4 でコピーしたユーザー UID を貼り、「値」に `true` と入れて「追加」を押します。値の種類を選ぶ欄があれば、「boolean」を選びます。

できあがりは、次のような形です。`true` に引用符（" "）が付いていないことを確かめます。

```
teacherList
  └ （ユーザー UID）: true
```

**パスワードは Claude Code に伝えません。** メモに残すときは、自分だけが見られる場所にします。ユーザー UID とメールアドレスは、伝えても大丈夫です。

---

## うまくいかないとき

- ルールの「公開」でエラーが出る: 貼った文字に、余分な文字や欠けがないか見てください。手順 3 をやり直します。
- 画面の様子が、この手順書と違う: そこで止めて、画面の様子を Claude Code に伝えてください。
