## Claude Code の対応
（Task 1 の修正の確認、Task 2、Task 3。2026-11-13）

| # | 判断 | 内容 |
|---|---|---|
| 1 | 一部対応する | `reserveIds` は、生徒の場所をまるごと置きかえず `students/<id>/createdAt` だけを書くようにした（すでにある `uid` を消さない）。**連番の重なりをサーバー側で防ぐ仕組み（条件つきの書きこみ）は入れない。** 理由: 先生は 1 人で、発行は先生が自分で押す操作。2 つの画面で同時に発行したときだけ起きる。重なっても、2 人目の発行は同じメールアドレスになって `EMAIL_EXISTS` → 回数が進み、同じ生徒 ID に新しいアカウントが付くだけで、ほかの生徒の記録が混ざることはない（記録は生徒 ID ごと）。README の使い方に「発行は 1 つの画面で行う」と書く（Task 6）。 |
| 2 | 対応する | `signIn` に `isCurrent` を足した。待ったあとは毎回確かめ、画面を離れていたら、ログインの通信を送らない／自分が入れた分だけ外す。確認の失敗でも、別の人のログインに替わっていたら外さない。`login.js` の、離れたあとの `signOut` をやめた。テスト 4 件を追加。 |
| 3 | 対応する | `records` の `level` と `marks` を整数だけにした（`% 1 === 0`）。形のテストを追加。 |
