# 実装指示書: 「どこに届くか」修正 3（レビューの指摘 1 件）

あなた（Codex）は、この指示書に沿ってコードを直します。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

Codex レビュー `.ai-review/20261117-161452_round1.md` の指摘 1（High）を直す。

はじめの指示書（Claude Code の設計）が、まちがっていた。ブラウザの `fetch` は、`mode: 'no-cors'` と `redirect: 'manual'` を一緒に使うと、通信する前に失敗する。そのため、届く行き先も全部「届きませんでした」になる。Claude Code が本物のブラウザ（`https` のページ）で確かめたところ、そのとおり全部が 10 ミリ秒以内に失敗した。`redirect: 'follow'` に変え、リダイレクトしないアドレスにすると、届く行き先 13 個は成功し、存在しない行き先は失敗した（2026-11-17）。

## 直すこと

1. `js/reach-check.js`: `fetch` の設定を `redirect: 'follow'` にする。ほかの設定（`GET`・`no-cors`・`no-store`・`omit`・`no-referrer`・10 秒）は変えない。
2. `js/reach-targets.js`: アドレスを、リダイレクトしないものに変える（名前・ホスト名の表示・順番は変えない。下に「注」があるものは、名前の後ろに付ける）。

   | 行き先 | 新しいアドレス |
   |---|---|
   | Firebase のデータベース | `<データベースの URL>/check/ping.json`（今ある接続確認が読む、だれでも読める場所。今ある設定・定数から組み立てる） |
   | このアプリの置き場所 | `check.html` と同じフォルダの `version.txt`（`new URL('version.txt', location.href)`。`https://` でなければ外す） |
   | 今の保存の仕組み（script.google.com） | `https://script.google.com/robots.txt` |
   | 今の保存の仕組みの返事（script.googleusercontent.com） | `https://script.googleusercontent.com/robots.txt` |
   | Google ドライブ（drive.google.com） | `https://drive.google.com/robots.txt` |
   | ドライブのファイルの本体 | `https://drive.usercontent.google.com/`（今のまま） |
   | Google の API | `https://www.googleapis.com/`（今のまま） |
   | Firebase のファイル置き場 | `https://firebasestorage.googleapis.com/`（今のまま） |
   | Google のファイル置き場 | `https://storage.googleapis.com/`（今のまま） |
   | Firebase のホスティング | `https://<ID>.web.app/`（今のまま） |
   | 中つぎの候補: Cloudflare Workers（workers.dev） | `https://workers.dev/`（今のまま）。注: 「workers.cloudflare.com へ転送されます」 |
   | 中つぎの候補: Cloudflare Pages（pages.dev） | `https://pages.dev/`（今のまま）。注: 「pages.cloudflare.com へ転送されます」 |
   | 中つぎの候補: Vercel（vercel.app） | `https://vercel.app/`（今のまま）。注: 「vercel.com へ転送されます」 |
   | 中つぎの候補: Netlify（netlify.app） | `https://netlify.app/robots.txt` |

   - 「クエリを付けない」決まりは、今のまま。
   - 注のある行き先は、表の「アドレス（ホスト名）」の欄に、ホスト名に続けて注を出す（例: 「workers.dev（workers.cloudflare.com へ転送されます）」）。コピーの文にも入れる。
3. 説明の文に 1 行足す: 「× は、その行き先か、転送された先のどちらかに届かなかったことを表します。」
4. README の説明を合わせる。

## 端の場合

- 不正な入力: 今のまま（`https://` でない決め打ちは `TypeError`。設定から作るものは外す）。データベースの URL の末尾に `/` があっても無くても、`/check/ping.json` が 1 つの `/` でつながる。
- 重複と境界: 今のまま。
- 違反や失敗の見せ方: 今の文のまま。上の 1 行だけ足す。

## テスト

- `tests/reach-check.test.js`: `fetch` に渡す設定が `redirect: 'follow'` であること（`'manual'` を使っていないこと）。一覧のアドレスが上の表のとおりであること。注がコピーの文に入ること。データベースの URL の末尾の `/` の有無。
- 代役の `fetch` では、この不具合を見つけられない。**代役の `fetch` に、「`no-cors` で `redirect` が `follow` 以外なら `TypeError` を投げる」という本物と同じ決まりを入れ**、今後同じまちがいをテストで止める。
- `npm test` がすべて成功し、変えた `.js` は `node --check` が通る。
