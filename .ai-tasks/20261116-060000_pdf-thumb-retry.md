# 実装指示書: PDF の小さい画像（1 ページ目）が出ないことがあるのを直す

あなた（Codex）は、この指示書に沿ってコードを直します。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

先生の報告（2026-11-15）: 授業ページで、PDF に何が入っているかが見えない（「PDF」の文字だけ）。押して読みこむと、やっと見える。PDF の画像（1 ページ目）が見えるようにしてほしい。

Claude Code の調べ:

- 仕組みとしては、PDF を足すときに 1 ページ目の小さい画像を作って保存している（先生の資料は `thumbs/…`、生徒の添付は `recThumbs/…`）。
- 公開先で、先生が iPad から足した生徒の PDF には、小さい画像が保存されていなかった（写真にはあった）。
- 原因の見立て: `js/views/parts/attachment-pane.js` の `prepare` と `js/views/teacher-lesson.js` の PDF の用意は、長辺 320 で 1 回だけ描き、`compressCanvas` が `null`（画質 0.45 でも `CONFIG.thumb.maxChars` を超えた）のとき、そのまま「小さい画像なし」で送っている。字の多いページは、長辺 320 でも 20000 文字を超える（手元で、字の詰まった 320×226 の絵が 22915 文字になることを確かめた）。写真（`compressImage`）は、超えたら長辺を 0.75 倍にしてやり直すが、PDF はやり直していない。

## 直すこと

1. `js/pdf.js` に足す:

   ```js
   // 1 ページ目を小さい画像（JPEG のデータ URL）にする。大きすぎたら、長辺を 0.75 倍にして描き直す。
   export async function pdfThumb(pdf, { maxEdge, maxBytes }) → Promise<string | null>
   ```

   - `edge = maxEdge` から始め、`pdf.renderPage(1, edge)` → `compressCanvas(canvas, { maxBytes })`。文字が返ればそれを返す。`null` なら `edge = Math.floor(edge * 0.75)` にしてやり直す。`edge < 64` になったら `null` を返す。
   - `renderPage`・`compressCanvas` が投げた例外は、そのまま投げる（呼ぶ側が今と同じく「小さい画像なし」にする）。
   - `maxEdge`・`maxBytes` が正の有限の数でなければ `TypeError`。
2. `js/views/parts/attachment-pane.js` と `js/views/teacher-lesson.js` の、PDF の小さい画像を作る所を、`pdfThumb(pdf, { maxEdge: CONFIG.thumb.maxEdge, maxBytes: CONFIG.thumb.maxChars })` に置きかえる。ほかの流れ（`alive` の確かめ、`pdf.close()`、こわれた PDF は小さい画像なしで送る）は今のまま。

## 端の場合

- 不正な入力: こわれた PDF・1 ページ目を描けない PDF は、今と同じく小さい画像なしで送る（「PDF」の文字が出る）。`maxEdge`・`maxBytes` が数でない・0 以下・無限 → `TypeError`。
- 重複と境界: 1 回目で収まる PDF は、今と同じ 1 回だけ描く。ちょうど `maxBytes` は収まった扱い（今の `compressCanvas` のまま）。長辺 64 未満まで下げても収まらないときは `null`（小さい画像なし）。描き直しの途中で画面を離れた・PDF を閉じたときは、今と同じく送らない（`renderPage` が投げる）。
- 違反や失敗の見せ方: 小さい画像が作れなかったときは、今と同じく「PDF」の文字を出す。文は足さない。

## テスト

- `tests/pdf.test.js`（無ければ、今ある PDF のテストの所）: `pdfThumb` — 1 回目で収まる → 1 回だけ描く／1 回目・2 回目が `null` で 3 回目に収まる → 長辺 320・240・180 で描く／ずっと `null` → `null` を返し、長辺 64 未満では描かない／`renderPage` が投げる → 投げる／引数が不正 → `TypeError`。`renderPage` と canvas は代役でよい。
- 添付と先生の資料の画面のテストに、「1 回目が大きすぎても、小さい画像が付いて送られる」を 1 つずつ足す（今あるテストの書き方で足せる範囲で。足せなければ報告に書く）。
- `npm test` がすべて成功し、変えた `.js` は `node --check` が通る。

## 守ること

- ネットワークからパッケージを足さない。
