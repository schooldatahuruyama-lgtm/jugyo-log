## 変える内容

### 指摘 1（High）: 細長い写真・PDF で、書きこみの縦の位置がずれる（`js/export-draw.js`）

写真・PDF のページへの書きこみは、今の画面（`js/views/parts/viewer.js`・`js/views/parts/ink-pad.js` の `picture`）では、横 `CONFIG.ink.width`・縦 `ink.h` の紙を、絵の全体に重ねている（`ink.h` は `emptyPictureInk` で 100〜4000 に丸めてあるので、絵の縦横の比と合わないことがある）。書き出しも、これと同じ見え方にする。

- 写真・PDF のページに重ねるとき: 横は `canvas.width / config.ink.width`、縦は `canvas.height / ink.h` で座標を変える。`ink.h` が正の有限の数でないときは、今までどおり横の比を縦にも使う。
- 線の太さは、今の画面での見え方に合わせる（今の画面が横の比だけで太さを決めているなら横の比、縦横で伸びているならその平均など。`viewer.js`・`ink-pad.js` を読んで決め、決めた理由を報告に書く）。
- メモなどの手書き（`draw.ink`）は、縦も横の比のまま（紙そのものなので、変えない）。

### 指摘 2（Medium）: 「やめる」のすぐ後に作り直すと、前の PDF が閉じる前に次の PDF が開く（`js/export-draw.js`・`js/views/student-export.js`）

- PDF を開く・閉じる処理を、アプリ全体で 1 本の列に並べる（`js/export-draw.js` の中に、モジュールで 1 つの列を持つ。`createExportDraw` を作り直しても、同じ列を使う）。
  - `openPdf` は、列の前の処理（前の PDF を開く途中・閉じる途中をふくむ）が終わってから、開き始める。
  - 開く途中で `dispose()` された PDF は、開き終わったらすぐ閉じ、その閉じる処理が終わるまで、次の `openPdf` を始めない。
  - `dispose()` は、開いている PDF を閉じ始めるだけでよい（待たない。今までどおりすぐ戻る）。閉じる処理は列に残る。
  - 開く・閉じるが失敗しても、列は止めない（次が進む）。
- 「同時に動いている PDF（開く途中・開いている・閉じる途中）は、いつも 1 つまで」を、やめる → 作り直す・えらび直す → 作る・年度を変える・画面を離れてもどる、のどの場合も守る。
- 画面（`student-export.js`）は、今の動き（「やめる」ですぐえらぶ部分にもどり、すぐ作り直せる）を変えない。作り直した側は、前の PDF が閉じるまで、PDF を開く所で待つだけ。

## 端の場合

- 不正な入力: `ink.h` が無い・0・負・数でない → 横の比を縦にも使う（絵は出す）。
- 重複と境界:
  - 1600×100 の写真（`ink.h` は 100）で、書きこみの点 (400, 80) → 出来た絵 1200×75 の中の (600, 60) に出る。
  - 100×1600 の写真（`ink.h` は 4000 に丸まる）で、書きこみの点 (400, 2000) → 絵のまん中に出る。
  - ふつうの 4:3 の写真 → 今までと同じ位置。
  - PDF を開く途中（`openPdf` の返事を止めてある）で `dispose()` → 新しい `createExportDraw` の `openPdf` は、前の返事が来て、それが閉じ終わるまで、もとの `openPdf`（引数の部品）を呼ばない。
  - 前の PDF を閉じる処理が失敗する → 次の PDF は開ける。
- 違反や失敗の見せ方: 変えない。
