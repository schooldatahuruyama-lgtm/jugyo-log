## 1. `js/ink-saver.js`（保存の時を決める。画面と通信を持たない）

今ある `js/record-saver.js` と同じ作り・同じ状態の名前にする（`dirty`・`saving`・`saved`・`retrying`・`failed`）。

```js
createInkSaver({ save, saveDraft, removeDraft, newKey, now, setTimeout, clearTimeout,
  delayMs, intervalMs, retryMs, onState }) → { edit(ink, opts), flush(), retry(), dispose(), dirty, state }
```

- `edit(ink, { editedAt, key } = {})`: 中身が変わった。`editedAt` が無ければ `now()`、`key` が無ければ `newKey()`（**中身が変わるたびに新しいキー**。同じ中身の送り直しは同じキー）。すぐ `saveDraft(ink, editedAt, key)` を呼び、状態を `dirty` にして、保存の時を決め直す。
- 保存の時: 「最後の `edit` から `delayMs`」と「前の保存を始めた時から `intervalMs`」の、おそいほう。はじめての保存は、`delayMs` だけ待つ。
- 保存: `save(ink, editedAt, key)`。成功したら、その間に新しい `edit` が無ければ `removeDraft()` を呼んで `saved`。新しい `edit` があれば、そのまま次の保存を待つ（下書きは消さない）。
- 失敗: `retryMs`（例 `[2000, 5000, 15000]`）の間隔でやり直す（`retrying`）。使い切ったら `failed`。`denied`（規則に断られた）は、やり直さずに `failed`。同じ中身のやり直しは、同じ `key` を使う。
- `flush() → Promise<boolean>`: 待たずに今すぐ保存し、保存できたら `true`。保存中なら、その終わりを待ち、そのあとに残りがあれば続けて保存する。変わったものが無ければ、すぐ `true`。
- `retry()`: `failed`・`retrying` のとき、今すぐもう一度保存する。
- `dispose()`: タイマーを止め、そのあとは `onState` を呼ばない。

テスト（`tests/ink-saver.test.js`。今ある `tests/record-saver.test.js` の書き方に合わせ、時計とタイマーは代役）: はじめは `delayMs` 後に保存。続けて書くと、最後から `delayMs`。前の保存から `intervalMs` たつまでは保存しない。`flush` はすぐ保存する。失敗 → やり直し → 成功。やり直しを使い切る → `failed` → `retry` で成功。`denied` はやり直さない。保存中に書くと、下書きを消さずに次を保存する。同じ中身のやり直しは同じキー、新しい中身は新しいキー。`dispose` のあとは何もしない。

## 2. 部品 `js/views/parts/ink-field.js`

1 つの欄の手書き（読みこみ・書く部品・保存）をまとめる。

```js
inkField({ ctx, classId, lessonId, studentId, field, label, index, onState, onChange })
  → { node, show(), hasInk(), dirty, state, flush(), retry(), refresh(index), setLocked(locked), destroy() }
```

- `index`: 開いたときの目録（`record.ink[field]` または `null`）。
- はじめに、端末の下書き（`ctx.inkDrafts.get`）を見る。
  - 下書きがあり、目録が無いか、`下書きの editedAt > 目録の updatedAt` → 下書きの中身を使い、`saver.edit(ink, { editedAt, key })` で送り直す（Drive からは読まない）。
  - それ以外で下書きがあれば、下書きを消す。
- **Drive からの読みこみは、必要になってから**（`show()` が呼ばれた = 生徒がこの欄の手書きを開いた時）。目録が無ければ、読まずに空の紙を出す。読みこみ中は「手書きを読みこんでいます…」。
- 読みこみ（`loadInkFlow`）に失敗した（通信・`bad-data`）: 紙を出さず、「手書きを読みこめませんでした。」（`role="alert"`）と「もう一度」を出す。**読めていない間は書けない**（空の紙を出して、あとで上書きしてしまわないため）。
- 読めたら `inkPad({ ink, label: `${label}の手書き`, onChange })` を出す。`onChange` で `saver.edit(ink)`。
- 保存（`saver` の `save`）: `ctx.recordQueue.run('<classId>/<lessonId>', …)` の中で `saveInkFlow({ …, ink, key, editedAt, thumb, previous: 今の目録 })`。`thumb` は、`field` が `CONFIG.inkThumbFields`（`learned`・`question`）に入っているときだけ `inkThumb(ink)`（線が無い・作れないときは `null`）。`memo` のときは `null`（メモの小さい画像は作らない。Task 2b）。成功したら、今の目録を入れかえる。
- 保存の設定: `delayMs: CONFIG.ink.saveDelayMs`、`intervalMs: CONFIG.ink.saveIntervalMs`、`retryMs: CONFIG.save.retryMs`、`newKey` は今ある添付と同じ作り方（`js/views/parts/attachment-pane.js` のキーの作り方に合わせる）。
- 下書きを端末に残せなかった（`put` が `false`）ときは、`onState` とは別に、欄の下に「この iPad に下書きを残せません。保存しましたと出るまで、このページを閉じないでください。」を 1 回出す。
- `hasInk()`: 今の中身に線がある（読みこむ前は、目録か下書きがあれば `true`）。`onChange(hasInk)` を、変わったときに呼ぶ。
- `refresh(index)`: ほかの端末で書きかわったとき用。保存待ち・保存中（`dirty`）でなく、渡された目録の `updatedAt` が今より新しければ、目録を入れかえ、すでに紙を出していれば読み直す。
- `setLocked(locked)`: 紙の `setLocked` に渡す。`flush()`・`retry()`・`dirty`・`state` は `saver` のもの。`destroy()` は、紙と `saver` を片付ける。

## 3. 生徒の授業ページ（`js/views/student-lesson.js`）

- メモ・分かったこと・疑問の 3 つの欄それぞれで、ラベルの横に「文字｜手書き」の切りかえを置く（くっついた 2 つのボタン。選ばれている側は `aria-pressed="true"` で、こい色。`role="group"` と `aria-label`「メモの書き方」など）。
  - 「文字」: 今ある入力欄（動きは変えない）。「手書き」: `inkField` の `node`（はじめて開いた時に `show()`）。
  - **はじめに出す側**: その欄に手書きがあり（`hasInk()`）、文字が空なら「手書き」。それ以外は「文字」。
  - 出していない側に中身があるとき（文字が 1 文字以上・手書きに線がある）、そのボタンの文字のあとに「●」を付け、読み上げの名前に「（書いてあります）」を足す。中身が変わったら付け直す。
  - 切りかえても、どちらの中身も消えない。出していない側も、保存は続く。
- 保存の状態（上の「保存中…／保存しました／保存できませんでした」）は、文字の保存と 3 つの手書きの保存を**まとめて 1 つ**で出す。いちばん悪いものを出す（`failed` > `retrying` > `dirty`・`saving` > `saved`）。「もう一度」は、失敗しているものすべてをやり直す。
- 離れるときの確かめ（`okToLeave`）: 今ある順番の、文字の保存の所で、3 つの手書きも `flush()` する（確かめの間は、紙も `setLocked(true)`。離れないときは戻す）。どれかが保存できなければ、今ある「まだ保存できていません」の確かめを出す（文は今のまま。手書きも端末の中に下書きが残り、次に一覧を開いたときに送り直す）。
- 接続が戻ったとき（`online`）: 今ある文字の保存と同じように、失敗している手書きもやり直す。
- 画面に戻ったとき（今ある `refreshRecord`）: 読み直した記録の `ink` を、それぞれの `inkField.refresh` に渡す。
- 画面を片付けるとき、3 つの `inkField` も `destroy()`。
- 振り返りの「記入済み／未記入」（理解度で決まる）は、変えない。

## 端の場合

- 不正な入力: 下書きがこわれている → `ctx.inkDrafts.get` が `null` を返すので、無いものとして扱う。Drive のファイルがこわれている（`bad-data`）→ 読みこめなかった文と「もう一度」（空として上書きしない）。
- 重複と境界: 切りかえを続けて押しても、読みこみは 1 回。読みこみ中に「文字」へ戻しても、読みこみは続き、次に開いたときに出る。線が 1 本も無くなった保存は、目録を消す（`saveInkFlow` がする）。下書きと目録の時刻が同じなら、目録（Drive）を使う。保存中に画面を離れようとしたら、その終わりを待つ。3 つの欄は、それぞれ別に保存する（1 つの失敗が、ほかを止めない）。
- 違反や失敗の見せ方: 保存の失敗は、上の保存の状態と「もう一度」、離れるときの確かめで見せる。読みこみの失敗は、その欄の中の文と「もう一度」。上限は、紙の下の文（Task 3）。出していない側に中身があることは「●」で見せる（黙って隠さない）。

- `npm test` がすべて成功し、変えた・作った `.js` は `node --check` が通ること。
- 代役の `ctx`（練習モードの部品でよい）で、次を確かめて報告に書く: (1) 「手書き」に切りかえて線を書くと、下書きが残り、時間がたつと保存され、目録と小さい画像が書かれる。(2) 開き直すと、手書きのある欄は「手書き」で開き、線が出る。(3) 保存に失敗 →「保存できませんでした」→「もう一度」で成功。(4) 保存できないまま「一覧へ」→ 確かめ → 一覧で送り直される。(5) 読みこみの失敗 → 文と「もう一度」、その間は書けない。(6) 文字の入力・保存・添付・重要用語が、今までどおり動く。
