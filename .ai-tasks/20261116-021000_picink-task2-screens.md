# 実装指示書: 写真への書きこみ Task 2 — 画面

あなた（Codex）は、この指示書に沿ってコードを書きます。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

Task 1（`.ai-tasks/20261116-020000_picink-task1-data.md`。実装済み）のデータの形と保存の流れを使い、**写真を大きく開いた画面で、写真の上に書きこめる**ようにする。対象は、先生の資料の写真と、生徒が自分で足した写真。PDF は対象外。

## 画面の動き（Claude Code の設計。先生に伝えてある）

### 生徒: 写真を大きく開いた画面（`js/views/parts/viewer.js`）

- 写真（`kind` が写真）で、書きこみが使えるときだけ、上の操作の並び（－・％・＋ のとなり）に「✎ 書きこむ」のボタン（`aria-pressed`）を出す。はじめは押していない。
- **押していないとき**: 今までどおりの表示（拡大・縮小、マウスやペンで引いて動かす）。書きこみがあれば、写真の上に重ねて出す（さわっても何も起きない）。
- **押したとき**: 手書きの道具の並び（動かす／書く、黒・赤・青、細い・太い、定規、消しゴム、1 つ戻す、全部消す、今の状態の文）を、写真の上（操作の並びの下）に出す。写真の上に書ける。
  - 「動かす」（はじめ）: 指は画面を動かす（たて・よこ）。ペンは書ける。「書く」: 指でもペンでもマウスでも書ける。欄の手書きと同じ決まり（手のひらを置いたまま書くときの扱いも同じ）。
  - 押している間は、マウスやペンで引いて写真を動かす動き（今の `viewport` の `pointerdown`）を止める。拡大・縮小のボタン、指での動かし、スクロールバーは使える。
  - 「＋ 下に書く場所を足す」と、紙の横線は出さない。
- 線は、写真といっしょに拡大・縮小される（写真と同じ大きさの SVG を、写真の上にぴったり重ねる。座標は横 800、縦は `emptyPictureInk(naturalWidth, naturalHeight)` の `h`。`preserveAspectRatio="none"`）。
- 保存の状態を、この画面の中に出す（`role="status"`）: 「保存中…」「✓ 保存しました」「保存できませんでした」＋「もう一度」。後ろの授業ページの見出しの状態は、この画面を開いている間は見えないため。
- 文:
  - 読みこみ中: 「書きこみを読みこんでいます…」
  - 読みこめない: 「書きこみを読みこめませんでした。」＋「もう一度」（写真は見られる。「✎ 書きこむ」は押せない）
  - ファイルが見つからない（`notfound`）: 「前の書きこみが見つかりませんでした。」＋「もう一度」＋「新しく書く」（確かめは、欄の手書きと同じ文で、「手書き」を「書きこみ」に言いかえる）
  - ほかの端末のほうが新しい: 「ほかの端末で書いたほうが新しいので、そちらを出しました。」
  - 写真が無くなっていた（`gone`）: 「この写真は、もうありません。書きこみは保存されませんでした。」（道具をしまい、書けなくする）
  - 上限（`too-big`）: 「これ以上は書けません。いらない線を消してください。」（欄の文の「写真にとって…」は出さない）
  - 「全部消す」の確かめ: 題「書きこみを全部消しますか？」、文「この写真への書きこみを全部消します。「1 つ戻す」で戻せます。」
- 閉じる: いつでも閉じられる。閉じるときに、まだ送っていない書きこみをすぐ送り始める（`flush`）。送り終わるのを待たない。保存の部品は、閉じても、授業ページを離れるまで生きている（下の「保存の部品の持ち方」）。

### 生徒: 授業ページ（`js/views/parts/material-pane.js`・`js/views/parts/attachment-pane.js`・`js/views/student-lesson.js`）

- 書きこみのある写真（目録があり、`on` がその写真のファイル ID と同じ。または、まだ送れていない下書きがある）に、「✎ 書きこみあり」の印を出す。先生の資料は、今めくって出している資料の名前の近く。自分の写真は、その写真の小さい表示の近く。書いた・消したら、開き直さなくても印が変わる。
- 自分の写真を消すときの確かめ: 書きこみがある写真では、文に「この写真への書きこみも消えます。」を足す。消すときは、その写真の保存の部品を先に止め、下書きも消す。
- 授業ページの見出しの保存の状態（`saveStates`）と、「もう一度」（`retrySaves`）、離れるときの確かめ（`okToLeave` の `flush` とロック）、戻ったときの読み直し（`refreshRecord`）に、写真への書きこみも入れる。
- まだ送れていない写真（保存の途中の添付）と PDF には、書きこみを出さない。

### 先生: 1 人の記録（`js/views/teacher-record.js`）

- 先生の資料の写真・生徒の写真に、同じ「✎ 書きこみあり」の印を出す。大きく開くと、書きこみが重なって見える。「✎ 書きこむ」のボタンと道具は出さない（読むだけ）。
- 読みこめないときは、上と同じ文と「もう一度」（「新しく書く」は出さない。`notfound` は「書きこみが見つかりませんでした。」）。
- 先生の「もう一度」は、欄の手書きと同じく、記録を読み直してから、今の目録のファイルを読む。
- 先生のほかの画面（授業の編集、記録の一覧）は変えない。

## 作り方

細かい分け方は任せるが、次を守る。

- **保存の決まりを二重に書かない**。欄の手書きの `js/views/parts/ink-field.js`（下書き・自動保存・`superseded`・`notfound`・読み直し・上げたファイルの片付け）を、写真でも使えるように広げるか、共通の部分を取り出して両方から使う。欄の手書きの今の動きは変えない。
- `js/views/parts/ink-pad.js` に、写真の上に重ねる使い方を足す（例: 紙（SVG）と道具の並びと文を、別々の要素として取り出せるようにする。横線なし・足すボタンなし・「動かす」のときの `touch-action` は `pan-x pan-y pinch-zoom`・上の文の言いかえ）。読むだけのときは、線が 0 本でも「（手書きはありません）」を出さない（重ねるだけ）。
- **保存の部品の持ち方**: 写真 1 枚につき 1 つ。はじめて大きく開いたとき（または、はじめに下書きが見つかったとき）に作り、`material-pane`・`attachment-pane` が持ち続け、部品の `destroy` で片付ける。同じ写真を開き直したら、同じ部品を使う（書いた線・戻す履歴・保存待ちを引きつぐ）。Drive からの読みこみは、はじめて大きく開いたときに 1 回（下書きがあれば、読みこまない）。
- `material-pane`・`attachment-pane` に渡すもの: 記録の `ink`・`inkCleared`、読むだけかどうか、状態が変わったときの知らせ（`onState`）。外へ出すもの: `dirty`・`state`・`flush()`・`retry()`・`setLocked()`・読み直し（`refreshInk(ink, inkCleared)`）。名前は、今のコードの書き方に合わせて決めてよい。
- 保存は、今ある順番待ち（`ctx.recordQueue.run(`${classId}/${lessonId}`, …)`）を通す。`saveInkFlow` には、場所の名前（`a1`〜`a6`、または資料の ID）と `on`（写真のファイル ID）を渡す。小さい画像（`thumb`）は渡さない。
- `gone` で返ったら、下書きを消し、保存は終わったものとして扱い、上の文を出す。
- 一覧（`js/views/student-home.js`）の送り直し・知らせ・ログアウトの確かめは、Task 1 で場所を広げてあるので、写真への書きこみの下書きも数に入るはず。入らなければ直す。
- 画面に出す文字は `textContent` で入れる。見た目（`css/app.css`）は、今ある手書きの道具・大きな表示の見た目に合わせる。道具の並びは、横 820px でも折り返して、はみ出さない。

## 端の場合

- 不正な入力: 写真の大きさが読めない（0 など）ときは、書きこみを出さない（写真の表示は今のまま）。記録の `ink` に知らない場所・`on` の合わない目録があっても、無いものとして扱う（印も出さない）。
- 重複と境界: 同じ写真を 2 回続けて開いても、保存の部品は 1 つ。書いてすぐ閉じても、線は送られる（または下書きに残る）。開いている間に別の写真へ切りかえる動きは無い（閉じてから開く）。線が 0 本になったら、印を消し、目録を消す（欄の手書きと同じ）。上限（線の数・大きさ）は、欄の手書きと同じ値。拡大率 400% でも、線の位置が写真とずれない。
- 違反や失敗の見せ方: 読みこみ・保存の失敗、ほかの端末のほうが新しい、写真が無くなっていた、上限は、上に書いた文で、大きな表示の中に出す（黙って捨てない）。送れていない書きこみは、今ある一覧の知らせ・タイルの印・ログアウトの確かめに出る。

## テスト・確かめ

- 計算に切り出せる所（印を出すかどうかの判断など）は、今ある `tests/` の書き方でテストを足す。
- `npm test` がすべて成功し、変えた `.js` は `node --check` が通ること。
- 代役（練習モードのデータ、または DOM の代役）で、次を確かめて報告に書く。確かめられなかったものは、そう書く。
  1. 自分の写真を開く →「✎ 書きこむ」→ 線を書く → 保存される → 閉じる →「✎ 書きこみあり」→ 開き直すと線が出る。
  2. 先生の資料の写真でも同じ。
  3. 書きこみのある自分の写真を消す → 目録も消える。同じ置き場所に別の写真を足しても、前の書きこみは出ない。
  4. 先生の 1 人の記録で、印が出て、開くと線が見え、道具が無い。
  5. PDF には「✎ 書きこむ」が出ない。
  6. 欄の手書き（メモなど）が、今までどおり動く。
