# 実装指示書: AI のまとめ Task 2 — 画面

あなた（Codex）は、この指示書に沿ってコードを書きます。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

Task 1（`.ai-tasks/20261118-100000_ai-summary-task1.md`。実装済み）の `js/ai-summary-logic.js`・`repo.getAiSummary`・`repo.setAiSummary`・`requestAiSummary` を使い、先生の「記録」の画面に、AI のまとめを足す。

## 画面の動き（Claude Code の設計。先生に伝えてある）

`js/views/teacher-review.js` の、今ある「まとめ（自動）」のカードの下・「生徒の記録」の上に、カード「**AI のまとめ**」を足す。部品は新しい `js/views/parts/ai-summary-box.js`。

### まだ作っていないとき

- 説明: 「文字で書いた記録を OpenAI に送り、AI がまとめます。名前や ID は送りません。手書きは入りません。」
- ボタン「AI でまとめる」。となりに「（文字で書いた N 人分）」。
- 文字で書いた記録が 0 人のときは、ボタンを押せず、「（文字で書いた記録がありません）」。

### 押したとき

- 確かめの窓: 題「AI でまとめますか？」、文「この授業の、文字で書いた記録（N 人分）を、OpenAI に送ります。名前や ID は送りません。」、ボタン「まとめる」／「やめる」。60 人を超えていて切るときは、文に「（人数が多いので、はじめの 60 人分だけ送ります）」を足す。
- 作っている間: 「AI がまとめています…（30 秒ほどかかります）」（`role="status"`）。ボタンは押せない。授業・クラスを変える・「読み直す」は、今までどおりできる（結果が返ってきたとき、もうちがう授業なら、画面には出さない。保存は、作った授業に対して行う）。
- できたら、データベースに保存し（`repo.setAiSummary`）、下の形で出す。保存に失敗しても、まとめは出し、「まとめは作れましたが、保存できませんでした。開き直すと消えます。」（`role="alert"`）と「もう一度保存する」を出す。

### まとめがあるとき

- いちばん上に、いつも: 「AI が作った文です。まちがいがあることがあります。」
- 1 行: 「M/D HH:MM に作成・N 人分の記録から」。
- 5 つの項目（見出しは、このとおり。中身が空の項目は「（ありません）」）:
  1. 「クラス全体の様子」: `overview`
  2. 「疑問のまとまり」: `questionGroups` を 1 つずつ。「（話題）（K 人: 2 番・3 番）」と、代表の文。
  3. 「まちがって覚えていそうな所」: `misconceptions`。「（N 番）『引用』— 気になる所」。
  4. 「次の授業で取り上げるとよいこと」: `nextLesson` を箇条書き。
  5. 「声をかけたい生徒」: `followUp`。「（N 番）理由」。
- 生徒の呼び名（「2 番」など）は、押せるボタンにする。押すと、その生徒の 1 人の記録へ行く（今ある一覧の行を押したときと同じ行き先）。呼び名から生徒が引けないとき（保存したあとに名簿が変わった、など）は、ボタンにせず、文字だけ。
- ボタン「作り直す」（押すと、上の確かめの窓から同じ流れ。できたら入れかえる）と「AI のまとめをコピー」（今ある「まとめをコピー」と同じ出し方）。
- 作ったあとに記録が変わっていたら（`isSummaryStale`）、「このまとめを作ったあとに、記録が変わっています。」を出す。

### 開いたとき

- 授業を選んだら、保存したまとめを読む（`repo.getAiSummary`）。読んでいる間は「読みこんでいます…」。読みこみに失敗したら「AI のまとめを読みこめませんでした。」と「もう一度」（一覧・グラフ・「まとめ（自動）」は、今までどおり出す）。
- 保存したまとめを読めるまでは、「AI でまとめる」を出さない（知らずに上書きしないため）。

### 失敗したときの文（どれも `role="alert"`。ボタンは、もう一度押せる）

| 失敗（`NetError` の `code`） | 文 |
|---|---|
| `ai-config` | AI の設定がまだです。手順書（docs/setup/ai-summary.md）のとおりに、保存の仕組みに鍵とモデルの名前を入れてください。 |
| `ai-key` | AI の鍵が正しくないか、使えなくなっています。 |
| `ai-busy` | AI が混んでいるか、使える量をこえています。少し待ってから、もう一度押してください。 |
| `ai-failed` | AI のまとめを作れませんでした。もう一度押してください。 |
| `bad` | 保存の仕組みが古い版のようです。手順書のとおりに、保存の仕組みを貼り直してください。 |
| `toobig` | 記録が多すぎて、送れませんでした。 |
| `denied`・`auth` | 先生としてログインし直してください。 |
| `network`・そのほか | 通信できませんでした。電波を確かめて、もう一度押してください。 |

- AI の返事が形に合わなかった（`cleanAiSummary` が `null`）→ `ai-failed` と同じ文。

### 見た目（`css/app.css`）

今ある「まとめ（自動）」のカードに合わせる。AI のまとめだと分かるよう、見出しの色か左の線を変える。ボタンは 44px 以上。文は `textContent`、長い文は折り返す。縦向き（幅 820px）でも、はみ出さない。

### 生徒の画面

何も足さない。生徒には見せない。

## 端の場合

- 不正な入力: 保存したまとめの形がおかしい → 無いものとして扱う（「AI でまとめる」を出す）。AI の文に HTML らしい文字があっても、文字として出す（`textContent`）。日時が数でない → 日時の行を出さない。
- 重複と境界: 「AI でまとめる」「作り直す」を続けて押しても、1 回だけ送る。作っている途中で授業を変えて、また戻ってきたら、「AI がまとめています…」を出し直す（同じ授業の作りかけがあるとき）。作っている途中でページを離れたら、結果は捨てる（保存しない）。ちょうど 60 人は、切らない。
- 違反や失敗の見せ方: 上の表の文を、カードの中に出す。失敗しても、前のまとめがあれば、消さずに出したままにする。

## テスト

- 計算に切り出せる所（日時の文、項目の文、失敗の文の選び方）は、`js/ai-summary-logic.js` に足して、テストを足す。
- `tests/ai-summary-box.test.js`・`tests/ai-summary-screen.test.js`（今ある `summary-screen`・`reply-screen` のテストの書き方で）: まだ無い → ボタンと人数／0 人で押せない／確かめ → 作っている文 → まとめが出て保存される／保存失敗 → まとめは出て、知らせが出る／開いたとき、保存したまとめが出る／記録が変わると知らせ／作り直すと入れかわる／失敗の文（表の全部）／失敗しても前のまとめが残る／続けて押しても 1 回／授業を変えたあとに届いた結果を出さない／呼び名を押すと 1 人の記録へ／生徒の画面に出ない／コピーの中身。
- `npm test` がすべて成功し、変えた `.js` は `node --check` が通ること。練習モードで動くこと（見本のまとめが出る）。
