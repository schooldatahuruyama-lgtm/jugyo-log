# 実装指示書: 手書き・書きこみを読みこめなかったとき、理由を画面に出す

あなた（Codex）は、この指示書に沿ってコードを書きます。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

先生の報告（2026-11-17）: 学校のタブレットで、生徒の手書きメモが「手書きを読みこめませんでした。」になった。同じ記録は、家の回線の PC からは読める（データは無事）。原因が、通信なのか・ログインなのか・端末なのかが、画面からは分からない。

今は、`notfound` 以外の失敗が、すべて同じ文になる（`js/views/parts/ink-field.js` の `load`、`js/views/teacher-record.js` の `loadInk`）。**原因を切り分けられるように、失敗の種類を文に添える。** 直し（原因そのものへの対応）は、種類が分かってから別に行う。

## 直すこと

1. `js/ink-flow.js` に足す:

   ```js
   // 手書き・書きこみを読みこめなかった理由を、画面に出す短い文にする。
   export function inkLoadReason(error) → 文字
   ```

   | `error` | 返す文 |
   |---|---|
   | `NetError` で `code === 'network'` | `通信できませんでした` |
   | `code === 'auth'` | `ログインが切れています` |
   | `code === 'denied'` | `見ることが許されていません` |
   | `code === 'toobig'` | `ファイルが大きすぎます` |
   | `code === 'bad-data'` | `中身を読めませんでした` |
   | `code === 'unknown'` | `保存の仕組みが断りました` |
   | そのほか（`NetError` でない例外。`TypeError` など） | `この端末では開けませんでした` |

   - `notfound` は今ある別の文のままなので、この関数では扱わなくてよい（来たら `見つかりませんでした`）。
   - エラーの中身（メッセージ・トークン・ファイル ID）は、画面に出さない。上の決まった文だけ。
2. 失敗の文を、次の形にする（`notfound` の文は変えない）:
   - 欄の手書き: 「手書きを読みこめませんでした。（理由: 通信できませんでした）」
   - 写真・PDF への書きこみ: 「書きこみを読みこめませんでした。（理由: …）」
   - 対象: `js/views/parts/ink-field.js`（生徒・先生の重ね表示の両方）と `js/views/teacher-record.js`。
3. `js/files.js` の `loadInk`: `Blob` に `text()` が無い端末でも読めるようにする（`text` が関数ならそれを使い、無ければ `FileReader` で読む。どちらも無ければ、今のとおり例外）。古い端末での失敗の原因を 1 つ減らす。

## 端の場合

- 不正な入力: `error` が `null`・`undefined`・文字・`code` の無い物 → 「この端末では開けませんでした」。`code` が知らない文字 → 「保存の仕組みが断りました」ではなく「この端末では開けませんでした」（`NetError` で知らない `code` のときだけ「保存の仕組みが断りました」）。
- 重複と境界: 「もう一度」を押して、ちがう理由で失敗したら、理由の文も入れかわる。成功したら、文は消える（今のまま）。
- 違反や失敗の見せ方: 上の文を、今ある失敗の文と同じ場所（`role="alert"`）に出す。「もう一度」のボタンは今のまま。

## テスト

- `tests/ink-flow.test.js`: `inkLoadReason` の表のすべての行と、おかしい入力。
- 画面のテスト（今ある欄の手書き・先生の記録・写真の書きこみのテストの所）: 通信の失敗 → 理由つきの文。`bad-data` → 「中身を読めませんでした」。`notfound` の文は変わらない。
- `tests/files.test.js`（今ある所）: `text()` の無い Blob の代役で、`FileReader` の代役から読める。
- `npm test` がすべて成功し、変えた `.js` は `node --check` が通る。
