## 変える内容

### 指摘 1（High）: 確かめたあとの保存が失敗し、やり直しで新しい記録を上書きする（`js/views/student-lesson.js`）

- `needsServerCheck` を false にするのは、**`saveRecord` が成功したあと**（または、サーバーの方が新しくて送らなかったあと）だけにする。確かめたあとの保存が失敗したら、次に送るときに、もう一度サーバーの記録を確かめる。

### 指摘 2（Medium）: 別の授業への書きこみで、読み直した記録が取り置きに入らない（`js/offline-net.js`）

- 書きこみの世代を、全体で 1 つの数にするのをやめる。「今読んでいる途中の `get`」の一覧を持ち、書きこみを **始めたとき** と **成功したとき** に、その書いた場所にかかる（同じ・下・上。今の取り置きを消す判定と同じ）`get` にだけ「取り置きに入れない」の印を付ける。
- `get` は、終わったときに、印が無く、scope とログインの世代が同じときだけ、取り置きに書く。終わったら一覧から外す（失敗したときも）。
- 関係のない場所への書きこみでは、取り置きに入る。

### 指摘 3（Medium）: サーバーの新しい記録を出したとき、取り置きが古いまま（`js/views/student-lesson.js`）

- サーバーの方が新しくて送らなかったとき（`{ superseded: true }` を返す所）にも、`ctx.offline?.touch?.(classId, lessonId, studentId)` を呼ぶ（画面を離れていても呼ぶ）。

### 指摘 4（Medium）: 新しい版のファイルを取れなかったのに、古い版のキャッシュを消す（`sw.js`）

- `install`:
  - 一覧（`app-files.json`）の取得が **通信の失敗**（`fetch` が投げる）→ install を失敗させる（投げる。古い Service Worker と古いキャッシュが残る）。
  - 一覧が 200 でない・形がちがう → 今までどおり install は成功（先に入れるものは無い）。この場合は「そろっていない」とする。
  - 一覧が取れた → `files` を全部取る。**1 つでも取れない（通信の失敗、または 200 でない）→ install を失敗させる**。全部取れたら「そろった」とする。
  - `skipWaiting()` は、install が成功するときだけ呼ぶ。
- `activate`: ほかの版のキャッシュを消すのは、「そろった」ときだけ。自分の版のキャッシュの、一覧に無いものを消すのも「そろった」ときだけ（今までどおり）。「そろっていない」ときは、何も消さない。
- `fetch` の、キャッシュをさがす所: 自分の版のキャッシュに無ければ、ほかの `jugyolog-app-` のキャッシュもさがす（「そろっていない」版が動いていても、前の版の取り置きで開けるようにする）。書くのは、今までどおり自分の版のキャッシュだけ。

## 端の場合

- 不正な入力: 一覧の `files` に文字列でない要素 → その要素はとばす（今までどおり）。ほかは全部取れれば「そろった」。
- 重複と境界:
  - 下書き 20 → サーバー 10 を確かめる → 保存が通信の失敗 → 別の端末が 30 を保存 → やり直し → もう一度確かめて、送らない。サーバーの 30 が出る。
  - 下書き 20 → サーバー 10 を確かめる → 保存が成功 → 次の入力の保存では、確かめない（`liveRepo.getRecord` は 1 回だけ）。
  - 授業 A の `get` の途中で、授業 B の記録に書いて成功 → A は取り置きに入る。
  - 授業 A の `get` の途中で、授業 A の記録（またはその下・上）に書く → A は取り置きに入らない。
  - 取り置き 10・下書き 20・サーバー 30 → 画面は 30、`touch` が 1 回呼ばれる。
  - 古い版がそろっている → 新しい版の install で、ファイル 1 つが 500 → install は失敗。古い版のキャッシュは残る。
  - 新しい版の install で、一覧の取得が通信の失敗 → install は失敗。
  - 一覧が 404（手もとの開発）→ install は成功。activate で何も消さない。
  - 自分の版のキャッシュに無く、前の版のキャッシュにあるファイル → ネットが失敗したとき、前の版のものを返す。
- 違反や失敗の見せ方: 変えない。
