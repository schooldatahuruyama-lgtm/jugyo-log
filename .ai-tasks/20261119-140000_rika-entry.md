# 実装指示書: 生徒の最初の画面に「理科クエスト」の入口を置く

あなた（Codex）は、この指示書に沿ってコードを書きます。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

設計書 `docs/superpowers/specs/2026-11-19-rika-link-design.md` の「段階 1. 入口」。授業ログの生徒の最初の画面（授業の一覧）のいちばん上に、理科クエスト（別のアプリ。公開先 `https://schooldatahuruyama-lgtm.github.io/Rika_app/`）を開くカードを置く。見た目の見本は `docs/mockups/rika-link.html` の画面 1（ただし、この段階では単元名・レベル・今日のクエストは出さない）。

この段階では、理科クエストとデータのやり取りはしない。リンクを置くだけ。

## 変えるファイルと内容

### 1. `js/config.js`

- `CONFIG` に足す: `rika: { url: 'https://schooldatahuruyama-lgtm.github.io/Rika_app/' }`（コメント: 理科クエスト（別のアプリ）の入口のアドレス）。

### 2. `js/rika-link.js`（新しく作る）

- `export function rikaEntryUrl(value)`: 入口に使ってよいアドレスなら、その文字列（`new URL(value).href`）を返す。使えないなら `null` を返す。例外は投げない。
- 使ってよい条件: 文字列である／前後の空白を除いて空でない／`new URL()` で読める／`protocol` が `https:` ／ `username` と `password` が空。
- ブラウザのもの（`window`・`document`）は使わない（`URL` は使ってよい）。

### 3. `js/views/student-home.js`

- `rikaEntryUrl(CONFIG.rika?.url)` が文字列のときだけ、カードを作る。`null` のときは何も作らない（空の箱も置かない）。
- カードの形（`el` で作る）:

  ```
  section.rika-entry（aria-label="理科クエスト"）
    div.rika-entry-text
      h2: 理科クエスト
      p: 理科の問題に、自分のペースで取り組めます。
    a.btn.btn-primary.rika-entry-link（href=アドレス）: ひらく
  ```

- 置く場所: `main.page-main` の中の先頭（`filters` の前）。画面を作ったときから出す。授業の読みこみ中・読みこみ失敗・「まだクラスに入っていません」・「まだ授業がありません」のときも、出したままにする。
- リンクは同じタブで開く（`target` は付けない）。`syncControls` での無効化は、しない（ふつうのリンクのまま）。
- ほかの動き（一覧・検索・再送・ログアウト）は変えない。

### 4. `css/app.css`

- `.rika-entry`: 横並び（`display: flex`、すき間あり、`flex-wrap: wrap`、上下中央）、下に `var(--s-3)` の余白、内側の余白、角丸 12px、背景 `var(--teacher-bg)`、枠 `2px solid var(--c-main)`。
- `.rika-entry-text`: `flex: 1 1 240px; min-width: 0;`。`h2` は 22px・余白 0、`p` は余白 0。
- `.rika-entry-link`: 押せる所の高さを 44px 以上にする（`.btn` で足りていれば何も足さない）。下線なし。
- 今ある色の変数だけを使う。新しい色は足さない。

### 5. `README.md`

- 機能の説明の所（生徒の画面の説明がある節）に 1 行足す:「生徒の最初の画面の上に、理科クエスト（別のアプリ）を開く入口がある。データのやり取りはまだ無い（設計書 `docs/superpowers/specs/2026-11-19-rika-link-design.md`）」。合う節が見つからなければ、足さずに報告に書く。

## 端の場合

- 不正な入力: `CONFIG.rika` が無い、`url` が文字列でない（数字・`null`・配列・オブジェクト）、空・空白だけ、`http:`・`javascript:`・`data:` のアドレス、`https://user:pass@…`、読めない文字列、とても長い文字列（読めて https なら通してよい）→ `https` で読めるもの以外は `rikaEntryUrl` が `null` を返し、カードを出さない。
- 重複と境界: カードは 1 つだけ。授業の読みこみをやり直しても（「もう一度」「年度を変える」）、カードは増えない・消えない。
- 違反や失敗の見せ方: アドレスが使えないときは、カードを出さないだけ（生徒に見せる文は無い。設定のまちがいはテストで見つける）。理科クエストの側が開けないときの文は、この段階では作らない（ブラウザの表示に任せる）。

## テスト

- `tests/rika-link.test.js`（新しく作る）: `rikaEntryUrl` について、上の「不正な入力」の例がすべて `null`、`https://example.com/a/` と前後に空白のあるものが文字列で返ること。`CONFIG.rika.url` が `rikaEntryUrl` を通ること。
- 生徒の最初の画面のテスト（`tests/helpers/picture-dom.js` を使う今あるテストの書き方に合わせ、新しいファイル `tests/rika-entry-screen.test.js` に書く）:
  - 画面を作った直後（読みこみが終わる前）に、`rika-entry` が 1 つあり、その中のリンクの `href` が `CONFIG.rika.url` と同じアドレスで、文字が「ひらく」であること。`target` が無いこと。
  - 読みこみが終わったあとも 1 つだけあり、`page-main` の最初の子であること。
  - クラスが 0 件のとき（「まだクラスに入っていません」）も出ていること。
  - 授業の読みこみが失敗したとき（「つながりません」）も出ていること。
- `npm test` がすべて成功すること。
