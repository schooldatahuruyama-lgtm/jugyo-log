# 実装指示書: 手書き Task 5 — 先生の画面（記録の一覧の小さい画像、1 人の記録、コピーの注）

あなた（Codex）は、この指示書に沿ってコードを書きます。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

段階 1b-2（手書き。計画は `docs/superpowers/plans/2026-11-15-jugyo-log-stage1b-2.md`）。生徒が書いた手書きを、先生が見られるようにする（設計書 7.6: 一覧は「文章（手書きは小さい画像）」、コピーには「（手書き N 件は含まれていません）」）。

使うもの（すでにある。読むだけ）: `repo.listRecords`・`repo.getRecord` の `ink`、`repo.listInkThumbs(classId, lessonId, field)`、`js/ink-flow.js` の `loadInkFlow`、`js/views/parts/ink-pad.js` の `inkPad`（`readOnly: true`）。

## 変えるファイル

`js/review-logic.js`、`tests/review-logic.test.js`、`js/views/teacher-review.js`、`js/views/teacher-record.js`、`css/app.css`、`README.md`（数行）。ほかのファイルは変えない。

## 1. `js/review-logic.js`

- `reviewRows(people, options)` の各行に `hasInk: boolean` を足す: その生徒の記録の `ink[field]`（`field` は今出している欄。`learned` または `question`）があるとき `true`。記録が無い・形がおかしいときは `false`。
- `copyText(rows) → { text, count, inkCount }`: `inkCount` は、`hasInk` が `true` の行の数。`inkCount` が 1 以上なら、`text` の最後に 1 行「（手書き N 件は含まれていません）」を足す（文章が 1 つも無いときは、この 1 行だけ）。`count` は、今までどおり文章の数。
- テストを足す: `hasInk` の付き方。`inkCount` と最後の行。手書きが無いときは今までと同じ文字。

## 2. 記録の一覧（`js/views/teacher-review.js`）

- 一覧を読みこむとき、今の読みこみと同時に `repo.listInkThumbs(classId, lessonId, field)` を読む。「疑問／分かったこと」を切りかえたら、その欄の分を読み直す（一度読んだ欄は、「読み直す」を押すまで使い回す）。
- 各行: 今の文章の下に、`hasInk` の行は手書きの小さい画像を出す（`<img>`。`alt`「手書き」。高さ 120px まで、幅は行の中におさめる。うすい線の枠、白い背景）。
  - 小さい画像が無い（作れなかった・まだ届いていない）ときは、「（手書きがあります。開くと見られます）」と出す。
  - 文章が空で手書きがある行は、「（まだ書いていません）」と出さない（手書きだけを出す）。
  - 小さい画像の読みこみ（`listInkThumbs`）に失敗したら、一覧はそのまま出し、手書きのある行は上の「（手書きがあります。開くと見られます）」にする（一覧全体を失敗にしない）。
- 「全員分をコピー」: `copyText` の新しい結果を使う。コピーできたときの知らせは、`inkCount` が 1 以上なら「N 人分をコピーしました。手書き M 件は含まれていません。」。文章が 0 で手書きだけのときは、コピーせずに「コピーできる文章がありません（手書き M 件）。」と知らせる。
- 行を押すと 1 人の記録へ移る動き・並び順・しぼりこみ・帯のグラフは、変えない。

## 3. 1 人の記録（`js/views/teacher-record.js`）

- メモ・分かったこと・疑問の 3 つそれぞれで、文章の下に、その欄の手書きを出す（目録 `record.ink[field]` があるときだけ）。
  - 「手書きを読みこんでいます…」→ `loadInkFlow({ files: ctx.files, fileId })` → `inkPad({ ink, readOnly: true, label: 'メモの手書き' など })` の `node`。
  - 読みこみに失敗（通信・`bad-data`）: 「手書きを読みこめませんでした。」（`role="alert"`）と「もう一度」。ほかの欄・文章・添付は、そのまま見られる。
  - 3 つの読みこみは、1 つずつ順に行う（GAS を同時に呼ばない）。
- 文章が空で手書きがある欄は、「（まだ書いていません）」と出さない。文章も手書きも無いときだけ「（まだ書いていません）」。
- 「前の人」「次の人」で移ったら、前の人の読みこみの結果を出さない（今ある `stale` のやり方に合わせる）。部品は `destroy()` する。
- 先生の画面には、書く道具を出さない（`readOnly`）。

## 見た目（`css/app.css`）

- 一覧の小さい画像: 行の中で左に寄せ、文章との間に少し余白。横にはみ出さない。
- 1 人の記録の手書き: 欄の幅いっぱい。うすい線の枠。

## 端の場合

- 不正な入力: 目録の形がおかしい記録は、`repo` が落としているので、手書きなしとして出る。小さい画像の値が `data:image/` で始まらない文字のときは、画像として出さず、「（手書きがあります。開くと見られます）」にする。
- 重複と境界: 欄の切りかえを続けて押しても、同じ欄の読みこみは 1 回。読みこみの途中で別の授業・別の人に移ったら、古い結果を出さない。手書きが 0 件のときのコピーは、今までと同じ文字・同じ知らせ。
- 違反や失敗の見せ方: 読みこみの失敗は、その場所の文（と「もう一度」）で見せ、ほかの部分は使えるままにする。コピーに手書きが入らないことは、コピーした文字の最後の行と、知らせの両方で見せる（黙って落とさない）。

## 確かめ

- `npm test` がすべて成功し、変えた `.js` は `node --check` が通ること。
- 代役の `ctx` で、次を確かめて報告に書く: (1) 手書きのある生徒の行に小さい画像が出る。(2) 小さい画像が無い・読めないとき、文が出て一覧は使える。(3) コピーの最後の行と知らせ。(4) 1 人の記録に、3 つの欄の手書きが出て、道具が無い。(5) 読みこみの失敗と「もう一度」。

## 守ること

- `git add`・`git commit` はしない。画面に出す文字は `textContent` で入れる。`innerHTML` を使わない。`<img>` の `src` には、`data:image/` で始まる値だけを入れる。
- 生徒の手書きは、先生と本人だけが見られる（ほかの生徒の画面に出さない）。
- 記録の一覧・1 人の記録の、今の動き（文章・添付・重要用語・理解度）は変えない。
