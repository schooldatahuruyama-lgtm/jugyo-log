## 考え方（Claude Code の設計）

- 書きこみは、**ページごとに別のファイル・別の目録**にする（1 ページにつき線 2000 本・250000 文字まで。今の上限をページごとに使う）。
- コードの中では、ページの場所を**1 つの文字**で表す: `<場所>#p<ページ番号>`（例: `a1#p3`、`<資料の ID>#p12`）。ページ番号は 1〜999。こうすると、`serverInkTime`・`pictureIndex`・`saveInkFlow`・下書きは、今の「場所の名前で引く」作りのまま使える。
- データベースでは、`#` を使えないので、別の場所に入れ子で置く。`js/repo.js` が、読むときに平らな名前（`a1#p3`）に直し、書くときに入れ子の道に直す。

| | 写真（今あるもの） | PDF のページ（新しい） |
|---|---|---|
| 目録 | `records/<c>/<l>/<sid>/ink/<場所>` | `records/<c>/<l>/<sid>/inkPages/<場所>/p<N>` |
| 消した時刻 | `records/<c>/<l>/<sid>/inkCleared/<場所>` | `records/<c>/<l>/<sid>/inkPagesCleared/<場所>/p<N>` |
| 目録の中身 | `{ fileId, bytes, strokes, updatedAt, on }` | 同じ（`on` は PDF のファイル ID） |
| 手書きの形 | `{ v: 1, k: 'pic', h, s }` | 同じ（`h` はページの縦横の比から。`emptyPictureInk` を使う） |

## 1. `js/ink-logic.js`

- `inkPlaceKind(name)` に、ページの場所を足す: `<attachment の場所>#p<N>` → `'attachment-page'`、`<material の場所>#p<N>` → `'material-page'`。`N` は 1〜999 の整数で、先頭に 0 を付けない（`p01` は不正）。
- `inkPagePlace(place, page) → 文字`（`a1`, 3 → `'a1#p3'`。不正なら `TypeError`）と、`splitInkPlace(name) → { place, page } | null`（ページの場所でなければ `null`）。
- `hasPageInk(record, place, fileId) → 真偽`: 記録の `ink` に、`<place>#p…` で、`on === fileId` の目録が 1 つでもあるか。

## 2. `js/repo.js`

- `getRecord`・`listRecords`: `inkPages`・`inkPagesCleared` を読み、`ink`・`inkCleared` に、平らな名前（`a1#p3`）で入れる。形のおかしいもの（場所・ページの名前が不正、`on` が無い、数でない）は落とす。
- `setInk`・`removeInk`: 場所がページのときは、`inkPages/<場所>/p<N>` と `inkPagesCleared/<場所>/p<N>` を、今と同じ決まりで書く（保存は目録を書いて「消した時刻」を消す。消すときは目録を消して「消した時刻」を書く）。`on` は必ず要る。小さい画像は書かない。
- `removeAttachment(classId, lessonId, studentId, slot, clearedAt, pages)`: `pages`（ページ番号の配列）があるときは、同じ update で `inkPages/<slot>` を全部消し、`pages` のそれぞれに `inkPagesCleared/<slot>/p<N> = clearedAt` を書く。`pages` が配列でない（`undefined` はよい）・中身がページ番号でないなら `TypeError`。写真の `ink/<slot>` の扱いは今のまま。

## 3. 保存の流れ（`js/ink-flow.js`・`js/attachment-flow.js`）

- `saveInkFlow`: ページの場所を受けつける。「まだあるか」の確かめは、ページの場所では、もとの場所（`a1`・資料の ID）の添付・資料が、`type === 'pdf'` で `fileId === on` であること（写真の場所は今のまま `type === 'image'`）。無ければ今と同じ `gone: true`。ほかは今のまま。
- `resendInkDrafts`: ページの場所の下書きも送る（今の作りで動くはず。動かなければ直す）。
- `removeAttachmentFlow`: 読んだ記録に、その置き場所のページの目録（`<slot>#p…`）か、ページの「消した時刻」があるときは、`clearedAt = max(now, それらと写真の分の serverInkTime の最大 + 1)` と、**目録のあるページ番号の一覧**を `repo.removeAttachment` に渡す。消せたあと、ページの書きこみのファイルも全部 `files.trashStudent` で片付ける（失敗は無視）。写真の動きは今のまま。

## 4. 下書き（`js/ink-drafts.js`）

ページの場所を受けつける（`on` が要る）。保存先の名前に `#` が入ってよい（今の `:` で分ける読み方がこわれないこと）。

## 5. 規則（`docs/setup/rules.json`）

`records/$classId/$lessonId/$sid` の下（`ink` のとなり。`$other` より前）に足す。長い式は、下の部品を組み合わせて 1 行に書く。

```json
"inkPagesCleared": {
  ".validate": "newData.hasChildren()",
  "$place": {
    ".validate": "newData.hasChildren()",
    "$page": {
      ".validate": "<P> && (<A1> || <M1>) && newData.isNumber() && (!data.exists() || newData.val() > data.val()) && (!<OLDINK>.exists() || newData.val() > <OLDINK>.child('updatedAt').val())"
    }
  }
},
"inkPages": {
  ".validate": "newData.hasChildren()",
  "$place": {
    ".validate": "newData.hasChildren()",
    "$page": {
      ".validate": "<P> && (<A2> || <M2>) && newData.hasChildren(['fileId', 'bytes', 'strokes', 'updatedAt', 'on']) && (!data.exists() || newData.child('updatedAt').val() > data.child('updatedAt').val()) && (!<OLDCLEARED>.exists() || newData.child('updatedAt').val() > <OLDCLEARED>.val())",
      "on": …, "fileId": …, "bytes": …, "strokes": …, "updatedAt": …, "$other": { ".validate": false }
    }
  }
}
```

- `<P>` = `$page.matches(/^p([1-9]|[1-9][0-9]|[1-9][0-9][0-9])$/)`
- `<A1>` = `$place.matches(/^a[1-6]$/)`
- `<M1>` = `root.child('lessons').child($classId).child($lessonId).child('materials').child($place).exists()`
- `<A2>` = `($place.matches(/^a[1-6]$/) && <ATT>.child('type').val() === 'pdf' && newData.child('on').val() === <ATT>.child('fileId').val())`、`<ATT>` = `newData.parent().parent().parent().child('attachments').child($place)`
- `<M2>` = `(<MAT>.child('type').val() === 'pdf' && newData.child('on').val() === <MAT>.child('fileId').val())`、`<MAT>` = `root.child('lessons').child($classId).child($lessonId).child('materials').child($place)`
- `<OLDINK>` = `data.parent().parent().parent().child('inkPages').child($place).child($page)`
- `<OLDCLEARED>` = `data.parent().parent().parent().child('inkPagesCleared').child($place).child($page)`
- 子の規則（`on`・`fileId`・`bytes`・`strokes`・`updatedAt`）は、今の `ink/$field` と同じ値。

今ある `ink`・`inkCleared` の規則は変えない（写真は `ink`、PDF は `inkPages`。写真の置き場所に `inkPages` は書けない。PDF の置き場所に `ink` は書けない＝今の `type === 'image'` の条件のまま）。

## 6. 規則の確認（`js/rules-probe.js`）

今ある確かめのやり方に合わせて足す（今は 83 行）。片付けで残さない。

- 自分の PDF（`a2` など。`type: 'pdf'`）があるとき、`inkPages/<その場所>/p1` を、その PDF の `fileId` と同じ `on` で書く → できる
- 同じ場所の `p1` を、ちがう `on` で書く → できない
- ページの名前が不正（`p0`、`p1000`、`1`）→ できない（どれか 1 つでよい。`p0` を使う）
- 写真の置き場所（`a1`）に `inkPages/a1/p1` を書く → できない
- PDF の置き場所に `ink/<その場所>`（写真の形）を書く → できない
- `inkPages/<場所>/p1` を、前より古い時刻で書く → できない
- 授業にある PDF の資料の ID で `inkPages/<資料の ID>/p1` を書く → できる（確かめ用の資料に PDF が無ければ、用意する）

用意がむずかしいものは、作れる分だけ足して、作れなかったものを報告に書く。行の数を README などに反映する。`docs/superpowers/specs/2026-11-13-jugyo-log-1a-data.md` に、この形を書く。

## 端の場合

- 不正な入力: ページ番号が 0・負・小数・1000 以上・数字でない・先頭が 0 → 場所として受けつけない（`inkPlaceKind` は `null`、`repo` は `TypeError`、読むときは落とす、規則は断る）。`on` が無い・文字でない → 落とす・断る。
- 重複と境界: `p1` と `p999` は使える。同じ時刻の保存はサーバーを残す（今のまま）。PDF を消すと、全ページの目録が同じ update で消える。置き場所に別の PDF・写真を足しても、前の書きこみは出ない（`on` がちがう。写真なら `ink` を見るので、`inkPages` は見ない）。資料が授業から外されたあとの書きこみは残るが、どこにも出ない（写真と同じ割り切り）。
- 違反や失敗の見せ方: この Task では画面を変えない。PDF が無くなっていた保存は `gone: true` で返す。規則の確認の失敗は、表に × で出る。
