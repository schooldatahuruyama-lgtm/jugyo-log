## データの形

- 目録: `records/<classId>/<lessonId>/<sid>/ink/<field>` = `{ fileId: 文字, bytes: 数, strokes: 数（線の本数。1 以上）, updatedAt: 数（書いた時刻） }`。`field` は `memo`・`learned`・`question` だけ。線が 1 本も無い欄は、目録を置かない。
- 小さい画像: `recThumbs/<classId>/<lessonId>/<sid>/<key>` = データ URL（20000 文字まで）。`key` は、欄ごとに `inkMemo`・`inkLearned`・`inkQuestion`（添付の `a1`〜`a6` と同じ場所）。
- Drive のファイル: 中身は `serializeInk(ink)` の文字。種類は `application/json`。名前と説明は、今ある生徒の添付と同じ決まり（`s_<key>`、`student:<sid>:<classId>:<lessonId>`）。

## 規則（`docs/setup/rules.json`）

`records/$classId/$lessonId/$sid` の中（`attachments` のとなり）に足す。

```json
"ink": {
  ".validate": "newData.hasChildren()",
  "$field": {
    ".validate": "($field === 'memo' || $field === 'learned' || $field === 'question') && newData.hasChildren(['fileId', 'bytes', 'strokes', 'updatedAt'])",
    "fileId": { ".validate": "newData.isString() && newData.val().length >= 1 && newData.val().length <= 200" },
    "bytes": { ".validate": "newData.isNumber() && newData.val() >= 0 && newData.val() <= 400000" },
    "strokes": { ".validate": "newData.isNumber() && newData.val() >= 1 && newData.val() <= 2000 && newData.val() % 1 === 0" },
    "updatedAt": { ".validate": "newData.isNumber()" },
    "$other": { ".validate": false }
  }
}
```

`recThumbs/…/$sid/$aid` の `.validate` を、次に変える。

```
($aid.matches(/^a[1-6]$/) || $aid === 'inkMemo' || $aid === 'inkLearned' || $aid === 'inkQuestion') && newData.isString() && newData.val().length <= 20000
```

## `js/ink-drafts.js`（端末の中の下書き）

`createInkDrafts({ storage }) → { get, put, remove, list, clear }`。今ある `js/drafts.js` と同じ作り（保存先が使えなくても止めない）。

- キー: `jugyolog:ink:<studentId>:<classId>:<lessonId>:<field>`。値: `{ ink, editedAt: 数, key: 文字（保存に使うキー） }` の JSON。
- `get(studentId, classId, lessonId, field) → { ink, editedAt, key } | null`: こわれている・形がちがう・`field` が 3 つ以外 → `null`。`ink` は `cleanInk` を通す。
- `put(studentId, classId, lessonId, field, { ink, editedAt, key }) → boolean`: 保存できたら `true`。容量がいっぱいなどで保存できなければ `false`（例外を出さない）。
- `remove(studentId, classId, lessonId, field)`、`list(studentId) → [{ classId, lessonId, field, ink, editedAt, key }]`、`clear()`（`jugyolog:ink:` で始まるものを全部消す）。
- 今ある文字の下書き（`jugyolog:draft:`）とは、キーの頭がちがうので、たがいに読まない・消さない。
- `js/main.js`: `createInkDrafts` を作って `ctx.inkDrafts` に入れる。`signOutAll` で `inkDrafts.clear()` も呼ぶ（今ある `drafts.clear()` と同じ所）。

## `js/ink-flow.js`（保存・読みこみの順番。画面を持たない）

- `saveInkFlow({ repo, files, classId, lessonId, studentId, field, ink, key, thumb, editedAt, previous }) → { index }`
  - `previous` は、今の目録（`{ fileId, … }` または `null`）。
  - 線が 1 本も無い（`isEmptyInk`）: `repo.removeInk(…)` → `previous` があれば `files.trashStudent(previous.fileId)`（失敗は無視）→ `{ index: null }`。
  - それ以外: `files.uploadInk({ key, classId, lessonId, text: serializeInk(ink) })` → `repo.setInk(…, { fileId, bytes, strokes: ink.s.length }, thumb, editedAt)` → `previous` があり、`fileId` がちがえば、古いファイルを `trashStudent`（失敗は無視）→ `{ index: { fileId, bytes, strokes, updatedAt: editedAt } }`。
  - `repo.setInk` が `denied` で失敗したら、上げたばかりのファイルを片付けて（失敗は無視）、エラーをそのまま投げる。通信の失敗なら、ファイルは残す（同じ `key` でやり直すと、GAS が同じファイルを返す）。
- `loadInkFlow({ files, fileId }) → ink`: `files.loadInk(fileId)` → `parseInk`。`null`（こわれている）なら `NetError('bad-data')` を投げる（空の手書きとして返さない）。
- `resendInkDrafts({ repo, files, inkDrafts, studentId, queue }) → { sent, kept, dropped }`: 残っている下書きを、1 件ずつ送り直す。今ある `resendDrafts`（`js/record-flow.js`）と同じ考え方にする。
  - 授業ごとの順番待ち（`queue.run('<classId>/<lessonId>', …)`）の中で行う。
  - サーバーの目録の `updatedAt` が、下書きの `editedAt` **以上**なら、サーバーのほうが新しいので、下書きを捨てる（`dropped`）。
  - それ以外は `saveInkFlow`（`thumb` は `undefined` でなく、**今ある小さい画像を消さないよう**、送り直しのときは小さい画像を書きかえない。そのために `saveInkFlow` と `repo.setInk` は、`thumb === undefined` のとき、小さい画像に触らない。`null` のときは消す。文字のときは書く）。成功したら、その間に下書きが変わっていなければ消す（`sent`）。
  - 失敗（規則に断られた場合もふくむ）は、下書きを残して次へ（`kept`）。

上の `thumb` の決まり（`undefined` は触らない・`null` は消す・文字は書く）に合わせて、`repo.setInk` の説明も読みかえること。

## 端の場合

- 不正な入力: 目録の形がおかしい（知らない欄・数の文字列・`strokes` が 0 や小数・とても大きい `bytes`）→ `repo` は落とし、規則は断る。`field` が 3 つ以外 → `TypeError`。こわれた JSON のファイル → `loadInkFlow` が `bad-data`、GAS は保存を断る。大きすぎるデータ → GAS は `toobig`。
- 重複と境界: 同じ `key` で 2 回送っても、ファイルは 1 つ（GAS の今ある決まり）。`bytes` が 400000 ちょうどは通る。`strokes` が 2000 ちょうどは通る。線が 1 本も無い保存は、目録と小さい画像を消す（もともと無くても成功）。送り直しで、`updatedAt` と `editedAt` が同じときは、下書きを捨てる。
- 違反や失敗の見せ方: このタスクは画面を持たない。失敗は、エラー（`NetError` のコード）として呼び出し元に返す（黙って成功にしない）。画面での見せ方は Task 4・5 で作る。規則の確認の失敗は、今までどおり結果の表に × で出る。
