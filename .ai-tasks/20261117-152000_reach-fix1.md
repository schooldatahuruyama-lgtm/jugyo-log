# 実装指示書: 「どこに届くか」修正 1（置き場所が https でないとき）

あなた（Codex）は、この指示書に沿ってコードを直します。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

`.ai-tasks/20261117-150000_reach-check.md` で作った「どこに届くか」を、手元（`http://127.0.0.1:8791/check.html`）で試したところ、「このアプリの置き場所」（`location.origin`）が `http://` のため、一覧を作る所で `TypeError` になり、**全部の行き先が調べられなかった**（「行き先の設定を確認してください（https:// のアドレスが必要です）。」）。

## 直すこと

- 設定や `location.origin` から作る行き先（Firebase のデータベース・このアプリの置き場所）は、アドレスが `https://` で始まらないとき、**その行き先だけを一覧から外す**（ほかの行き先は調べる）。指示書の「設定から取れないときは、その行き先を一覧から外す」と同じ扱いにする。
- 決め打ちで書いてある行き先（`https://script.google.com/` など）が `https://` でないときは、今のとおり `TypeError`（書きまちがいを見つけるため）。

## 端の場合

- 不正な入力: `location.origin` が `null`（`file:` で開いた）・`http://`・空 → その行き先を外す。データベースの URL が `http://`・空・文字でない → 外す。
- 重複と境界: 2 つとも外れても、残りの行き先は調べる。
- 違反や失敗の見せ方: 外した行き先は、表に出さない。文は足さない。

## テスト

- `tests/reach-check.test.js`（または一覧のテストの所）: 置き場所が `http://127.0.0.1:8791` → その行き先だけ無く、ほかは残る。`null` でも同じ。決め打ちの行き先が `http://` → `TypeError`。
- `npm test` がすべて成功し、変えた `.js` は `node --check` が通る。
