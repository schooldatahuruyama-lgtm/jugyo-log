# 実装指示書: 段階 1b-1 Task 3 の修正 3（添付の操作を、1 つずつ順に行う）

あなた（Codex）は、この指示書に沿ってコードを直します。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

Codex レビュー `.ai-review/20261114-200217_round1.md` の指摘 1・2（High）・3（Medium）を直す。

3 つとも、添付の部品（`js/views/parts/attachment-pane.js`）の中で、**2 つの操作（足す・やり直す・やめる・消す・目録の読み直し）が同時に進む**ときに起きる。そこで、**部品の中の操作を 1 つずつにする**（Claude Code の判断）。同時に進む操作が無ければ、指摘された順番の入れちがいは起きない。

## 変えるファイル

`js/views/parts/attachment-pane.js` だけ。

- 部品の中で、通信をともなう操作（足す・「やり直す」・「やめる」・「消す」と、その中の目録の読み直し）は、**同時に 1 つだけ**にする。1 つが進んでいる間は、部品の中のほかの操作のボタン（「＋ 写真・PDF」、ファイルの入力欄、ほかの添付の「やり直す」「やめる」「消す」）を押せなくする（`disabled`）。終わったら（成功でも失敗でも）、押せるように戻す。
  - 進んでいる間も、保存済みの添付を押して大きく表示することは、できてよい（通信はするが、目録を変えない）。
  - 進んでいる間は、どの操作が進んでいるかを、今までどおりその添付の場所に文字で出す（「送っています…」「消しています…」など）。「＋ 写真・PDF」の下には「終わるまで、少し待ってください。」と出す（`role="status"`）。
- 進んでいる操作が終わる前に、同じ添付や別の添付の処理を始める道（タイマー・並行の Promise など）を残さない。操作の入り口で「進んでいる操作があれば何もしない」を確かめる。
- 配列から行を外すときは、**その行が今の配列にあるときだけ**外す（`indexOf` が `-1` のときに `splice` しない）。
- `destroy()` のあとは、画面を書きかえない。登録の前なら登録しない（今ある `isCancelled`）。
- 生徒から見えるほかの動き（文・並び順・6 個まで・確かめのダイアログ）は変えない。`busy`（送っている途中・失敗して止まっているものがある）も今のまま。

## 端の場合

- 不正な入力: 進んでいる間にファイルが選ばれた（入力欄が押せないので、ふつうは起きない）ときは、何もせず、入力欄を空に戻す。
- 重複と境界: 「消す」の確かめのダイアログを出している間も、「進んでいる」として、ほかの操作を始めない（やめたら、すぐ戻す）。操作が例外で終わっても、必ず押せるように戻す（`finally`）。続けて 6 個足すときは、1 つ終わるごとに次を選べる。
- 違反や失敗の見せ方: 今ある文のまま（「送れませんでした」「消せませんでした。もう一度ためしてください。」「確かめられませんでした。もう一度ためしてください。」）。待っている間は「終わるまで、少し待ってください。」。
