# 実装指示書: 理科クエストの記録の置き場所（規則と、規則の確認）

あなた（Codex）は、この指示書に沿ってコードを書きます。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

設計書 `docs/superpowers/specs/2026-11-19-rika-link-design.md` の「段階 2b」。理科クエスト（別のアプリ）が、授業ログと同じ Firebase に、生徒ごとの記録を保存できるようにする。この指示書で作るのは、**データベースの規則**と、**規則の確認（`js/rules-probe.js`）の項目**だけ。授業ログの画面は変えない。理科クエスト側は、別の指示書で作る。

## データの形（理科クエストが読み書きする）

| 場所 | 中身 | 読める人 | 書ける人 |
|---|---|---|---|
| `rika/state/<Firebase の uid>` | `{ v: 1, updatedAt: 数, json: 文字列 }`。`json` は「今の状態」（プロフィール・レベル・理解度など）を JSON にした文字列。500000 文字まで | 本人・先生 | 本人（授業ログのアカウントがある人・先生）。先生は、消すことだけできる |
| `rika/log/<Firebase の uid>/<かたまりの id>` | 文字列（答えの履歴のかたまりを JSON にしたもの）。200000 文字まで。**1 回書いたら、本人は書きかえも削除もできない** | 本人・先生 | 本人（新しく書くだけ）。先生は、`rika/log/<uid>` を消すことだけできる |

- キーは、生徒 ID（`s26-001` など）ではなく、**Firebase の uid**。理科クエストは授業ログのログイン（uid）しか知らないため。
- 本名・メールアドレスは置かない（理科クエスト側の決まり）。

## 変えるファイルと内容

### 1. `docs/setup/rules.json`

`rules` の最後（`marks` のあと）に足す。先生かどうか・生徒かどうかの式は、今ある書き方と同じにする。

```json
"rika": {
  "state": {
    ".read": "auth != null && root.child('teacherList').child(auth.uid).val() === true",
    "$uid": {
      ".read": "auth != null && auth.uid === $uid",
      ".write": "auth != null && ((auth.uid === $uid && (root.child('teacherList').child(auth.uid).val() === true || root.child('accounts').child(auth.uid).isString())) || (root.child('teacherList').child(auth.uid).val() === true && !newData.exists()))",
      ".validate": "newData.hasChildren(['v', 'updatedAt', 'json'])",
      "v": { ".validate": "newData.val() === 1" },
      "updatedAt": { ".validate": "newData.isNumber()" },
      "json": { ".validate": "newData.isString() && newData.val().length >= 2 && newData.val().length <= 500000" },
      "$other": { ".validate": false }
    }
  },
  "log": {
    ".read": "auth != null && root.child('teacherList').child(auth.uid).val() === true",
    "$uid": {
      ".read": "auth != null && auth.uid === $uid",
      ".write": "auth != null && root.child('teacherList').child(auth.uid).val() === true && !newData.exists()",
      "$chunk": {
        ".write": "auth != null && auth.uid === $uid && !data.exists() && (root.child('teacherList').child(auth.uid).val() === true || root.child('accounts').child(auth.uid).isString())",
        ".validate": "$chunk.matches(/^[A-Za-z0-9_-]{8,40}$/) && newData.isString() && newData.val().length >= 2 && newData.val().length <= 200000"
      }
    }
  }
}
```

- 上の式で、下の「規則の確認」の期待どおりにならない所を見つけたら、**期待のほうを正**として式を直し、報告に書く（規則の式は Firebase の本物では試せないので、読んで確かめる）。
- 今ある規則は変えない。

### 2. `js/rules-probe.js`

今ある「AI のまとめ」の項目と同じ作りで、次の項目を足す（確認用の生徒 = `makeProbeStudent` で作る 2 つ目のログイン。その `uid` を使う）。項目の名前は、今ある項目の言い方に合わせる。

| 試すこと | 期待 |
|---|---|
| 生徒として、自分の `rika/state/<自分の uid>` に正しい形を書く | ok |
| 生徒として、自分の `rika/state` を読む | ok |
| 生徒として、`json` の無い `rika/state` を書く | denied |
| 生徒として、知らない項目（`extra`）の付いた `rika/state` を書く | denied |
| 生徒として、`json` が 500001 文字の `rika/state` を書く | denied |
| 生徒として、自分の `rika/log/<自分の uid>/<id>` に文字列を書く | ok |
| 生徒として、同じ `rika/log` のかたまりを、もう一度書く（上書き） | denied |
| 生徒として、自分の `rika/log` のかたまりを消す | denied |
| 生徒として、id の形がちがう（`a.b`・7 文字以下）`rika/log` を書く | denied |
| 生徒として、ほかの人の uid（先生の uid）の `rika/state` を読む | denied |
| 生徒として、ほかの人の uid の `rika/state` を書く | denied |
| 生徒として、ほかの人の uid の `rika/log` に書く | denied |
| 生徒として、`rika/state` 全体を読む | denied |
| 先生として、生徒の `rika/state` を読む | ok |
| 先生として、生徒の `rika/log` を読む | ok |
| 先生として、生徒の `rika/state` を書きかえる（消す以外） | denied |
| ログインなしで、`rika/state/<生徒の uid>` を読む | denied |

- 片付け: 確認のあと、先生として `rika/state/<生徒の uid>` と `rika/log/<生徒の uid>` を消す（今ある片付けと同じ所で。失敗したら、今ある片付けと同じように「片付け」の行を不合格にする）。前の確認の残りがあっても、やり直しで通るようにする（今ある項目と同じ考え方）。
- 500001 文字の値は、その項目のときだけ作る。
- `id` の形のちがう項目は、パスに使えない文字（`.`）を REST のパスとして送ると別の意味になるので、送り方が今ある通信の道具（`net`）で安全にできないなら、「7 文字以下の id」だけにして、報告に書く。

## 端の場合

- 不正な入力: `v` が 1 でない・`updatedAt` が文字・`json` が数字や空文字や 500001 文字以上・知らない項目つき → 規則で拒む。`rika/log` の値が文字列でない・200001 文字以上・id が 8〜40 文字の英数字と `_` `-` でない → 拒む。
- 重複と境界: `json` がちょうど 500000 文字・かたまりがちょうど 200000 文字は通る（確認の項目には入れなくてよい。式で保証する）。同じ id のかたまりの 2 回目は、中身が同じでも拒む。
- 違反や失敗の見せ方: 規則の確認の表に、今までどおり ○／× で出す。授業ログの画面には、何も足さない。

## テスト

- `tests/rules-probe.test.js`: 足した項目が、期待どおりの順・期待（ok／denied）で出ること。規則が古い（`rika` が無く、すべて denied になる）ときに、足した「ok」の項目が不合格になること。片付けで `rika/state/<uid>` と `rika/log/<uid>` が消えること・片付けの失敗が不合格になること。今あるテストの数の確かめ（項目の合計）を新しい数に直す。
