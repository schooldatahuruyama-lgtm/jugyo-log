# 実装指示書: スタンプ 修正 1（レビューの指摘 1 件）

あなた（Codex）は、この指示書に沿ってコードを直します。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

Codex レビュー `.ai-review/20261117-180905_round1.md` の指摘 1（High）を直す。

`repo.stampReplies` は、一覧を読んだときの返事（`existing`）から、返事の全体を書きかえている。一覧を開いたあと、別のタブ・端末で返事の文を足した・直した場合、「全員にスタンプを押す」で、新しい文が消える・古い文にもどる。はじめの指示書（Claude Code の設計）が、返事の全体を書く形にしていたのが原因。

## 直すこと

- `js/repo.js` の `stampReplies`: 返事の全体を書かない。生徒ごとに、**`replies/<クラス>/<授業>/<生徒>/seen` を `true`、`…/updatedAt` を `now`、`replyMarks/<生徒>/<クラス>/<授業>` を `now`** にする書きこみだけを、1 回のルート update で行う。`text` の道には触れない（今ある文は、そのまま残る）。
- 引数の `existing` は要らなくなるので外す（呼ぶ側 `js/views/teacher-review.js` も合わせる）。`studentIds` の確かめ（配列・空でない・ID の形・60 人まで）は今のまま。
- 1 人の記録（`js/views/parts/reply-box.js`）の「スタンプを押す」「スタンプを取り消す」も、同じ問題が無いかを見る。今は `setReply`・`removeReply` で返事の全体を書いている。次のようにする:
  - 押す: `repo.stampReplies(classId, lessonId, [studentId], now)` を使う（文に触れない）。
  - 取り消す: 新しく `repo.unstampReply(classId, lessonId, studentId, { hasText }, now)` を足す。`hasText` が真なら、`…/seen` を `null`、`…/updatedAt` を `now`、`replyMarks/…` を `now` にする（文は残す）。偽なら、今ある `removeReply` と同じ（返事と目印を消す）。`hasText` は、画面が今持っている「保存してある文」があるかどうか。
- 返事の文の「保存する」（`setReply`）は、今のまま（文と、今の `seen` を一緒に書く。1 人の記録を開いている先生が、自分で書きかえる操作なので）。

## 端の場合

- 不正な入力: 今のまま（`TypeError`）。`unstampReply` の `hasText` が真偽でない → 偽として扱う。
- 重複と境界: 返事がまだ無い生徒に `stampReplies` → `seen` と `updatedAt` だけの返事ができる（規則の「`updatedAt` があり、`text` か `seen` がある」を満たす）。もうスタンプがある生徒に押しても、時刻が進むだけ。別の端末で返事ごと消された直後に `unstampReply`（`hasText` 真）→ `seen` を消して `updatedAt` だけを書くことになり、規則が断る → 今ある失敗の文を出す（「保存できませんでした。もう一度押してください。」）。そのあと、欄は読み直した中身に合わせる。
- 違反や失敗の見せ方: 今ある文のまま。
