# 実装指示書: 理科クエストの `rika/state` に、古い状態からの上書きを止める決まりを足す

あなた（Codex）は、この指示書に沿ってコードを直します。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。もとの指示書は `.ai-tasks/20261119-160000_rika-rules.md`。

## 目的

理科クエスト側のレビューで、「古い状態のままの端末が保存すると、別の端末で進めた分を上書きして消す」ことが分かった。規則で、**いちばん新しい版を見てから書いた保存だけを通す**ようにする。

## 決まり

`rika/state/<uid>` の形を `{ v: 1, updatedAt: 数, json: 文字列, base: 数（無くてもよい） }` にする。

- 値がまだ無いとき（初めて）: 今までどおり。`base` は無くてよい。
- すでに値があるとき: `base` が**今入っている `updatedAt` と同じ**で、新しい `updatedAt` が**今の `updatedAt` より大きい**ときだけ書ける。
- 消すこと（本人・先生）は、今までどおりできる。

## 変えるファイルと内容

### 1. `docs/setup/rules.json`

`rika/state/$uid` を次のように直す（`.read`・`.write`・`v`・`updatedAt`・`json`・`$other` は変えない）。

```json
".validate": "newData.hasChildren(['v', 'updatedAt', 'json']) && (!data.exists() || (newData.child('base').val() === data.child('updatedAt').val() && newData.child('updatedAt').val() > data.child('updatedAt').val()))",
"base": { ".validate": "newData.isNumber()" },
```

### 2. `js/rules-probe.js`

- 今ある「自分の `rika/state` に正しい形を書く」（初めての書きこみ。`base` なし）は、そのまま。
- そのあとの「拒まれるはず」の項目（`json` なし・`extra` つき・500001 文字）は、**正しい `base`（今入っている `updatedAt`）と、より大きい `updatedAt`** を付けて送る（`base` の決まりでなく、本来の理由で拒まれることを確かめるため）。
- 次の 4 項目を、「500001 文字」の項目のあとに足す。

| 試すこと | 期待 |
|---|---|
| 生徒として、`base` なしで自分の `rika/state` を書きかえる | denied |
| 生徒として、古い `base`（今の `updatedAt` とちがう数）で書きかえる | denied |
| 生徒として、正しい `base` でも `updatedAt` が今と同じで書きかえる | denied |
| 生徒として、正しい `base` と、より大きい `updatedAt` で書きかえる | ok |

- 最後の「ok」のあとは、入っている `updatedAt` が変わる。そのあとの項目（先生として書きかえる → denied など）は、**新しい `updatedAt` を正しい `base` として**送る（先生が拒まれる理由が `base` でなく、権限であることを確かめるため）。
- 「ほかの人（確認用の uid）の `rika/state` を書く」は、値が無い所への初めての書きこみの形（`base` なし）のままでよい。
- 項目の合計は 124 → 128。片付けは今のまま。

### 3. 文書

- `README.md` の「規則の確認」の表に 4 行を足し、項目の数（124）を書いてある所をすべて 128 に直す（`docs/setup/` の手順書も）。過去の実施の記録（日付つきの結果）の数は変えない。

## 端の場合

- 不正な入力: `base` が文字・真偽 → 拒む。`base` が今の `updatedAt` とちがう・無い（値があるとき）→ 拒む。
- 重複と境界: `updatedAt` が今と同じ → 拒む。今より 1 大きい → 通る。
- 違反や失敗の見せ方: 規則の確認の表に ○／× で出す。授業ログの画面は変えない。

## テスト

- `tests/rules-shape.test.js`: 新しい `.validate` と `base` の式。
- `tests/rules-probe.test.js`: 足した 4 項目の順と期待。偽のデータベースに `base` の決まりを入れ、「拒まれるはず」の項目が正しい `base` を付けて送られていること。規則が古い（`base` を見ない）と、足した「denied」の 3 項目が不合格になること。項目の合計を 128 に。
- `npm test` がすべて成功すること。
