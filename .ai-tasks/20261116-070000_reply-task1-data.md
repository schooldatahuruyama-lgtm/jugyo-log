## 決めたこと（Claude Code の設計。先生に伝えてある）

- 返事は、**生徒 1 人・授業 1 回につき 1 つ**。中身は、文（1〜400 文字。無くてもよい）と、「見ました」の印（あり・なし）。どちらかは必ずある。
- 書けるのは先生だけ。読めるのは、先生と、その生徒本人だけ。生徒は返事に返せない。
- 生徒の一覧（タイル）に印を出すため、生徒ごとの目印を別に持つ。

## データの形

| 場所 | 中身 | 読める | 書ける |
|---|---|---|---|
| `replies/<classId>/<lessonId>/<studentId>` | `{ text?: 文字（1〜400）, seen?: true, updatedAt: 数 }` | 先生（クラスごとにまとめて）、本人 | 先生 |
| `replyMarks/<studentId>/<classId>/<lessonId>` | `updatedAt` と同じ数 | 先生、本人 | 先生 |

- `text` と `seen` のどちらも無い返事は作らない（消す）。`seen` は `true` だけ（`false` は書かない）。
- 2 つは、いつも同じ 1 回の update で書く・消す。

## 1. `js/config.js`

`reply: { textMax: 400 }` を足す。

## 2. 計算（新しい `js/reply-logic.js`）

- `cleanReply(value) → { text, seen } | null`: `value` が物でなければ `null`。`text` は文字なら、改行を `\n` にそろえ、前後の空白を取る（中の改行は残す）。文字でなければ `''`。`seen` は `value.seen === true`。`text` が `''` で `seen` が `false` なら `null`。
- `checkReply({ text, seen }) → { ok: true } | { ok: false, error }`: `text` が `CONFIG.reply.textMax` を超える → `'too-long'`。`text` が `''` で `seen` でない → `'empty'`。文字数は、今ある記録の文字数の数え方（`js/record-logic.js`）に合わせる。
- `toReply(value) → { text, seen, updatedAt } | null`: データベースから読んだ値を直す。形のおかしいもの（物でない、`updatedAt` が数でない、`text` が 400 を超える、`text` も `seen` も無い）は `null`。

## 3. `js/repo.js`

- `getReply(classId, lessonId, studentId) → reply | null`
- `listReplies(classId, lessonId) → { [studentId]: reply }`（おかしいものは落とす）
- `getReplyMarks(studentId, classId) → { [lessonId]: 数 }`（数でないものは落とす）
- `setReply(classId, lessonId, studentId, { text, seen }, now)`: `cleanReply` と `checkReply` を通し、だめなら `TypeError`。`replies/…` に `{ text（'' のときは入れない）, seen（true のときだけ）, updatedAt: now }` を、`replyMarks/…` に `now` を、1 回のルート update で書く。
- `removeReply(classId, lessonId, studentId)`: 2 つを 1 回の update で `null` にする。
- `deleteLesson`: 同じ update で `replies/<cid>/<lid>` も `null` にする。`replyMarks` は、消す前に `replies/<cid>/<lid>` を浅く読んで（`shallow: true`）、その生徒の分を同じ update で `null` にする（読めなかったら、授業は消さずに失敗を投げる）。

## 4. 規則（`docs/setup/rules.json`）

`marks` のとなりに足す。`<T>` = `auth != null && root.child('teacherList').child(auth.uid).val() === true`、`<ME>` = `auth != null && root.child('accounts').child(auth.uid).val() === $sid`。

```json
"replies": {
  "$classId": {
    ".read": "<T>",
    ".write": "<T>",
    "$lessonId": {
      "$sid": {
        ".read": "<ME>",
        ".validate": "newData.hasChildren(['updatedAt']) && (newData.hasChild('text') || newData.hasChild('seen'))",
        "text": { ".validate": "newData.isString() && newData.val().length >= 1 && newData.val().length <= 400" },
        "seen": { ".validate": "newData.val() === true" },
        "updatedAt": { ".validate": "newData.isNumber()" },
        "$other": { ".validate": false }
      }
    }
  }
},
"replyMarks": {
  "$sid": {
    ".read": "<T> || <ME の中身>",
    ".write": "<T>",
    "$classId": { "$lessonId": { ".validate": "newData.isNumber()" } }
  }
}
```

今ある規則は変えない。

## 5. 規則の確認（`js/rules-probe.js`）

今ある確かめのやり方に合わせて足す（今は 90 行）。片付けで残さない。

- 先生が `replies/（クラス）/（授業）/（確認用の生徒）` に `{ text, updatedAt }` を書く → できる
- 先生が `{ seen: true, updatedAt }` を書く → できる
- 先生が `{ updatedAt }` だけ → できない／`text` が 401 文字 → できない／`seen: false` → できない（どれも 1 行ずつ）
- 先生が `replyMarks/（確認用の生徒）/（クラス）/（授業）` に数を書く → できる
- 確認用の生徒が、自分の `replies/…/（自分）` を読む → できる／書く → できない
- 確認用の生徒が、自分の `replyMarks/（自分）/…` を読む → できる／書く → できない
- 確認用の生徒が、ほかの生徒の `replies/…/（ほかの生徒）` を読む → できない
- 確認用の生徒が、`replies/（クラス）/（授業）` をまとめて読む → できない

用意がむずかしいものは、作れる分だけ足して、作れなかったものを報告に書く。行の数を README などに反映する。`docs/superpowers/specs/2026-11-13-jugyo-log-1a-data.md` に、この形を書く。

## 端の場合

- 不正な入力: `text` が文字でない → `''` として扱う。401 文字以上 → `TypeError`（画面では Task 2 で止める）。空白だけ・改行だけ → `''`。`seen` が `true` 以外（`'true'`、`1`）→ 印なし。ID に使えない文字 → 今ある `key()` のとおり `TypeError`。読んだ値がおかしい → 無いものとして扱う。
- 重複と境界: ちょうど 400 文字は書ける。同じ返事を続けて保存すると、`updatedAt` だけ進む。返事の無い生徒の `removeReply` は成功する。記録の無い生徒にも書ける（規則では止めない。画面は Task 2）。授業を消すと、返事と目印も消える。
- 違反や失敗の見せ方: この Task では画面を変えない。規則の確認の失敗は、表に × で出る。
