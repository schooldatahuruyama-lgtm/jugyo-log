# 実装指示書: クラスの疑問のまとめ（自動。AI を使わない）

あなた（Codex）は、この指示書に沿ってコードを書きます。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

設計書 `docs/superpowers/specs/2026-11-12-jugyo-log-design.md` の「4 以降: アプリ内の自動要約」。要件定義書の課題 ③「先生が一人ひとりの理解や疑問を把握しにくい」。

先生の決定（2026-11-15）:

- **先生用**。先生の「記録」の画面で、その授業の全員の「疑問」と「分かったこと」をまとめて出す。
- **AI を使わない**。アプリの中（先生のブラウザ）だけで集計する。生徒の文章を外へ送らない。費用をかけない。
- 手書きの記録は、まとめに入れない（人数だけ出す）。

データベース・規則・GAS は変えない。今 `js/views/teacher-review.js` が読んでいるもの（記録の一覧、名簿、授業と重要用語）だけを使う。新しい通信は足さない。

## 画面の動き（Claude Code の設計。先生に伝えてある）

`js/views/teacher-review.js` の、理解度のグラフの下・「生徒の記録」の上に、カード「まとめ（自動）」を足す。部品は新しい `js/views/parts/summary-box.js`、計算は新しい `js/summary-logic.js`（DOM を使わない）。

カードの中身（上から）:

1. **説明の 1 行**: 「文字で書いた記録を、このアプリの中で数えたものです。手書きは入っていません。」
2. **書いた人数**（「疑問」と「分かったこと」のそれぞれ）: 「文字 N 人・手書き M 人・まだ K 人」。
   - 文字: その欄に、空白でない文字がある。手書き: その欄の文字が空で、手書きの目録（`record.ink.question`・`record.ink.learned`）がある。まだ: どちらも無い（記録そのものが無い名簿の生徒を含む）。文字と手書きの両方がある生徒は「文字」に数える。
   - 人数の母数は、今ある理解度のグラフと同じ人たち（名簿の生徒 ＋ 名簿にいないが記録のある生徒。返事だけの生徒は入れない）。
3. **重要用語ごとの人数**（授業に重要用語があるときだけ）: 表。列は「用語・疑問に出てきた人数・分かったことに出てきた人数」。「疑問に出てきた人数」の多い順、同じなら「分かったこと」の多い順、同じなら授業の用語の順。どちらも 0 人の用語も出す（0 と出す）。
4. **よく出てくる言葉**（「疑問」と「分かったこと」のそれぞれ）: 2 人以上が書いた言葉を、人数の多い順に 10 個まで。「言葉（N 人）」の形のボタン。無ければ「（2 人以上が書いた言葉は、ありません）」。
5. **理解度が低い生徒の疑問**: 理解度が「あまり分からなかった」「全然分からなかった」の生徒のうち、「疑問」を文字で書いた人の、出席番号と文。出席番号順（名簿にいない生徒は最後）。いなければ「（ありません）」。該当の生徒で手書きの人がいれば、最後に「ほかに、手書きの人が N 人います。」
6. 3 の表の行と 4 のボタンを押すと、その下に、**その言葉を書いた生徒の出席番号と文**（「疑問」と「分かったこと」を分けて）を出す。もう一度押すと閉じる。別の言葉を押すと、入れかわる。押してあるものは `aria-expanded="true"`。
7. ボタン「まとめをコピー」: 2〜5 を、今ある「全員分をコピー」と同じやり方で、文字としてコピーする（成功・失敗の知らせも同じ出し方）。生徒の ID は入れず、今ある一覧と同じ呼び方（「N 番」「名簿にいない」）にする。

- 記録が 1 つも無い授業では、カードに「まだ記録がありません。」だけ出す。
- 授業・クラスを選びなおしたとき、「読み直す」を押したときは、まとめも作り直し、開いていた 6 は閉じる。
- 1 人の記録へ行って戻ったときも、今の一覧と同じ中身で出す。
- 生徒の画面には出さない。

## 言葉の数え方（`js/summary-logic.js`）

外の辞書・`Intl.Segmenter` は使わない（端末によって結果が変わらないようにする）。

- そろえ方 `normalizeText(text)`: `NFKC` にし、英字は小文字にし、空白・改行を取る。数えるとき・探すときは、いつもこれを通す。
- 重要用語が「出てきた」: そろえた文に、そろえた用語が含まれる。空の用語は数えない。
- よく出てくる言葉 `extractWords(text) → 文字の配列（重複なし）`: そろえた文から、**漢字が 2 文字以上続く所**と、**カタカナ（長音「ー」を含む）が 3 文字以上続く所**を取り出す。次の言葉は除く: 今日・授業・自分・先生・疑問・理解・勉強・学習・感想・最初・最後・今回・次回・時間・内容・部分・場合・必要・大切・大事。授業の重要用語と同じ言葉（そろえて同じ）も除く（3 で出るので）。
- 人数は、**書いた生徒の数**で数える（同じ生徒が同じ言葉を何度書いても 1）。同じ人数のときは、言葉の文字コード順。
- 主な関数（名前と形。中は任せる）:
  - `summarize({ students, records, terms }) → { counts: { question: { text, ink, none }, learned: { text, ink, none } }, terms: [{ term, question: [生徒], learned: [生徒] }], words: { question: [{ word, students: [生徒] }], learned: [...] }, low: { items: [{ student, text }], ink: 数 } }`
    - `students`: 画面が今持っている、並び順つきの対象の生徒（グラフと同じ人たち）。`records`: `listRecords` の結果。`terms`: 授業の重要用語の文字の配列（今ある `lessonTerms` の結果から作る）。
    - 形のおかしい入力（`null`、配列でない、文字でない欄）は、空として扱い、例外を出さない。
  - `summaryText(summary, labelOf) → 文字`（コピー用。`labelOf(生徒)` は呼び名を返す）

## 見た目（`css/app.css`）

今あるカード・表・ボタンの見た目に合わせる。ボタンは 44px 以上。表は、幅が足りないとき横に動かせる（今ある `.table-scroll`）。縦向き（幅 820px）でも、はみ出さない。文は `textContent` で出し、長い文は折り返す（`overflow-wrap: anywhere`、`white-space: pre-wrap`）。

## 端の場合

- 不正な入力: 記録の欄が文字でない・とても長い（2000 文字）・空白だけ → 空として扱う、または今ある `normalizeRecord` の結果をそのまま使う。重要用語が 0 個 → 3 を出さない。用語が正規表現の記号（`(`、`*` など）を含んでも、文字として探す（正規表現に入れない）。理解度が無い・範囲外 → 5 に入れない。
- 重複と境界: 同じ用語が 2 つあっても 1 行（今ある用語の重複の決まりに合わせる）。ちょうど 2 人の言葉は出る・1 人だけの言葉は出ない。11 個目からは出さない。生徒が 0 人のクラス → 「まだ記録がありません。」。名簿にいない生徒の記録も数える（グラフと同じ）。漢字 1 文字・カタカナ 2 文字は言葉にしない。
- 違反や失敗の見せ方: まとめは通信をしないので、通信の失敗は無い。記録の読みこみに失敗したときは、今ある失敗の出し方のままで、まとめのカードは出さない。コピーの失敗は、今ある「全員分をコピー」と同じ文。
