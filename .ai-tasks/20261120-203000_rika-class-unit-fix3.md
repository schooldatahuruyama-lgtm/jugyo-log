# 実装指示書（修正 3）: クラスの単元 — 単元を読みこめていない間は、窓の「決める」を止める

あなた（Codex）は、この指示書に沿ってコードを直します。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。もとの指示書は `.ai-tasks/20261120-190000_rika-class-unit.md`、レビューは `.ai-review/20261120-184644_round1.md`。

## 目的

レビュー（サイクル 2・round 1）の指摘（High）に対応する。クラスの一覧の読みこみ直しの途中に単元の窓を開き、そのあと `listClassUnits()` が失敗すると、窓は開いたまま、手元の単元の一覧が空になる。この状態で「決めない」を選んで「決める」を押すと、「今と同じ」と見なして書きこまずに窓を閉じ、保存してある単元が残る。

## 変える内容（`js/views/teacher-classes.js`）

- 「単元を読みこめている」（`classUnitsReady` など、今ある印）と「決めていない」を分ける。
- 窓の「決める」を押した時点で、単元を読みこめていない（読みこみ中・読みこみ失敗）ときは、書きこまず、窓も閉じず、窓の中に「理科クエストの単元を読みこめていません。この窓をとじて、「もう一度」を押してください。」（今ある窓の中の赤い文の出し方）を出す。「同じ値なら書かない」の判定は、読みこめているときだけ行う。
- 読みこみ直しが失敗したときに、前に読めていた一覧を空にしてもよいが、そのときは必ず「読みこめていない」の状態にする（各行の単元の表示とボタンを出さない、は今のまま）。
- 「単元を決める」ボタンは、読みこめていない間は出さない・押せない（今のまま）。すでに開いている窓は、勝手に閉じない。

## 端の場合

- 不正な入力: 変えない。
- 重複と境界: 読みこみ直しの途中に窓を開く → 読みこみ成功 →「決める」: 新しい値と比べて、ふつうに動く。読みこみ失敗 →「決める」: 赤い文、書かない、閉じない。「やめる」で閉じられる。そのあと「もう一度」で読めたら、ふつうに決められる。
- 違反や失敗の見せ方: 窓の中の赤い文（`role="alert"`）。

## テスト（`tests/class-unit-screen.test.js`）

- 「読みこみ直しを始める（返事を止める）→ 窓を開く → `listClassUnits` が失敗 →『決めない』を選んで『決める』」: `setClassUnit` が呼ばれず、窓が閉じず、赤い文が出る。
- そのあと「やめる」→「もう一度」で読みこめる → 窓を開いて「決めない」→ `setClassUnit(…, null)` が呼ばれる。
- 読みこみ直しの途中に窓を開く → 読みこみ成功（値が変わっている）→ 新しい値と同じものを選ぶと書かない、ちがうものを選ぶと書く。
- `npm test` がすべて成功すること。
