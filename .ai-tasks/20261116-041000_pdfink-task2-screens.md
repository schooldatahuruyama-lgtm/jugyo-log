あなた（Codex）は、この指示書に沿ってコードを書きます。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

Task 1（`.ai-tasks/20261116-040000_pdfink-task1-data.md`。実装済み）のデータの形を使い、**PDF を大きく開いた画面で、ページの上に書きこめる**ようにする。対象は、先生の資料の PDF と、生徒が自分で足した PDF。写真への書きこみ（`.ai-tasks/20261116-021000_picink-task2-screens.md`、`…030000_picink-task3-fixes.md`、`…033000_picink-fix1-review.md`）と同じ動き・同じ文を使い、ちがう所だけ下に書く。

## 画面の動き（Claude Code の設計。先生に伝えてある）

### 生徒: PDF を大きく開いた画面（`js/views/parts/viewer.js`）

- 書きこみが使える PDF では、操作の並び（前のページ・ページ数・次のページ）のとなりに「✎ 書きこむ」を出す。押したときの道具・文・保存の状態の出し方は、写真と同じ（保存の文の場所は、はじめから 1 行ぶん取っておく。押してあるときは塗り）。
- 線は、今出しているページ（canvas）の上に、同じ大きさの SVG をぴったり重ねる。手書きの形は `emptyPictureInk(canvas.width, canvas.height)`（Task 1。ページの縦横の比）。
- **ページごとに別の書きこみ**。場所の名前は `inkPagePlace(<置き場所 または 資料の ID>, ページ番号)`、`on` は PDF のファイル ID。
- ページをめくったとき:
  - 「✎ 書きこむ」を押してあるかどうかと、選んだ道具（動かす／書く・色・太さ・定規・消しゴム）は、**引きつぐ**。「1 つ戻す」の履歴はページごと。
  - めくる前のページに、まだ送っていない書きこみがあれば、すぐ送り始める（`flush`。待たない）。
  - めくった先のページに目録（`on` が同じ）か下書きがあるときだけ、そのページの書きこみを読みこむ（「書きこみを読みこんでいます…」）。無ければ、通信せずに空で始める。一度読んだページは、開いている間・授業ページにいる間は、読み直さない（保存の部品をページごとに持ち続ける）。
  - ページの絵の読みこみ中（今ある「読みこんでいます…」）は、書けない。
- 文は写真と同じ。ただし「写真」と言っている文は、PDF では言いかえる: 「この PDF は、もうありません。書きこみは保存されませんでした。」、全部消すの確かめ「このページへの書きこみを全部消します。「1 つ戻す」で戻せます。」。読みこみの失敗・「新しく書く」・ほかの端末のほうが新しい、は同じ文（そのページだけに効く）。
- 上限は、ページごとに、欄の手書きと同じ値。
- PDF の拡大・縮小は足さない（今の表示のまま）。「動かす」のとき、指で上下・左右に動かせること。
- 閉じるとき: 開いていたページの、まだ送っていない書きこみを送り始める（写真と同じ）。

### 生徒: 授業ページ（`js/views/parts/material-pane.js`・`js/views/parts/attachment-pane.js`・`js/views/student-lesson.js`）

- どこかのページに書きこみ（目録で `on` が同じ、または下書き）がある PDF に、「✎ 書きこみあり」の印（`hasPageInk` と下書き）。書いた・消したら、開き直さなくても変わる。
- 自分の PDF を消すときの確かめ: 書きこみがあるときは「この PDF への書きこみも消えます。」を足す。消すときの順番（送るのを止める → 消せたら片付ける → 失敗したら元にもどす）は、写真の修正 1（`.ai-tasks/20261116-033000_picink-fix1-review.md`）と同じ。全ページの保存の部品・下書きに行う。
- 見出しの保存の状態・「もう一度」・離れるときの確かめ・戻ったときの読み直しに、PDF のページの書きこみも入れる（写真と同じ入れ方）。

### 先生: 1 人の記録（`js/views/teacher-record.js`）

- 同じ印。PDF を開くと、ページごとに書きこみが重なって見える（道具・「✎ 書きこむ」は出さない）。読みこめないときの文と「もう一度」は、写真と同じ（先生の「もう一度」は、記録を読み直してから、今の目録を読む）。
- 先生のほかの画面は変えない。

## 作り方

- 写真のために作った部品（`js/views/parts/picture-ink.js`、`ink-field.js`、`ink-pad.js`、`viewer.js` の重ね方）を広げる。保存の決まりを二重に書かない。
- 保存の部品は、**ページ 1 枚につき 1 つ**。はじめてそのページを出したとき（または下書きが見つかったとき）に作り、`material-pane`・`attachment-pane` が持ち続け、`destroy` で片付ける。1 つの PDF で作る数に上限は付けない（開いたページの分だけ）。
- 道具の選び方を引きつぐために、`ink-pad` に、今の道具の状態を取り出す・入れる口を足してよい。
- 一覧（`js/views/student-home.js`）の送り直し・知らせは、Task 1 でページの場所を受けつけるので、動くはず。動かなければ直す。
- 画面に出す文字は `textContent`。見た目は、写真のときの見た目に合わせる。

## 端の場合

- 不正な入力: ページの大きさが読めない（0 など）ときは、そのページでは書きこみを出さない（PDF の表示は今のまま）。ページ番号が 999 より大きい PDF では、1000 ページ目からは「✎ 書きこむ」を押せない（文は出さなくてよい。印と表示は今のまま）。記録に、知らない場所・`on` の合わない目録があっても、無いものとして扱う。
- 重複と境界: ページを速く続けてめくっても、前のページの線が、ちがうページに重ならない（今ある `generation` の考え方で守る）。めくっている途中に届いた読みこみの結果は、今のページがそのページのときだけ出す。1 ページだけの PDF でも動く。同じページへ戻ったら、書いた線・履歴・保存待ちを引きつぐ。線が 0 本になったページは、目録を消す。全ページが 0 本になったら、印を消す。
- 違反や失敗の見せ方: 写真と同じ場所（大きな表示の中）に、同じ文で出す。送れていない書きこみは、今ある一覧の知らせ・タイルの印・ログアウトの確かめに出る。

## テスト・確かめ

- 計算に切り出せる所はテストを足す。写真のときの画面のテスト（`tests/picture-ink-screen.test.js`、`tests/helpers/picture-dom.js`）の書き方で、PDF の分を足す。
- `npm test` がすべて成功し、変えた `.js` は `node --check` が通ること。
- 代役で、次を確かめて報告に書く。確かめられなかったものは、そう書く。
  1. 自分の PDF（2 ページ以上）を開く →「✎ 書きこむ」→ 1 ページ目に書く → 2 ページ目へ（道具が引きつがれる）→ 書く → 保存される → 閉じる → 印 → 開き直すと、ページごとに線が出る。
  2. 先生の資料の PDF でも同じ。
  3. 書きこみのある PDF を消す → 全ページの目録が消える。消すのに失敗したら、下書きが残る。
  4. 先生の 1 人の記録で、印が出て、ページごとに線が見え、道具が無い。
  5. ページを速くめくっても、線がちがうページに出ない。
  6. 写真への書きこみと、欄の手書きが、今までどおり動く。
