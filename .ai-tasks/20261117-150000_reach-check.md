# 実装指示書: 接続確認ページに「どこに届くか」の確認を足す

あなた（Codex）は、この指示書に沿ってコードを書きます。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

学校の iPad・学校の回線で接続確認ページ（`check.html`）を試したところ、Firebase には届くが、保存の仕組み（Google Apps Script）には届かなかった（2026-11-17。`docs/reports/stage1b-2-check.md` の最後）。

保存の仕組みをどうするかを先生が決める前に、**学校の回線から、どの行き先に届くか**を調べたい。先生の決定（2026-11-17）: 接続確認ページに、この確認を足す。

- 生徒のデータ・ログインの情報は、何も送らない。届くかどうかを見るだけ。
- 規則・GAS・アプリ本体は変えない。

## 画面の動き（Claude Code の設計。先生に伝えてある）

`check.html` の、今ある確認の結果の下（「端末の情報」の上）に、節「どこに届くか」を足す。

- 説明: 「保存の仕組みを選ぶために、この回線から、いくつかの行き先に届くかを調べます。何も保存せず、データも送りません。30 秒ほどかかります。」
- ボタン「どこに届くかを調べる」。調べている間は押せない。終わったら「もう一度調べる」。
- 結果の表（行き先ごとに 1 行）: 「行き先の名前」「アドレス（ホスト名）」「結果」。結果は「○ 届きました」「× 届きませんでした」「△ 返事がありませんでした（10 秒）」。調べる前は「－ まだ調べていません」。
- 全部終わったら、表の下に 1 行: 「○ N 個・× M 個・△ K 個でした。」
- ボタン「結果をコピー」（今ある「結果をコピー」と同じ出し方・同じ知らせ）。コピーする文は、日時、行き先ごとの「○／×／△ 名前（ホスト名）」、ブラウザ（今ある端末の情報と同じ文）、今ある「確認している場所」（学校・家・そのほか）。
- 今ある 1〜11 番の確認とは別に動く（どちらを先に押してもよい。同時に動かしても壊れない）。

## 調べ方（新しい `js/reach-check.js`。DOM を使わない）

- 1 つの行き先につき、`fetch(url, { method: 'GET', mode: 'no-cors', redirect: 'manual', cache: 'no-store', credentials: 'omit', referrerPolicy: 'no-referrer' })` を 1 回。
  - 約束が果たされた（中身の見えない返事・リダイレクトでもよい）→ 「届きました」。
  - 約束が破られた（`TypeError` など）→ 「届きませんでした」。
  - 10 秒たっても決まらない → `AbortController` で止めて「返事がありませんでした」。
- 4 つずつ同時に調べる（一度に全部は送らない）。結果は、決まった順に 1 行ずつ画面に出す。
- 返事の中身は読まない・保存しない。URL に、付け足しの文字（クエリ）を付けない。
- 主な関数（名前と形。中は任せる）:
  - `checkReach(target, { fetch, timeoutMs, setTimeout, clearTimeout, AbortController }) → Promise<'ok' | 'blocked' | 'timeout'>`
  - `runReach(targets, { onResult, limit = 4, ...上と同じ }) → Promise<結果の配列>`
  - `reachText({ results, when, place, browser }) → 文字`（コピー用）
- 先生のメールアドレス・トークン・生徒の ID は、どこにも入れない。

## 端の場合

- 不正な入力: 行き先の一覧が空・配列でない → 何も調べず、「調べる行き先がありません。」。アドレスが `https://` で始まらない行き先は、調べずに「× 届きませんでした」ではなく、一覧を作るときに `TypeError`（テストで守る）。設定からプロジェクト ID・データベースの URL が取れないときは、その行き先を一覧から外す。
- 重複と境界: ボタンを続けて押しても、調べるのは 1 回（調べている間は押せない）。「もう一度調べる」で、表を「まだ調べていません」にもどしてから始める。ちょうど 10 秒で返事が来たときは、先に決まったほう。ページを離れたら、残りは止める。
- 違反や失敗の見せ方: 行き先ごとに ○・×・△ を出す。文は上のとおり。調べる途中で例外が出ても、ほかの行き先は続ける。コピーの失敗は、今ある「結果をコピー」と同じ文。
