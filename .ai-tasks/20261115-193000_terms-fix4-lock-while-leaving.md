# 実装指示書: 重要用語の修正 4（離れるかを確かめている間は、用語の操作を止める）

あなた（Codex）は、この指示書に沿ってコードを直します。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

Codex レビュー `.ai-review/20261114-225613_round1.md` の指摘 1（Medium）を直す。

離れるときの確かめ（文字の保存を待つ・ダイアログを出す）の間に、生徒が用語を足す・外すと、その成否を取りこぼす道が残る。待ち方を足していくのではなく、**確かめの間は、用語の操作そのものを始められなくする**（Claude Code の判断）。そうすれば、確かめの最初に 1 回、進んでいる通信の終わりを待つだけで足りる。

## 変えるファイル

`js/views/parts/term-row.js`、`js/views/student-lesson.js`、`js/views/teacher-lesson.js`。ほかのファイルは変えない。

- `termRow` の戻り値に `setLocked(locked: boolean) → void` を足す。`true` の間は、部品の中の入力欄・「＋ 足す」・用語の「×」を押せなくする（`disabled`）。Enter でも足せない。`false` で元に戻す（今ある「1 つずつ」の決まり・8 個の上限などは、そのまま働く）。進んでいる通信は止めない。
- `js/views/student-lesson.js` の、離れるときの確かめ:
  1. 最初に `terms.setLocked(true)`。
  2. `await terms.settle()`。`false`（用語の保存に失敗）なら、`terms.setLocked(false)` して、離れない。
  3. 今までの確かめ（文字の保存・添付）。
  4. 離れない（`false` を返す）ときは、必ず `terms.setLocked(false)` で元に戻す（例外で終わるときも。`finally`）。離れるとき（`true` を返す）は、止めたままでよい。
  - 前の修正で足した「最後にもう一度 `settle()` を待つ」くり返しは、いらなくなるので外してよい（残しても害は無いが、止めている間は新しい通信が始まらない）。
- `js/views/teacher-lesson.js`: 先生の用語の欄も同じ考え方にする。離れるときの確かめの間は、用語の足す・外すを始められなくし、進んでいる通信の終わりを最初に待ち、失敗したら離れない。離れないときは、元に戻す。

## 端の場合

- 不正な入力: 変えない。
- 重複と境界: 確かめを続けて 2 回始めても（今ある leave guard は 2 回目を断る）、止めた状態が残らない。確かめのダイアログで「ここに残る」を選ぶと、用語の操作がまた使える。通信が無いときは、今までと同じ速さで離れる。
- 違反や失敗の見せ方: 用語の保存に失敗したら、画面に残り、部品の中の失敗の文を出す（今のまま）。止めている間、入力欄とボタンは薄くなる（`disabled` の見た目）。

## 確かめ

- テストのファイルは足さない。`npm test` がすべて成功し、変えた `.js` は `node --check` が通ること。
- 代役の `ctx` を使った手元の実行で、次を確かめて報告に書く: (1) 文字の保存を止めておく →「一覧へ」→ この間、用語の入力欄・ボタンが `disabled`。(2) 確かめで離れないことになったあと、用語の操作がまた使える。(3) 用語の通信の途中で「一覧へ」→ 通信が失敗 → 画面に残り、失敗の文が出て、操作がまた使える。
