# 実装指示書: 段階 1a-4 Task 2 の修正 1（記録の画面で、読み直しのあともハッシュを表示に合わせる）

あなた（Codex）は、この指示書に沿ってコードを直します。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

Codex レビュー `.ai-review/20261114-120300_round1.md` の指摘 1（Medium）を直す。

`js/views/teacher-review.js` で、クラス A の記録からクラス B へ切りかえている途中に通信が失敗し、上の「読み直す」で読み直すと、B の記録が出てもハッシュ（URL）は A のままになる。ページを開き直すと、見ていた B ではなく A に戻ってしまう。

## 変えるファイル

`js/views/teacher-review.js` だけ。

- クラス・授業を切りかえるときの「移る先」を覚えておき、失敗のあと「読み直す」「もう一度ためす」のどちらで読み直しても、読みこめたら、ハッシュを画面に出しているクラス・授業に合わせる（`ctx.navigate('t-review', { classId, lessonId })` または今ある同じ仕組み）。
- すでにハッシュが合っているときは、余計に移らない（履歴を増やさない）。
- ほかの動きは変えない。

## 端の場合

- 不正な入力: 切りかえ先のクラス・授業が見つからなくなっていたら、今までどおり「この授業は見つかりません。」を出し、選択は使える。
- 重複と境界: 「読み直す」を続けて押しても、通信は今ある仕組みで 1 つにまとめる（古い結果は捨てる）。失敗が 2 回続いても、3 回目の成功でハッシュが合う。
- 違反や失敗の見せ方: 読めないときは、今までどおり「つながりません。もう一度ためしてください。」と「もう一度ためす」。

## 確かめ

- テストのファイルは足さない（画面のため）。`npm test` がすべて成功し、`node --check js/views/teacher-review.js` が通ること。
- 直した流れ（A → B の切りかえで失敗 →「読み直す」→ 成功）で、最後のハッシュが B になることを、代役の `ctx` を使った手元の実行で確かめ、結果を報告に書く。
