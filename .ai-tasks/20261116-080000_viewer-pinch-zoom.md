# 実装指示書: 写真・PDF の大きな表示を、指 2 本で拡大・縮小する

あなた（Codex）は、この指示書に沿ってコードを書きます。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

先生の要望（2026-11-15）: 写真や PDF を拡大するとき、ボタンでは使いにくい。**指 2 本を開く・閉じる操作（ピンチ）で拡大・縮小できるようにする。**

今の作り（`js/views/parts/viewer.js`）: 写真は「－」「100%」「＋」のボタンで 100〜400%（0.25 きざみ）。PDF は拡大なし（幅に合わせる）。指 1 本はブラウザのスクロール。書きこみ中（「✎ 書きこむ」→「書く」）は、紙の上の触れた動きを止めている（`js/views/parts/ink-pad.js` の `preventTouchScroll`）。

## 画面の動き（Claude Code の設計。先生に伝えてある）

### 拡大・縮小

- 写真と PDF のどちらも、表示の枠（`.viewer-viewport`）の上で指 2 本を開く・閉じると、100〜400% の間でなめらかに拡大・縮小する。**2 本の指のまん中の場所が、指の下からずれない**ようにスクロール位置を合わせる。2 本の指を一緒に動かすと、表示も動く（2 本指の移動）。
- 100% は、今と同じ「画面に合う大きさ」（写真: 枠に収まる大きさ。PDF: 枠の幅に合う大きさ）。
- PDF にも拡大を足す。操作の並びは「前のページ・ページ数・次のページ・－・％・＋・✎ 書きこむ」。写真は今のまま。ボタンは今と同じ 0.25 きざみ（PC やマウスの人のために残す）。ピンチで半端な倍率（たとえば 137%）になったあとのボタンは、そこから ±0.25（100〜400 に収める）。
- ％の文字は、ピンチの間も今の倍率に変わる。
- PDF は、ページをめくったら 100% にもどす（今と同じく、上の端から出す）。
- PC では、`Ctrl`（Mac は `⌘` も）を押しながらホイールを回すと、ポインタの場所を中心に拡大・縮小する（トラックパッドのピンチも、これで動く）。ブラウザのページ全体の拡大は起こさない（`preventDefault`）。
- 表示の枠の上では、ブラウザのページ全体のピンチ拡大を起こさない（`.viewer-viewport` の `touch-action` から `pinch-zoom` を外す。iPad の Safari の `gesturestart`・`gesturechange` も `preventDefault`）。

### 書きこみとの関係

- 「動かす」: 指 1 本はスクロール（今のまま）。指 2 本はピンチ。ペンは書ける（今のまま）。
- 「書く」: 指 1 本は書く（今のまま）。**2 本目の指が触れたら、1 本目で書きかけていた線は取り消し（保存しない・「1 つ戻す」にも入れない）、ピンチと 2 本指の移動にする。** 指が全部離れるまで、指では書かない。離れたら、また書ける。
- ペンで書いている途中（今ある `penPointer`・`penUntil` の間）は、指 2 本が触れてもピンチにしない（手のひら・指の置きまちがいで動かさない）。
- 読みこみ中（`busy`）は、ピンチしない。
- 先生の見るだけの表示（書きこみを重ねて見る・授業の編集）でも、ピンチできる。

### PDF をくっきり出す

- PDF は、今は長辺 1600 で描いている。拡大すると字がぼやけるので、**倍率が 150% を超えた状態で 0.3 秒止まったら、今のページを長辺 3200 で描き直して、入れかえる**（1 ページにつき 1 回。もう 3200 で描いてあるページは描き直さない）。
- 入れかえても、倍率・スクロール位置・書きこみ（重ねた線、道具、保存の状態）は変えない。描き直しの間も、見る・書く・めくるは止めない。文は出さない。
- 描き直しに失敗したら、今の絵のまま（文は出さない）。描き直しの途中でページをめくった・閉じたら、その結果は捨てる（今ある `generation` の考え方）。
- 書きこみの形（`emptyPictureInk` の縦横の比）は、はじめの canvas で決めたまま変えない。

## 作り方

- 倍率の計算（指の間の長さの比 → 新しい倍率、まん中を保つスクロール位置、ボタンの次の倍率、範囲に収める）は、新しい `js/zoom-logic.js` に、DOM を使わない関数として切り出す。
- ピンチは touch の出来事（`touchstart`・`touchmove`・`touchend`・`touchcancel`。`{ passive: false }`）で扱う。2 本以上が枠の上にあるとき `preventDefault` する。pointer の出来事は使わない（ブラウザのスクロールに取られると `pointercancel` になるため）。
- `ink-pad` に、ピンチの間は指の線を止める口を足す（たとえば `setGesture(true|false)`: `true` で、書きかけの線を取り消し、指の `pointerdown` を受けつけない。ペンは今のまま）。`picture-ink` の部品を通して、`viewer` から呼ぶ。
- 拡大したときの大きさの決め方は、写真・PDF とも「100% の大きさ × 倍率」を枠（`pictureFrame`）と絵の幅・高さに入れる今のやり方に合わせる。重ねた線（SVG）が、どの倍率でも絵とずれないこと。
- 画面の向きを変えた・窓の大きさを変えたとき（今ある `resize`）も、倍率を保って合わせ直す。

## 端の場合

- 不正な入力: 2 本の指の間の長さが 0・数でないときは、その動きを無視する。倍率は、どんな値が来ても 100〜400% に収める（`NaN` は今の倍率のまま）。絵の大きさが読めない（0）ときは、拡大しない。`touches` が無い端末・テストの代役でも、例外を出さない。
- 重複と境界: 100% でさらに閉じても 100% のまま。400% でさらに開いても 400% のまま。3 本以上の指は、はじめの 2 本だけを使う。2 本のうち 1 本を離したら、ピンチを終える（残った 1 本では、離すまで書かない・スクロールは今のブラウザの動きのまま）。ピンチの途中で「✎ 書きこむ」やページのボタンが押されることはない（指が枠の上にあるので）が、押されても壊れないこと。ちょうど 150% では描き直さない（超えたとき）。長辺 3200 で描いた canvas が作れない端末（失敗）では、1600 のまま。
- 違反や失敗の見せ方: 文は足さない。範囲の端では、それ以上動かないだけ。「－」「＋」は、今と同じく端で押せなくなる。

## テスト・確かめ

- `tests/zoom-logic.test.js`（新しい）: 倍率の計算（比、範囲、`NaN`・0）、まん中を保つスクロール位置、ボタンの次の倍率（半端な倍率から）。
- 今ある画面のテスト（`tests/picture-ink-screen.test.js`・`tests/pdf-ink-screen.test.js`、代役は `tests/helpers/picture-dom.js`）の書き方で足す:
  - 2 本の指を開く → 倍率が上がり、％の文字が変わり、`defaultPrevented` になる。閉じる → 下がる。100% より下・400% より上にならない。
  - 「書く」で 1 本で書きかけ → 2 本目 → 線が取り消され、線の数が増えない・保存が走らない。指を全部離したあと、また書ける。
  - ペンで書いている間は、指 2 本でも倍率が変わらない。
  - PDF: 「＋」で拡大できる。めくると 100% にもどる。150% を超えて 0.3 秒 → 長辺 3200 で 1 回だけ描き直す。描き直しの途中でめくる → 結果を捨てる。描き直しが失敗 → 今の絵のまま。
  - `Ctrl` ＋ホイール → 倍率が変わり、`defaultPrevented`。`Ctrl` なしのホイール → 変わらない。
- `npm test` がすべて成功し、変えた `.js` は `node --check` が通ること。
