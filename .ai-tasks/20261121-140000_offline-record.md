# 実装指示書: オフラインでの記録（段階 4 以降）

あなた（Codex）は、この指示書に沿ってコードを書きます。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

要件定義書 `docs/requirements.md` の「オフラインでの記録」（ネットにつながっていないときもメモ・振り返りを残し、再接続時に反映する）と、設計書 `docs/superpowers/specs/2026-11-12-jugyo-log-design.md` の「4 以降: オフラインでの記録」。

今あるもの: 授業のページを開いている間に電波が切れても、文字の記録は下書き（`js/drafts.js`）に残り、つながったら送る（`js/record-saver.js`・`js/record-flow.js`）。
足りないもの: (1) 電波がないと、アプリのファイルが読めず、開けない。(2) 電波がないと、ログインを確かめられず「つながりません」で止まる。(3) 電波がないと、授業の一覧も授業も読めない。

この 3 つを足す。**書きこみ（保存）の仕組みは変えない**。読む方だけ、前に読んだ内容を iPad に取り置いて、電波がないときに使う。対象は生徒だけ（先生の画面は今までどおり）。規則（`docs/setup/rules.json`）と GAS は変えない。

## 利用者から見える動き（決定ずみ。変えない）

| 項目 | 動き |
|---|---|
| アプリを開く | 一度開いた iPad では、電波がなくても開く |
| ログイン | 電波がなくても、前に確かめた生徒のまま入れる。先生は今までどおり「つながりません」 |
| 見られるもの | 前に読みこんだ内容（一覧、開いたことのある授業、新しい方から 5 つの授業） |
| 書けるもの | メモ・理解度・分かったこと・疑問（文字）。今の下書きの仕組みで残り、つながったら送る |
| 書けないもの | 写真・PDF の追加、手書きの保存、用語の追加など（今の「保存できませんでした」の出し方のまま） |
| 印 | 取り置きの内容を出している間は、画面の上に帯を出す |
| まだ入っていない授業 | 開かずに、文を出す |
| ログアウト | 取り置きを全部消す |

## 作る・変えるファイル

### 1. `sw.js`（新しい。フォルダの直下。Service Worker）

- ふつうのスクリプト（`import` を使わない。iPad の Safari で確実に動かすため）。1 つのファイルで完結させる。
- 定数: キャッシュ名 `jugyolog-app-v1`、一覧 `app-files.json`、待ち時間 5000 ミリ秒。
- `install`: `app-files.json` を `cache: 'no-store'` で取る（形は `{ "version": "abc1234", "files": ["index.html", "css/base.css", …] }`）。取れたら、`files` を 1 つずつ `cache: 'no-cache'`（変わっていなければ 304 で軽くすむ）で取り、成功（status 200）したものをキャッシュに入れる。一覧が取れない・形がちがう・個々のファイルが取れない、のどれでも **install は成功させる**（取れた分だけ入れる）。最後に `skipWaiting()`。
- `activate`: `clients.claim()`。install で一覧が取れていたときだけ、キャッシュの中の、一覧に無いものを消す。
- `fetch`: 次の全部に当てはまるときだけ `respondWith` する。それ以外は何もしない（ブラウザにまかせる）。
  - `GET`、ページと同じ origin、この Service Worker の scope の中。
  - `request.cache` が `'no-store'` でない（`version.txt` の確認をじゃましない）。
  - パスの最後が `app-files.json`・`version.txt`・`sw.js` でない。
- 返し方（ネットを先に見る）:
  - ネットに取りに行く。成功（status 200・`type` が `basic`）なら、写しをキャッシュに入れて、返す。200 以外はそのまま返し、キャッシュに入れない。
  - ネットが失敗したら、キャッシュにあればそれを返す。なければ失敗のまま。
  - 5000 ミリ秒たっても返事がなく、キャッシュにあれば、キャッシュを返す（ネットの方は続け、成功したらキャッシュを新しくする）。
  - キャッシュをさがすときは `ignoreSearch: true`。ページを開く要求（`request.mode === 'navigate'`）で見つからないときは `index.html` をさがす。
- 生徒のデータ・Firebase・GAS・中つぎへの通信には、さわらない（origin がちがうので、上の条件で外れる）。

### 2. `js/sw-register.js`（新しい）

- `export function shouldRegister({ hostname, search, hasWorker })`: `hasWorker` が偽なら false。`localhost`・`127.0.0.1`・`[::1]` では、`search` に `sw=1` があるときだけ true。それ以外の場所は true。
- `export function workerUrl(version)`: `` `sw.js?v=${encodeURIComponent(version)}` ``（版が変わるたびに install をやり直させるため）。
- `js/main.js` の `start()` の最後で、`shouldRegister` が true なら `navigator.serviceWorker.register(workerUrl(VERSION))` を呼ぶ。失敗しても何も出さず、アプリは続ける。

### 3. `js/offline-store.js`（新しい。読んだデータの取り置き）

- `export function createOfflineStore({ caches, name = 'jugyolog-data-v1' })`。`js/file-cache.js` と同じ作り方（Cache API。使えなければ、このページのメモリで続ける。処理は順番に行う）。
- キー: `https://data.jugyolog.invalid/<encodeURIComponent(scope)>/<encodeURIComponent(key)>`。
- `get(scope, key)` → `{ value }`（取り置きがある。`value` は null のこともある）または `null`（無い・こわれている）。
- `put(scope, key, value)`: `JSON.stringify({ v: value })` を入れる。失敗（容量など）は投げない。
- `removeWhere(scope, test)`: その scope のキーのうち、`test(key)` が真のものを消す。
- `clear()`: 全部消す（全 scope）。

### 4. `js/offline-net.js`（新しい。`net` を包む）

- `export function createOfflineNet({ net, store, scope })`。`scope()` は、今の生徒の uid（生徒でなければ null）を返す関数。戻り値は `net` と同じ形（`get`・`getPublic`・`set`・`update`・`remove`・`serverTimestamp`）に、`stale`（読み取り専用）と `onChange(listener)`（戻り値は外す関数）を足したもの。
- `get(path, opts)`:
  - `scope()` が null: そのまま `net.get`（取り置きを読まない・書かない）。
  - ネットで成功: `store.put(scope, キー, 値)` して返す。キーは、`shallow` が真なら `` `${path}?shallow` ``、偽なら `path`。`stale` を false にする。
  - ネットが `NetError` の `code === 'network'` で失敗: 取り置きがあれば、その値を返し、`stale` を true にする。なければ、もとのエラーを投げる。
  - それ以外の失敗（`denied`・`auth`・`unknown` など）: 取り置きを使わず、そのまま投げる。
  - ネットを待つ間に scope が変わっていたら（ログアウトなど）、取り置きに書かない・取り置きから返さない（scope は呼んだ時点の値を使い、終わったときに同じかを確かめる）。
- `set`・`update`・`remove`: そのまま `net` に渡す（**ためない。失敗はそのまま投げる**）。成功したら、`stale` を false にし、scope があれば、書いた場所にかかる取り置きを消す。
  - 書いた場所: `set`・`remove` は `path`。`update` は、`patch` のキーごとに `path` とキーを `/` でつないだもの（`path` が `''` ならキーそのもの）。
  - 消す取り置き: キー（`?shallow` を外したもの）が、書いた場所と同じ・書いた場所の下・書いた場所の上、のどれか。例: `records/c1/l1/s1` に書いたら、`records/c1/l1/s1` と `records/c1/l1/s1/ink` と `records/c1` を消す。`records/c1/l10/s1` は消さない（`/` で区切って比べる）。
- `getPublic`: そのまま渡す。
- `stale` が変わったときだけ、`onChange` の相手を呼ぶ。相手が投げても、通信の結果は変えない。

### 5. `js/session-memo.js`（新しい）と `js/session.js`

- `export function createSessionMemo({ storage, key = 'jugyolog:session' })`: `get()` → `{ uid, studentId }` または null（無い・こわれている・`uid` が空でない文字列でない・`studentId` が `isStudentId` でない）。`put({ uid, studentId })`、`clear()`。`storage` が使えなくても投げない。
- `resolveSession({ auth, repo, memo = null })` を変える:
  - 生徒と確かめられたら `memo?.put({ uid, studentId })`。先生・だれでもない（`none`）と確かめられたら `memo?.clear()`。
  - 今 `{ role: 'offline' }` を返している 2 か所: `memo?.get()` があり、`auth.user` があり、`auth.user.uid === memo.uid` なら、`{ role: 'student', uid, studentId, offline: true }` を返す。そうでなければ今までどおり `{ role: 'offline' }`。
  - 保存してあるのは uid と生徒 ID だけ（名前・メールアドレス・トークンを入れない）。

### 6. `js/main.js`

- `const liveRepo = createRepo(backend.net)`（取り置きを使わない）。`const offlineNet = createOfflineNet({ net: backend.net, store, scope })`、`const repo = createRepo(offlineNet)`。`scope` は、`session?.role === 'student'` のときだけ `session.uid`、ほかは null。`store` は `createOfflineStore`（`caches` は `window.caches`。練習モードでは渡さず、メモリだけ）。
- `resolveSession` には **`liveRepo`** と `memo` を渡す（古い取り置きで、ログインを確かめたことにしない）。
- `ensureSession`: `session.offline` のときは、前に確かめてから `CONFIG.offline.recheckMs` 以上たっていれば、確かめ直す（たっていなければ、今の session のまま）。`window` の `online` のでき事でも、裏で確かめ直す。確かめ直した結果が「同じ uid の生徒」なら、`session` を入れかえるだけで、画面は描き直さない。それ以外（`none`・先生・`offline`）になったら `render()` する（`offline` で `memo` が使えたときは、また `offline: true` の生徒になるので、描き直さない）。
- `ctx` に足す: `liveRepo`、`offline: { get down() { return offlineNet.stale || session?.offline === true; } }`。
- 帯: `bannerRoot` に `div.offline-banner`（`role="status"`）を 1 つだけ出す・消す。出す条件は `ctx.offline.down` と同じ。文: 「電波がありません。前に読みこんだ内容を出しています。メモと振り返りは、この iPad に残り、つながったら送ります。」。`offlineNet.onChange` と、session を入れかえたときに、出し直す。練習モードの帯・新しい版の帯は消さない（`bannerRoot.replaceChildren` を使わない）。
- `signOutAll`: `store.clear()` と `memo.clear()` を足す（失敗してもログアウトする。今の書き方に合わせる）。
- Service Worker の登録（上の 2）。

## 端の場合

- 不正な入力:
  - 取り置きの中身が JSON でない・`v` が無い → 無いものとして扱う（ネットのエラーをそのまま投げる）。
  - `jugyolog:session` がこわれている・`studentId` の形がちがう → 無いものとして扱う（「つながりません」）。
  - `app-files.json` が配列でない・文字列でない要素がある → その要素・一覧を使わない（install は成功）。
  - とても大きい値で取り置きに入らない → 入れないだけ（読んだ値は返す）。
- 重複と境界:
  - 同じ場所を同時に 2 回読む → どちらも成功し、取り置きはあとの方。
  - `memo.uid` と `auth.user.uid` がちがう（別の生徒がログインし直した）→ 電波なしでは入れない（「つながりません」）。
  - 先生のログイン → 取り置きを読まない・書かない。電波なしでは今までどおり「つながりません」。
  - ログアウト → 取り置き・`jugyolog:session`・下書きが全部消える。ログアウトの前に読み始めた通信が、あとから取り置きに書かない。
  - `warmLessons`: 授業が 0 個・`max` より少ない → ある分だけ。`max` が 0・負・数でない → 何もしない。
  - `recheckMs` より短い間かくの画面の移動 → 確かめ直さない。
- 違反や失敗の見せ方:
  - 取り置きを出している間は、上の帯を出す（だまって古い内容を出さない）。ネットで読めたら消す。
  - 取り置きの無い授業は、開かずに上の文を出す。
  - 書きこみの失敗は、今の出し方のまま（「保存できませんでした」「まだ保存できていない記録が ○ 件あります」）。

## 守ること

- `git add`・`git commit` はしない。パッケージを足さない。
- 書きこみを端末にためて、あとで送る仕組みを新しく作らない（今ある下書きだけ）。
- トークン・パスワード・名前・メールアドレスを、取り置きや `jugyolog:session` に入れない。
- 先生の画面（`js/views/teacher-*.js`）・`check.html`・`docs/setup/rules.json`・`gas/`・`relay/` は変えない。
- `js/views/` と `js/main.js` のほかでは、ブラウザのもの（`window`・`caches`・`navigator`）を直接使わない（引数で受け取る）。`sw.js` は別。
- このフォルダの外は読まない・変えない。
