# 実装指示書: 手書き Task 6 — 確かめて見つけた直し

あなた（Codex）は、この指示書に沿ってコードを直します。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

段階 1b-2（手書き）の Task 1〜5 を、Claude Code がブラウザで確かめ、Codex の報告も読んで見つけた点を直す。

## 直すこと

### 1. 一覧の「送れていない」の数と、ログアウトの確かめに、手書きの下書きも入れる（`js/views/student-home.js`）

今は、文字の下書き（`ctx.drafts`）だけを数えている。手書きの下書き（`ctx.inkDrafts`）が残ったままログアウトすると、確かめが出ずに消える。

- 「まだ送れていない記録」の数（今ある知らせ）と、ログアウトの確かめは、**授業の数**で数える: 文字の下書きがある授業と、手書きの下書きがある授業を合わせ、同じ授業は 1 つと数える（`classId`・`lessonId` の組）。
- タイルの「送れていない」の印（今ある `pendingLessons`）も、手書きの下書きがある授業に付ける。
- 文は今のまま（「記録」と言っているので、手書きもふくむ）。

### 2. 一覧からの送り直しでも、小さい画像を作り直す（`js/ink-flow.js`・`js/views/student-home.js`・テスト）

今は、`resendInkDrafts` が `thumb: undefined`（触らない）で送るので、先生の一覧の小さい画像が古いまま・無いままになる。

- `resendInkDrafts({ …, makeThumb })` を足す: `makeThumb(ink) → 文字 | null`。渡されていて、`field` が `CONFIG.inkThumbFields` に入っているときは、`thumb: makeThumb(draft.ink)`（例外は `null` として扱う）。渡されていない・`memo` のときは、今までどおり `undefined`。
- `js/views/student-home.js` は、`makeThumb: inkThumb`（`js/ink-thumb.js`）を渡す。
- `tests/ink-flow.test.js` に足す: `makeThumb` を渡すと、`learned`・`question` ではその値が `setInk` に届く。`memo` では届かない（`undefined`）。`makeThumb` が例外を投げても、保存は進む（`null`）。

### 3. ファイルが見つからない手書きは、書き直せるようにする（`js/views/parts/ink-field.js`）

今は、目録にあるファイルが Drive に無い（`notfound`）と、「手書きを読みこめませんでした。」と「もう一度」がくり返されるだけで、その欄にずっと書けない。

- 読みこみの失敗が `notfound` のとき（`error.code === 'notfound'`）だけ、文を「前に書いた手書きが見つかりませんでした。」にし、「もう一度」のとなりに「新しく書く」を出す。
- 「新しく書く」は、`confirmDialog` で確かめる: 題「新しく書きますか？」、文「前に書いた手書きは、もどせません。空の紙から書き直します。」、OK「新しく書く」、取り消し「やめる」。OK なら、空の紙を出す（この時点では保存しない。線を書くと、ふつうに保存され、目録が新しいファイルに変わる。古いファイルの片付けは `saveInkFlow` がためし、失敗は無視される）。
- 通信の失敗・`bad-data`（中身がこわれている）のときは、今までどおり「もう一度」だけ（こわれた中身を、うっかり上書きさせない）。
- 先生の 1 人の記録（`js/views/teacher-record.js`）は、`notfound` のとき「手書きが見つかりませんでした。」と出す（「新しく書く」は出さない）。

### 4. 「もう一度」が 2 つ出ないか確かめる（`js/views/teacher-record.js`・`js/views/parts/ink-field.js`）

Claude Code の確かめで、手書きの読みこみに 1 つ失敗したとき、失敗の文は 1 つなのに「もう一度」のボタンが 2 つ見つかった（先生の 1 人の記録。生徒の授業ページでも同じに見えた）。1 つの失敗につき、文 1 つ・「もう一度」1 つになるよう直す。2 つあるのが正しい（別々の失敗）場合は、それぞれに文が付くようにする。調べた結果を報告に書く。

### 5. 振り返りの中の道具の色（`css/app.css`）

「振り返り」（緑の枠）の中でも、手書きの道具の並び・紙の線・「＋ 下に書く場所を足す」が、「自分の記録」の色（オレンジ）で出ている。振り返りの枠の中では、`--reflect`・`--reflect-bg` の色にする（先生の 1 人の記録の、振り返りの中の紙も同じ）。

### 6. 公開した版の印のファイルから BOM を外す（`tools/pages-branch.ps1`）

今は、PowerShell のパイプで `git hash-object -w --stdin` に渡しているので、`version.txt` と `js/version.js` の先頭に BOM（EF BB BF）が付き、行の終わりが CRLF になる。動きには影響しないが、外す。

- BOM なし・行の終わり LF の中身で blob を作る。やり方の例: 一時ファイルに `[IO.File]::WriteAllText($path, $text, (New-Object Text.UTF8Encoding($false)))` で書き、`git hash-object -w -- <一時ファイル>` で入れ、一時ファイルを消す（`-LiteralPath` を使う）。`.nojekyll`（空）は、今のままでよい（空であることを確かめる）。
- スクリプトは実行しない（git の状態を変えるため）。読んで確かめたことを報告に書く。

## 端の場合

- 不正な入力: 手書きの下書きの一覧に、形のおかしいものがあっても（`ctx.inkDrafts.list` が落とす）、数に入れない。
- 重複と境界: 同じ授業に、文字の下書きと 3 つの欄の手書きの下書きがあっても、数は 1。「新しく書く」の確かめで「やめる」→ 何も変わらない（文とボタンは残る）。「新しく書く」のあと、何も書かずに離れたら、目録は元のまま（次に開くと、また同じ文が出る）。
- 違反や失敗の見せ方: 送れていない手書きは、一覧の知らせ・タイルの印・ログアウトの確かめで見せる（黙って消さない）。見つからない手書きは、その欄の文とボタンで見せる。

## テスト・確かめ

- `tests/ink-flow.test.js` に、2 のテストを足す。数え方（1）に計算の関数を足したなら、そのテストも足す（`js/record-flow.js` など、今ある置き場所に合わせる）。
- `npm test` がすべて成功し、変えた `.js` は `node --check` が通ること。
- 代役で、次を確かめて報告に書く: (1) 手書きの下書きだけが残っているとき、一覧の知らせ・タイルの印・ログアウトの確かめが出る。(3) `notfound` で「新しく書く」→ 確かめ → 空の紙 → 書くと保存される。通信の失敗では「新しく書く」が出ない。

## 守ること

- 上の 6 つのほかは変えない。文字の記録・添付・重要用語の今の動きは変えない。
- 画面に出す文字は `textContent` で入れる。
