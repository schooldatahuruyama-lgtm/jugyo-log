# 実装指示書（修正 1）: 規則の確認で、先生の本物の記録を書きこみの的にしない

あなた（Codex）は、この指示書に沿ってコードを直します。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

`.ai-tasks/20261119-160000_rika-rules.md` の実装への、Codex レビュー（`.ai-review/20261119-213155_round1.md`）の指摘 #1（High）に対応する。

今は「ほかの人の `rika/state`・`rika/log` に書けないこと」を、**先生の uid** を的にして確かめている。公開されている規則がゆるい（本人かどうかを見ていない）と、先生が理科クエストを使ったときの本物の記録を、確認用の中身で上書きしてしまう。片付けも、確認用の生徒の uid しか消していない。

## 変えるファイルと内容

### `js/rules-probe.js`

- 「ほかの人」の 3 項目（`rika/state` を読む・`rika/state` を書く・`rika/log` に書く）の的を、先生の uid から、**だれも使わない確認専用の uid** に変える。値は定数 `'rules-probe-other-uid'`（Firebase の uid は 28 文字の英数字なので、本物と重ならない）。先生の uid は、理科クエストの項目では使わない。
- 項目の名前も「ほかの人（確認用の uid）の …」に直す。
- 片付け: 確認専用の uid の `rika/state/rules-probe-other-uid` と `rika/log/rules-probe-other-uid` も、先生として消す（今ある `removeRika` を使う）。次のどの場合も消すこと:
  - 書きこみが拒まれた（ふつうの場合。消すものが無くても、消す操作は成功する）
  - 規則がゆるくて、書きこみが通ってしまった
  - 書きこみの返事が届かなかった（通信の失敗）
  - 前回の確認の残りがある（確認の最初の片付けでも消す）
- 片付けに失敗したら、今ある片付けの失敗と同じように「片付け」の行を不合格にする。
- ほかの項目・順番・項目の数（124）は変えない。

### `README.md`

- 「規則の確認」の表の、該当の 3 行の言い方を、新しい項目の名前に合わせる。

## 端の場合

- 不正な入力: なし（的の uid は定数）。
- 重複と境界: 確認を続けて 2 回行っても、確認専用の uid の下に何も残らない。
- 違反や失敗の見せ方: 書きこみが通ってしまったら、その項目は今までどおり × になる。片付けの失敗は「片付け」の行が × になる。

## テスト（`tests/rules-probe.test.js`）

- 理科クエストの項目のどの通信も、先生の uid の `rika/` の下に `set`・`update`・`remove` をしないこと（規則がゆるい偽物でも、先生の `rika/state/<先生の uid>` に前から入れておいた値が、確認のあとも同じであること）。
- 規則がゆるくて「ほかの人」への書きこみが通った場合: その 2 項目が不合格になり、片付けのあと `rika/state/rules-probe-other-uid`・`rika/log/rules-probe-other-uid` が残っていないこと。
- 書きこみの返事が届かなかった場合も、片付けで消えること。
- 片付けの失敗で「片付け」の行が不合格になること。
- `npm test` がすべて成功すること。
