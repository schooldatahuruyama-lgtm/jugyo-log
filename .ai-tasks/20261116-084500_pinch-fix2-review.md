# 実装指示書: ピンチの拡大 修正 2（レビュー round 2 の指摘 1 件）

あなた（Codex）は、この指示書に沿ってコードを直します。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

Codex レビュー `.ai-review/20261115-215554_round2.md` の指摘 1（Medium）を直す。

`js/views/parts/viewer.js` の、くっきり描き直した絵を今の canvas に写す所で、`width`・`height` を変えたあとの `drawImage()` が失敗すると、空白の canvas が残る。「失敗したら、今の絵のまま」になっていない。

## 直すこと

- 写す前に、今の canvas の絵と大きさを控える（控え用の canvas に `drawImage` で写す。控えを作れなかったら、描き直しをやめて今の絵のまま）。
- 大きさを変えたあとの `drawImage()` が失敗したら、大きさを元にもどし、控えから描きもどす。描きもどしも失敗したら、今あるページの読みこみ直し（`showPage(pageNo)` に当たる処理）で出し直す。どちらの場合も、そのページでは、もう描き直しを試さない。
- 成功したら、控えは捨てる。

## 端の場合

- 不正な入力: 控えの canvas の `getContext('2d')` が `null` を返す → 描き直しをやめる（今の絵のまま）。
- 重複と境界: 失敗のあと、同じページで倍率を変えても、描き直しをくり返さない。ページをめくれば、次のページでは試す。
- 違反や失敗の見せ方: 文は足さない。

## テスト

- `tests/pdf-ink-screen.test.js`: 大きさを変えたあとの `drawImage()` が例外 → canvas の大きさが元（1600）にもどり、控えから描きもどされる・そのページで描き直しをくり返さない。控えが作れない → 写さない。
- `npm test` がすべて成功し、変えた `.js` は `node --check` が通る。
