# 実装指示書（修正 1）: 記録の書き出し — PDF を 1 つずつ開いて閉じる

あなた（Codex）は、この指示書に沿ってコードを直します。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。もとの指示書は `.ai-tasks/20261121-100000_record-export.md`。

## 目的

Claude Code の確認で見つけた点を直す。今の `js/export-flow.js` の `gatherLesson` は、1 つの授業の PDF（先生の資料は 12 個まで、自分の添付は 6 個まで）を全部開いてから絵を作り、最後にまとめて閉じる。PDF を 1 つ開くたびに worker が 1 つできるので、iPad では同時に開く数が多すぎて、止まるおそれがある。もとの指示書の「読む順」（ファイル → 手書き）の書き方が原因。読む順の決まりを、下のように変える。

## 変える内容（`js/export-flow.js`）

- **同時に開いている PDF は、いつも 1 つまで**にする。PDF は、1 つごとに「ファイルを読む → 開く → 出すページごとに（そのページの書きこみを読む → 絵を作る）→ 閉じる」を済ませてから、次のファイルへ進む。
- 写真も同じく、1 枚ごとに「（先生の写真は今までどおり `loadImages` でまとめて読んでよい）→ その写真の書きこみを読む → 絵を作る」を済ませる。絵を作り終わった写真の Blob を、あとまで持ち続けない（`jobs` にためない）。
- 出す順（入れ物の中の並び）は変えない: 先生の資料は `materialList` の順、自分の添付は `attachmentList` の順、PDF のページは小さい順。
- GAS を同時に 2 つ以上呼ばない決まり（`readFile` の列）は、そのまま。
- 絵の数の上限（`budget`）の決まりは、そのまま: 残りが 0 なら、ファイルを読まずに `problem: 'budget'` を入れる。PDF の途中で 0 になったら、残りのページは `problem: 'budget'` を 1 つ入れて、その PDF を閉じる（今は、開く前にページ分をまとめて取り置いている。取り置きはやめて、1 枚作るたびに 1 へらす形でよい）。
- 失敗の扱いは、そのまま: 1 つの失敗でほかを止めない。書きこみだけ読めない・重ねられないときは、絵だけ出して `problem: 'ink'`。中止（`signal`）では `AbortError` を投げ、開いている PDF を必ず閉じる。
- 返す入れ物の形は変えない。

## 端の場合

- 不正な入力: 変えない（開けない PDF は `problem: 'pdf'`、ページが 0 の PDF も `problem: 'pdf'`）。
- 重複と境界:
  - PDF が 3 つある授業 → どの時点でも、開いている PDF は 1 つ以下。
  - PDF の 5 ページめで絵の残りが 0 になる → 4 ページ分の絵と `problem: 'budget'` が 1 つ。その PDF は閉じる。次のファイルは読まない。
  - PDF の 2 ページめの絵を作る所で中止 → その PDF が閉じ、`AbortError`。
  - PDF の 1 ページだけ絵を作れない → 今の扱い（そのファイルの `problem` を `'pdf'` にする）のまま。ほかのページの絵は残す。
- 違反や失敗の見せ方: 変えない。

## テスト（`tests/export-flow.test.js`）

- PDF が 3 つの授業で、「開いている PDF の数」の最大が 1 であること（にせ物の `draw.openPdf` で、開く・閉じるを数える）。
- 次の PDF のファイルを読み始める前に、前の PDF が閉じていること（呼ばれた順で確かめる）。
- PDF の途中で `budget` が 0 になる場合、中止の場合、1 ページだけ失敗する場合。
- 今あるテスト（読む順のテストは、新しい順に合わせて直してよい）が通ること。
- `npm test` がすべて成功すること（ファイルの読みこみの失敗が出たら、`node --test --test-concurrency=1 "tests/*.test.js"` でも確かめ、両方の結果を報告する）。
