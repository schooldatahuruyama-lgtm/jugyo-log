# 実装指示書: ピンチの拡大 修正 1（レビューの指摘 1 件）

あなた（Codex）は、この指示書に沿ってコードを直します。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

Codex レビュー `.ai-review/20261115-214546_round1.md` の指摘 1（High）を直す。

touch の出来事は、触れ始めたときの要素に届き続ける。その要素が画面から外されると、`touchmove`・`touchend` が表示の枠（viewport）まで上がってこなくなり、ピンチが途切れる・終わりが分からなくなる。今の作りでは、次の 2 つで起きうる。

1. PDF を 150% より大きくして指を置いたまま止めると、くっきり描き直した canvas に**入れかえる**ので、元の canvas（触れている要素）が外される。
2. 「書く」で、すでにある線の上から書き始め、2 本目の指で取り消すと、`cancelActive()` → `render()` が線（SVG の path）を作り直すので、触れている path が外される。

## 直すこと

1. `js/views/parts/viewer.js`: くっきり描き直すとき、canvas の要素は**入れかえない**。今出している canvas の `width`・`height` を新しい大きさにし、新しく描いた canvas の中身を `drawImage` で写す（表示の大きさ・class・`aria-label`・重ねた線は変えない）。写すのに失敗したら、元の絵にもどせないので、**写す前に失敗しうる所（描く所）を終えてから**写す。
2. 同じく、描き直しを写すのは、**枠の上に指が 1 本も無いとき**だけにする。指があるときは、指が全部離れたあとに写す（その間にページをめくった・閉じた・もう一度描き直しが要らなくなったら、捨てる）。
3. `css/app.css`: 紙（`.ink-paper`）の中の要素（線・けい線など）は `pointer-events: none` にし、触れた先がいつも紙（SVG の本体）になるようにする。先生の見るだけの重ね表示も同じでよい。消しゴム・書く動きは、座標で計算しているので変わらないこと（変わるなら報告に書く）。
4. ピンチの終わりを取りこぼさないよう、`touchend`・`touchcancel` は `window`（または `document`）でも聞き、今のピンチの指が無くなったら終える（今すでにそうなら、そのまま）。

## 端の場合

- 不正な入力: 新しい canvas の大きさが 0・数でないときは、写さない（今の絵のまま）。
- 重複と境界: 指を置いたまま 0.3 秒を何度またいでも、描き直しは 1 ページにつき 1 回。指を離した瞬間に写す。写したあとも、倍率・スクロール位置・書きこみは変わらない。指が離れる前にめくったら、次のページには写さない。
- 違反や失敗の見せ方: 文は足さない。失敗したら、今の絵のまま。

## テスト

- `tests/pdf-ink-screen.test.js`: 150% を超えて指を置いたまま 0.3 秒 → canvas の要素が同じまま・まだ写していない → 指を離す → 同じ要素の大きさが 3200 になる。指を置いたままめくる → 写さない。描き直しのあとも、同じ要素に `touchmove` を送ると倍率が変わる。
- `tests/picture-ink-screen.test.js`: すでにある線の上（path）を触れた先にして書き始め → 2 本目の指 → 取り消し → そのあとの `touchmove`・`touchend` でピンチが続き・終わること。紙の中の要素に `pointer-events: none` の規則があること（CSS の文字を読むテストでよい）。
- `npm test` がすべて成功し、変えた `.js` は `node --check` が通る。
