# 実装指示書: 写真への書きこみ Task 1 — データの形・規則・保存の流れ

あなた（Codex）は、この指示書に沿ってコードを書きます。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

先生の要望（2026-11-15）: 「先生の資料や、自分が添付した資料にも書きこみができるようにしたい」。まず**写真**だけ作る（PDF は対象外）。要件定義書 `docs/requirements.md` の「自分の記録は本人と先生だけが見られる」「Drive のファイルは共有しない」を守る。

この Task 1 は、画面を変えない。データの形・規則・保存の流れだけを作る。画面は Task 2（`.ai-tasks/20261116-021000_picink-task2-screens.md`）で作る。

## 考え方（Claude Code の設計）

今ある手書き（`ink`・`inkCleared`・`saveInkFlow`・下書き）を、そのまま使い回す。今は「欄」（`memo`・`learned`・`question`）だけだが、**書く場所**を次の 3 種類に広げる。

| 種類 | 場所の名前 | 何の上に書くか |
|---|---|---|
| 欄（今あるもの） | `memo`・`learned`・`question` | 白い紙 |
| 自分の写真 | `a1`〜`a6`（添付の置き場所） | その置き場所の写真 |
| 先生の資料の写真 | 資料の ID（`lessons/<c>/<l>/materials/<資料の ID>`） | その資料の写真 |

写真の上の書きこみは、目録に `on`（その写真のファイル ID）を持つ。置き場所 `a1` の写真が入れかわったあとに、前の写真への書きこみを出さないため。

## 1. 手書きの形（`js/ink-logic.js`・`js/config.js`）

- 写真の上の手書きは `{ v: 1, k: 'pic', h, s }`。横は今と同じ 800。`h` は写真の縦横の比に合わせた**整数**（400 の倍数に丸めない）。範囲は `CONFIG.ink.pictureMinHeight`（100。`js/config.js` に足す）〜`pageHeight * maxPages`（4000）。
- `cleanInk(value)`: `value.k === 'pic'` のときは、`h` を四捨五入して上の範囲におさめ、返す値に `k: 'pic'` を付ける。それ以外は今のまま（`k` は付けない）。線の確かめ（`cleanStroke`）は同じ。
- `emptyPictureInk(naturalWidth, naturalHeight) → { v: 1, k: 'pic', h, s: [] }`: `h = round(800 * naturalHeight / naturalWidth)` を範囲におさめる。引数が正の有限の数でなければ `h = 600`。
- `addPage`・`canAddPage`: `k === 'pic'` では足せない（`canAddPage` は `false`、`addPage` は今ある `too-long` の失敗）。
- `inkPlaceKind(name) → 'field' | 'attachment' | 'material' | null`:
  - `CONFIG.inkFields` にある → `'field'`
  - `CONFIG.attachmentSlots` にある → `'attachment'`
  - 資料の ID の形 → `'material'`。資料の ID の作り方（文字の種類と長さ）は、今のコード（先生の資料を足す所、`js/ids.js`、GAS の `MATERIAL_ID_RE`）を読んで合わせ、報告に書く。欄の名前・置き場所の名前と重ならないこと。
  - 文字でない・空・どれでもない → `null`
- `pictureIndex(record, place, fileId) → 目録 | null`: `record.ink[place]` があり、その `on` が `fileId` と同じときだけ返す。

## 2. `js/repo.js`

- 場所の名前の確かめ（今の `inkField(field)`）を、`inkPlaceKind` が `null` でないことに広げる。
- `getRecord`・`listRecords` の `ink`: 3 種類の場所を残す。写真の場所（`attachment`・`material`）の目録は `on`（1〜200 文字の文字）が無ければ落とし、返す目録に `on` を入れる。欄の目録には `on` を入れない。`inkCleared` も 3 種類の場所を残す。
- `setInk(classId, lessonId, studentId, place, { fileId, bytes, strokes, on }, thumb, now)`: 写真の場所では `on` が文字でなければ `TypeError`。目録に `on` を入れて書く。欄では `on` を書かない。小さい画像（`inkThumbs`）は今のまま、`CONFIG.inkThumbFields` の欄だけ。
- `removeInk`: 場所を広げるだけ。
- `removeAttachment(classId, lessonId, studentId, slot, clearedAt)`: `clearedAt` が数のときは、同じ update で `ink/<slot>` を消し、`inkCleared/<slot> = clearedAt` を書く。`clearedAt` が無ければ今のまま。数でも `undefined` でもなければ `TypeError`。
- `js/review-logic.js` の一覧・コピーは、今のまま欄だけを数える（写真への書きこみを「手書き N 件」に入れない）。そうなっていることを確かめ、テストを 1 つ足す。

## 3. 保存の流れ（`js/ink-flow.js`・`js/attachment-flow.js`）

- `saveInkFlow({ …, field, on })`: `field` は場所の名前（引数名は今のままでよい）。`inkPlaceKind(field)` が `null` なら `TypeError`。写真の場所で `on` が文字でなければ `TypeError`。
- **写真がまだあるかの確かめ**（写真の場所だけ。ファイルを上げる前に行う）:
  - `attachment`: 読んだ記録の `attachments` に、その置き場所で、`fileId === on`、`type === 'image'` のものがある。
  - `material`: `repo.getLesson(classId, lessonId)` の `materials[field]` があり、`fileId === on`、`type === 'image'`（資料の目録の項目名は、今のコードを読んで合わせる）。
  - 無ければ、保存せずに `{ index: null, superseded: true, gone: true, record }` を返す（ファイルも上げない）。
- 時刻のくらべ（`serverInkTime(record, field) >= editedAt` → `superseded`）は、3 種類とも同じ。返す `index` は、写真の場所では `pictureIndex(record, field, on)`（前の写真への書きこみは返さない）。
- `repo.setInk` に `on` を渡す。`denied` のあとの読み直しでは、「自分の保存が届いていた」の判断に `on` も同じことを足し、どちらでもないときは、上の「写真がまだあるか」をもう一度確かめて、無ければ `gone: true` の `superseded` を返す（上げたファイルは片付ける）。
- 古いファイルの片付け（`previous`）は、`on` がちがう前の書きこみのファイルも片付ける（今のまま、記録の `ink[field]` を見ればよい）。
- `resendInkDrafts`: 下書きに `on` があれば `saveInkFlow` に渡す。`gone` も `superseded` と同じく、下書きを捨てて `dropped`。小さい画像は欄だけ（今のまま）。
- `removeAttachmentFlow({ repo, files, classId, lessonId, studentId, attachment, now })`: はじめに `repo.getRecord` で記録を読み、`ink[attachment.slot]` がある（`on` がどれでも）か、`inkCleared[attachment.slot]` があるときは、`clearedAt = max(now, serverInkTime(record, slot) + 1)` を `repo.removeAttachment` に渡す。無ければ渡さない（今の動き）。写真を消せたあと、書きこみのファイルも `files.trashStudent` で片付ける（失敗は無視）。`now` は呼ぶ側（`js/views/parts/attachment-pane.js`）から `ctx.now()` を渡す。この 1 行の呼び出しの変更だけ、画面のファイルを触ってよい。

## 4. 下書き（`js/ink-drafts.js`）

- 場所を 3 種類に広げる（`inkPlaceKind`）。
- 下書きは `{ ink, editedAt, key, on? }`。写真の場所では `on`（文字）が無い下書きは捨てる（`null`）。欄では `on` を落とす。`list` の返す値にも `on` を入れる。`ink` の `k: 'pic'` は `cleanInk` が残す。

## 5. 規則（`docs/setup/rules.json`）

`records/$classId/$lessonId/$sid/ink/$field` の `.validate` の、場所の確かめ（今の `($field === 'memo' || $field === 'learned' || $field === 'question')`）を、次に入れかえる。ほかの条件（`hasChildren`・時刻のくらべ）は残す。

```
((($field === 'memo' || $field === 'learned' || $field === 'question') && !newData.child('on').exists()) || ($field.matches(/^a[1-6]$/) && newData.parent().parent().child('attachments').child($field).child('type').val() === 'image' && newData.child('on').val() === newData.parent().parent().child('attachments').child($field).child('fileId').val()) || (root.child('lessons').child($classId).child($lessonId).child('materials').child($field).child('type').val() === 'image' && newData.child('on').val() === root.child('lessons').child($classId).child($lessonId).child('materials').child($field).child('fileId').val()))
```

`ink/$field` の下に、子の規則を足す。

```json
"on": { ".validate": "newData.isString() && newData.val().length >= 1 && newData.val().length <= 200" }
```

`inkCleared/$field` の `.validate` の、場所の確かめを、次に入れかえる（時刻のくらべは残す）。

```
($field === 'memo' || $field === 'learned' || $field === 'question' || $field.matches(/^a[1-6]$/) || root.child('lessons').child($classId).child($lessonId).child('materials').child($field).exists())
```

資料の目録の項目名（`type`・`fileId`）が今のコードとちがっていたら、コードに合わせ、報告に書く。

## 6. 規則の確認（`js/rules-probe.js`）

今ある手書きの確かめの近くに、次を足す（今は 77 行）。確かめ用のデータは、今ある確かめのやり方（先生が用意して、あとで片付ける）に合わせる。片付けで残さない。

- 自分の写真（`a1`。`type: 'image'`）があるとき、`ink/a1` を、その写真の `fileId` と同じ `on` で書く → できる
- `ink/a1` を、ちがう `on` で書く → できない
- `ink/a2`（写真が無い置き場所）を書く → できない
- `ink/memo` に `on` を付けて書く → できない
- 授業にある写真の資料の ID で、`ink/<資料の ID>` を、その資料の `fileId` と同じ `on` で書く → できる
- 授業に無い資料の ID で書く → できない

今の確かめの作りで用意がむずかしいもの（資料を足すなど）があれば、作れる分だけ足して、作れなかったものを報告に書く。行の数を README・`docs/setup/` などの「77」に反映する。`docs/superpowers/specs/2026-11-13-jugyo-log-1a-data.md` に、この形（場所の 3 種類・`on`・`k: 'pic'`）を書く。

## 7. 練習モード（`js/dev/`）

練習モードの代役（データベース・GAS）で、上の保存と読みこみが動くこと。規則を持たない代役の動きは変えない。

## 端の場合

- 不正な入力: 場所の名前が文字でない・空・知らない形 → `repo`・`saveInkFlow`・下書きが受けつけない（`TypeError`、下書きは捨てる）。`on` が文字でない・空・200 文字より長い → `repo` が目録を落とし、規則が断る。`h` が数でない・とても大きい・小さい → `cleanInk` が範囲におさめる。写真の大きさが 0 や数でない → `emptyPictureInk` は `h = 600`。
- 重複と境界: 同じ時刻の保存はサーバーを残す（今のまま）。置き場所 `a1` の写真が入れかわったあとの古い書きこみは、`pictureIndex` が `null` を返し、新しい保存のときに古いファイルが片付く。写真を消すと、書きこみの目録も同じ update で消える。資料が授業から外されたあとの書きこみは、目録に残るが、どこにも出ない（割り切り。`docs/superpowers/specs/2026-11-13-jugyo-log-1a-data.md` に 1 行書く）。
- 違反や失敗の見せ方: この Task では画面を変えない。写真が無くなっていた保存は `gone: true` で返し、Task 2 の画面が文で見せる。規則の確認の失敗は、表に × で出る。
