# 実装指示書（修正 2）: 「規則の確認」の片付け — 単元の削除だけが失敗したときに、次回も消せるようにする

あなた（Codex）は、この指示書に沿ってコードを直します。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。もとの指示書は `.ai-tasks/20261120-190000_rika-class-unit.md` と `.ai-tasks/20261120-193000_rika-class-unit-fix1.md`、レビューは `.ai-review/20261120-183332_round2.md`。

## 目的

レビュー round 2 の指摘（Medium）に対応する。今は「クラスなどを消す → そのあと `rika/classUnit` を消す」の順なので、後ろだけが通信の失敗で残ると、次回はクラスが無いため、残った `rika/classUnit/<確認用のクラス>` を見つけられない。

## 変える内容（`js/rules-probe.js`）

`removeKnown` と `removeLeftovers` の両方で、片付けの順番を次にする。

1. **先に** `rika/classUnit/<確認用のクラス>`（と `rules-probe-no-class`）を消す `update` を行う。
2. 1 が成功した → 今までどおり、クラス・授業・所属などを消す。
3. 1 が **規則で拒まれた**（`NetError` の `denied`）→ 単元の規則がまだ貼られていない場合。このときは単元を書けてもいないので、クラス・授業・所属などを消す。結果には「片付け」の ×（`pass: false`）の行を足す（今と同じ）。
4. 1 が **そのほかの失敗**（通信の失敗など）→ 確認用のクラス・所属は**消さずに残す**（次回の `removeLeftovers` が、残ったクラスを手がかりに、単元とクラスの両方を消せるように）。結果には「片付け」の × の行を足す。`removeLeftovers`（準備の中）でこうなったときも、準備は止めず、先へ進む（fix1 の決まりのまま）。

- 行の数（139）と順番は変えない。fix1 で入れた「分けて消す」は保つ（順番だけ入れかえ、4 の場合の扱いを足す）。
- 生徒として先に消す分（生徒の持ちもの）や、`rika/state`・`rika/log` の片付けは変えない。

## 端の場合

- 不正な入力: 変えない。
- 重複と境界:
  - 単元の書きこみは成功 → 片付けで単元の削除だけが通信の失敗 → クラスが残る → 次回の実行の準備で、単元とクラスの両方が消える。
  - 規則が古い（単元の削除が毎回 `denied`）→ クラスなどは毎回消え、たまらない。
  - 単元の削除は成功、クラスの削除が失敗 → 今までどおり「片付け」の ×。次回、残ったクラスから消す。
- 違反や失敗の見せ方: 「片付け」の行の ×（今ある見せ方）。

## テスト（`tests/rules-probe.test.js`）

- 「単元の書きこみ成功 → 片付けの単元の削除だけ通信の失敗 → もう一度実行」: 1 回目の結果に「片付け」の × があり、クラスと所属が残っている。2 回目のあと、`rika/classUnit/<1 回目のクラス>` もクラスも残っていない。
- 「単元の削除が `denied`」: クラス・授業・所属は消える（fix1 のテストが通ること）。
- `npm test` がすべて成功すること。
