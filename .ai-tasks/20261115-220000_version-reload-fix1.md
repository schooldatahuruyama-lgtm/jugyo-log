# 実装指示書: 新しい版の知らせの修正 1（読みこみ直す間は、画面を片付けて操作できなくする）

あなた（Codex）は、この指示書に沿ってコードを直します。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

Codex レビュー `.ai-review/20261115-081924_round1.md` の指摘 1・2（どちらも High）を直す。

1. 「読みこみ直す」で、離れるかの確かめ（`leave.ask()`）が済んだあと、ファイルを取り直している間（最大 10 秒）も、画面を操作できる。この間に始めた保存は、終わりを待たずに読みこみ直してしまう。
2. 画面が自分で付けた `beforeunload` が残るので、ブラウザがもう一度たずね、そこで取り消すと、ボタンが押せないまま残る。

待ち方やロックを足すのではなく、**離れてよいと決まったら、ふつうに画面を移るときと同じように、今の画面を片付ける**（Claude Code の判断）。片付ければ、操作する相手も、画面が付けた `beforeunload` も無くなる。

## 変えるファイル

`js/main.js` だけ。ほかのファイルは変えない。

- 「読みこみ直す」を押したとき（`showVersionBanner` の中）の順番を、次にする。
  1. すでに進めている（`reloading`）なら何もしない。
  2. `await leave.ask()`。`false` なら、`reloading` を戻して終わる（知らせとボタンは、押せるまま残る）。
  3. `true` なら、**同じ流れの中で続けて（間に `await` をはさまずに）**: 読みこみ直しを始めた印（`start()` の中の変数。例 `appReloading = true`）を立て、`renderId` を 1 つ進めて（進んでいる描き直しを古くする）、`teardown()` を呼び、`appRoot` を「読みこみ直しています…」（`role="status"`。今ある `showLoading` と同じ形でよい）に置きかえる。知らせの帯のボタンは押せなくし、文も「読みこみ直しています…」にする。
  4. `await refreshAppFiles()`（失敗は無視）。
  5. `location.reload()`。
- 読みこみ直しを始めた印が立っている間は、`render()` を呼ばれても何もしない（はじめで戻る）。`hashchange`（ブラウザの「戻る」など）が来ても、画面を描き直さない。`navigate()` も `'stayed'` を返す。
- `teardown()` は今あるものをそのまま使う（画面の `cleanup` が、その画面の `beforeunload` を外す）。`teardown()` や `cleanup` が例外を投げても、4・5 に進む（`try`/`catch`）。
- 印は戻さない（このあとは必ず読みこみ直すため）。

## 端の場合

- 不正な入力: 入力は無い。
- 重複と境界: 「読みこみ直す」を続けて押しても、進むのは 1 回。離れるかの確かめで「ここに残る」を選んだら、画面も知らせも元のままで、もう一度押せる。確かめの間に別の画面へ移っていた場合も、`true` が返ったら、その時の画面を片付けて読みこみ直す。
- 違反や失敗の見せ方: 読みこみ直している間は、画面に「読みこみ直しています…」だけを出す（前の画面のボタンを残さない）。ファイルの取り直しに失敗しても、読みこみ直す。読みこみ直したあとに取れなければ、`index.html` の「読みこめませんでした。…」が出る。

## 確かめ

- テストのファイルは足さない。`npm test` がすべて成功し、`node --check js/main.js` が通ること。
- 代役を使った手元の実行で、次を確かめて報告に書く: (1) 確かめで `true` → 画面が片付き（`cleanup` が 1 回呼ばれる）、取り直しの間に `render()`・`navigate()` を呼んでも画面が出ない → 読みこみ直す。(2) 確かめで `false` → 画面はそのまま、ボタンをもう一度押せる。

## 守ること

- `git add`・`git commit` はしない。版を確かめる動き（5 分の間隔など）と、ほかの画面の動きは変えない。
