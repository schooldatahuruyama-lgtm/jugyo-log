# 実装指示書: 中つぎ（学校の回線から、保存の仕組みへ届かせる）

あなた（Codex）は、この指示書に沿ってコードを書きます。進め方は `AGENTS.md` の「実装を頼まれたとき」のとおりです。

## 目的

学校の回線では、`script.google.com` だけが止められていて、保存の仕組み（Google Apps Script。`js/gas-config.js` の `appUrl` と `url`）に届かない（`docs/reports/stage1b-2-check.md` の最後。2026-11-17）。`workers.dev`・`script.googleusercontent.com`・Firebase には届く。

先生の決定（2026-11-17）: **中つぎを置く。** 学校から届く場所（Cloudflare Workers）に小さな中つぎを置き、ブラウザ → 中つぎ → 今の保存の仕組み、と送る。保存先は先生の Drive のまま。GAS・規則は変えない。

- 中つぎは、先生が Cloudflare に登録して置く（手順書は Claude Code が書く）。置くまでは、アプリは今までどおり動く。
- 中つぎは、何も保存しない・記録（ログ）に本文やトークンを出さない。

## 1. 中つぎの本体（新しい `relay/worker.js`）

Cloudflare Workers の形（`export default { async fetch(request) { … } }`）。1 つのファイルで、ほかを読みこまない。テストから呼べるよう、中身は `export async function handleRelay(request, { fetch })` に切り出す。

- 先頭の定数:
  - `ALLOWED_ORIGINS`: `https://schooldatahuruyama-lgtm.github.io`、`http://127.0.0.1:8791`、`http://localhost:8791`。
  - `TARGETS`: `{ app: <js/gas-config.js の appUrl>, check: <js/gas-config.js の url> }`（今の値を書きうつす。テストで、`js/gas-config.js` と同じであることを確かめる）。
  - `MAX_BODY = 40 * 1024 * 1024`（文字数ではなくバイト）。`VERSION = 'relay-1'`。
- 道:
  - `GET /ping` → `200`、`{ "ok": true, "version": "relay-1" }`。
  - `POST /gas/app`・`POST /gas/check` → 本文をそのまま、`TARGETS` のアドレスへ `POST`（`Content-Type: text/plain;charset=utf-8`、`redirect: 'follow'`）し、返ってきた本文と状態コードを、そのまま返す（`Content-Type: application/json; charset=utf-8`）。
  - `OPTIONS`（どの道でも）→ `204`（CORS の下見）。
  - そのほか → `404`、`{ "ok": false, "error": "notfound" }`。
- CORS: `Origin` が `ALLOWED_ORIGINS` にあるときだけ、`Access-Control-Allow-Origin: <その Origin>`、`Vary: Origin`、`Access-Control-Allow-Methods: GET, POST, OPTIONS`、`Access-Control-Allow-Headers: Content-Type`、`Access-Control-Max-Age: 86400` を付ける。
- `POST` で `Origin` が無い・一覧に無い → `403`、`{ "ok": false, "error": "denied" }`（保存の仕組みへは送らない）。`GET /ping` は、`Origin` が無くても答える（先生がブラウザで直接開いて確かめられるように）。
- 本文が `MAX_BODY` を超える（`Content-Length` で分かるとき、または読んだ長さ）→ `413`、`{ "ok": false, "error": "toobig" }`。
- 保存の仕組みへの通信が失敗した（例外）→ `502`、`{ "ok": false, "error": "server" }`。
- すべての返事に `Cache-Control: no-store`。`console.log` などで、本文・トークン・アドレスを出さない。
- 送り先は `TARGETS` の 2 つだけ。本文やアドレスから、送り先を決めない（ほかの場所へ送る踏み台にさせない）。

## 2. 設定（`js/gas-config.js`）

`relayUrl: ''` を足す（説明の 1 行: 「学校の回線から保存の仕組みへ届かないときの中つぎ。空なら使わない。末尾の / は付けない」）。値は空のまま（Claude Code が、先生が置いたあとに入れる）。

## 3. 送り先の決め方（新しい `js/gas-endpoint.js`。DOM を使わない）

```js
// 中つぎが設定されていれば中つぎの道を、無ければ今のアドレスを返す。
export function gasEndpoint({ relayUrl, target, directUrl }) → 文字
```

- `relayUrl` が空・文字でない → `directUrl`。
- `relayUrl` が `https://` で始まる文字 → `relayUrl` の末尾の `/` を取り、`/gas/<target>`（`target` は `'app'` か `'check'`。それ以外は `TypeError`）を付けて返す。
- `relayUrl` が空でないのに `https://` で始まらない → `TypeError`（設定のまちがいを見つけるため）。ただし `http://127.0.0.1`・`http://localhost` で始まるものは、手元の確かめ用に受けつける。

## 4. アプリ（`js/main.js`）と接続確認ページ（`check.html`）

- `js/main.js`: `createGas` に渡す `url` を、`gasEndpoint({ relayUrl: GAS.relayUrl, target: 'app', directUrl: GAS.appUrl })` にする。`js/gas.js` は変えない（送り方・やり直し・時間切れは同じ）。
- `check.html`: 6〜10 番で使うアドレスを、`gasEndpoint({ relayUrl: GAS.relayUrl, target: 'check', directUrl: GAS.url })` にする。中つぎを使っているときは、「確認の結果」の見出しの下に 1 行「保存の仕組みへは、中つぎを通して送っています。」を出し、「結果をコピー」の文にも「中つぎ: 使っている／使っていない」を入れる。
- `check.html` の「どこに届くか」: 中つぎが設定されているとき、一覧の「今の保存の仕組み」の前に「先生が置いた中つぎ」（アドレスは `<relayUrl>/ping`）を足す（`js/reach-targets.js`）。
- 練習モードは、今のまま（GAS を使わない）。

## 端の場合

- 不正な入力（中つぎ）: `POST` の本文が空 → そのまま送る（保存の仕組みが `bad` を返す）。道が `/gas/other` → `404`。メソッドが `PUT`・`DELETE` → `404`。`Origin` が大文字まじり・末尾に `/` → 一覧と同じ文字でなければ `403`。保存の仕組みが JSON でない本文（HTML のエラーページ）を返した → そのまま返す（ブラウザ側は今と同じく失敗として扱う）。
- 不正な入力（設定）: `relayUrl` が `null`・数 → 使わない。`'http://example.com'` → `TypeError`。末尾の `/` が 2 つ以上 → 全部取る。
- 重複と境界: 本文がちょうど `MAX_BODY` は通す。`OPTIONS` は、`Origin` が一覧に無いときも `204` を返す（CORS の見出しは付けない）。同じ要求が続けて来ても、中つぎは何も覚えない。
- 違反や失敗の見せ方: 中つぎの失敗は、上の状態コードと `{ ok: false, error }`。ブラウザ側では、今ある文（「通信できませんでした」など）のまま。画面の文は、接続確認ページの 1 行のほかは足さない。
