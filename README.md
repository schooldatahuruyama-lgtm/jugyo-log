# 授業ログ

授業 1 回ごとに、先生の板書・配布資料と、生徒自身のメモ・写真・振り返りを 1 か所に残すアプリです。

## いまの状態

段階 0（接続確認）を作っているところです。アプリ本体はまだありません。

段階 0 では、学校の iPad と学校のネットワークから、ログインとデータベース（Firebase）、写真を先生の Google Drive に保存する仕組みが使えるかを確かめます。

## 接続確認の手順（先生がすること）

1. `docs/setup/firebase.md` を開き、書いてある順番に Firebase を準備します。終わったら、データベースの URL とウェブ API キーを控えます。
2. `docs/setup/gas.md` を開き、書いてある順番に GAS（写真を保存する小さなプログラム）を公開します。終わったら、`/exec` で終わる URL を控えます。
3. 控えた 3 つの値（データベースの URL、ウェブ API キー、GAS の URL）を Claude Code に伝えます。パスワードは伝えません。
4. Claude Code が確認ページを公開します。公開できたら、ページの URL を教えてもらいます。
5. 学校の iPad（学校のネットワーク）で、その URL を開きます。「確認している場所」を「学校」にして、「確認を始める」を押します。
6. 終わったら「結果をコピー」を押し、コピーした文章を Claude Code に貼り付けて伝えます。コピーできないときは、画面に出る欄の文章を選んでコピーします。
7. 学校では、合計 3 回確認します（同時に 40 回呼ぶ結果を 3 回分ほしいためです）。2 回目と 3 回目は、ボタンが「もう一度確認する」に変わっているので、それを押します。毎回、6 と同じように「結果をコピー」で伝えます。
8. 家でも、同じページを開いて 5 と 6 をします。「確認している場所」は「家」にします。家は 1 回で大丈夫です。
9. コピーした文章には入らないものを、次の 2 つ、Claude Code に伝えます。
   - Google Drive の空き容量: パソコンで https://drive.google.com/ を開き、学校用のアカウントでログインします。左のメニューの下のほうにある「保存容量」の「○○ GB / ○○ GB を使用中」という文字を見て、そのまま伝えます。確認ページの項目 10 の数字と見比べます。
   - iPad の機種名と iPadOS のバージョン: iPad の「設定」→「一般」→「情報」を開き、「機種名」と「システムバージョン」に出ている文字を、そのまま伝えます。
10. 結果を伝え終わったら、`docs/setup/gas.md` と `docs/setup/firebase.md` の「確認が終わったら」を行います。

結果は `docs/reports/stage0-check.md` に書き残します。

## 開発者向け

### 確認ページの公開

確認ページは、GitHub Pages で公開します。公開の手順は次のとおりです。

1. 最初の 1 回だけ、GitHub に新しいリポジトリを作ります（先生の作業）。Pages を無料で使うには、リポジトリを公開にする必要があります。その場合、`master` に入れたファイル（`docs`、`gas`、`tests`、`.ai-tasks`、`.ai-review` を含む）はすべて見えます。
2. 変更をコミットしてから、次のコマンドで、公開用の `pages` ブランチを作ります（コミット済みのアプリのファイルだけが入ります）。

   ```
   powershell -NoProfile -ExecutionPolicy Bypass -File tools/pages-branch.ps1
   ```

3. 2 つのブランチを送ります。

   ```
   git push origin master
   git push origin pages
   ```

4. 最初の 1 回だけ、GitHub のリポジトリで Settings → Pages を開き、Branch を `pages` / (root) にして保存します。

公開したあと、設定の変更が届くまで 10 分ほどかかることがあります。古い表示のままなら、待ってから読み直してください。

### テスト

```
npm test
```

Node.js 組み込みのテストランナー（`node --test`）で `tests/*.test.js` を実行します。依存パッケージはありません。ビルドもありません。
